## 1. 认账

全部 8 项出自 ISS-0030 双文件方案及其 install.ps1 接线:方案设计时只覆盖了
主路径组合(迁移×空 local、撤回×出厂条目),未枚举"迁移×撤回墓碑、脚本×失败、
手写×缺省语义"等交叉面——违反 §2.1 交叉面清单(本单即按该规则补表)。

## 2. 整改项(编号对应评审发现)

| # | 修复 | 约束 |
|---|------|------|
| A1 | migrate_whitelist:**local 已有条目(墓碑或显式)一律跳过,禁止覆写**——人类裁决永远优先于出厂差额 | 迁移只增补 local 缺席的进程 |
| A4 | install.ps1 每个 `& <原生命令>` 后必查 `$LASTEXITCODE`,非零 → 警告+继续(不静默) | 继续语义保留(尽力而为),但必须出声 |
| A5 | _merge_local_whitelist:条目**缺 max_level 键 → PolicyError**(fail-closed 显式化);墓碑仅 `max_level: null` 显式表达 | 三种 YAML 语义归一:唯一隐式入口全部消灭 |
| A6 | remove() 双文件模式**一律写墓碑**(不再分 base/本地新增);WhitelistAdmin 双文件模式(local_path 给定)缺 base_whitelist → 构造即 PolicyError | 撤回记录永续;装配缺参 fail-closed |
| B2 | migrate 异常收敛 PolicyError(CLI 可捕);local 落盘走 .bak+tmp+os.replace 原子写(提取模块级 `atomic_write_yaml` 共用) | 不复制实现 |
| B3 | load_policy:**先校验 base 必填节/类型,后合并 local** | 坏 base 永远先炸 |
| B4 | 迁移审计目录用 resolve_audit_dir(new_policy 的 audit_dir, policy_path=新策略路径) 锚定 | 审计落入安装目录,不再按 CWD 流浪 |
| B5 | migrate _names 对 level `.strip()` 后再 `.upper()` | 旧文件脏值不变成启动事故 |
