# ISS-0045：大文本读回窗口不匹配规模——重试耗尽+写锁级联超时

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0045 |
| 标题 | type_text 大文本(约 65k 字符)粘贴后读回轮询窗口(3×300ms)远小于文本稳定所需时间 → 误判"读回不一致"→ 重贴(内容翻倍风险)→ 写锁被占 60s+ → 后续调用排队 TOOL_TIMEOUT(连超限输入都来不及被 validate 拒绝) |
| 严重级 | **中**(可靠性:误判+潜在内容翻倍+锁级联;sdfang 手工测试实证) |
| 状态 | **已关闭**(2026-09-22 ④裁定:不采纳,原则保留(v0.3);①+③早已绿,④系最后悬置项) |
| 提出 | 2026-09-08(手工测试 C-09 实证) |

## 1. 背景(实证)

2026-09-08 手工测试:
- 输入 65536 字符(恰在 input_max_chars 边界):粘贴落盘(记事本全 A),
  但调用返回 ok=False——读回轮询(3×300ms)在 65k 文本稳定前即耗尽,
  误判不一致并重试;期间写锁被占 ~60s+;
- 紧随输入 65537 字符(超限):本应在 validate 即 INVALID_PARAMS 零派发,
  但因排在写锁之后,预算先耗尽 → TOOL_TIMEOUT,校验根本没机会执行。
- 副作用:目标记事本留下未保存巨文档(重贴可能使内容翻倍——
  ISS-0035 的"宁重复不丢字"原则在边界规模下的放大面)。

## 2. 整改方向(评审后定)

| # | 方向 | 说明 |
|---|------|------|
| ① | 读回轮询窗口按文本长度缩放(如 300ms×ceil(len/8k),封顶) | 直接对症 |
| ② | 大文本跳过逐字读回,改长度比对(剪贴板长度 vs 文档增量) | 性能取向 |
| ③ | 超限校验前置到写锁之前(validate 在锁外) | 防级联 |
| ④ | 重贴前先全选清空(防翻倍)——与"宁重复不丢字"原则的边界评审 | 语义取舍 |

### 约束

- 方案评审前不动代码;④涉"宁重复不丢字"既有原则,必须 sdfang 裁定;
- 测试设计(五要素)于评审通过后产出。
