# ISS-0085:【设计引入】白名单管理窗口撤销条目即整窗销毁重建,位置丢失

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0085 |
| 标题 | 白名单管理窗口每次撤销条目都**整窗销毁再重建**,呈现明显的「退出-重启」效果,且重建后窗口位置改变;理想状态是窗口始终保持不动——最基本的 UI 效果 |
| 严重级 | **中**(UI 观感缺陷,人类操作者的直接体验面;不涉安全语义) |
| 状态 | **已实现,待真机验收**(SDD P1→P3 完成 2026-09-16;单元 6/6 绿+全量 763 passed;真机肉眼面「撤销后窗不动」待手工验收) |
| 提出 | 2026-09-14 sdfang 撤销微信白名单时实测发现 |

## 1. 现象与证据

**现象**(sdfang 实测):在白名单管理窗口撤销微信条目时,窗口有明显的退出重启效果,重启之后窗口位置改变。

**机制层根因(源码实证)**:

- `deskpilot/whitelist_window.py:732-737` `on_remove(proc)`:POST `/whitelist/remove` 成功后调 `refresh()`;
- `whitelist_window.py:709-729` `refresh()`:**`state["win"].destroy()` 整窗销毁 → `build_window(...)` 整窗重建**(同 `root` 上销毁重建,Tk 层面即整窗消失再出现);
- 重建的几何取缺省值,**销毁前不记忆 `geometry()`、重建后不恢复** → 位置改变;
- 对照:`_render_block`(whitelist_window.py:404+)已有**块级就地刷新**路径(搜索过滤 `_on_search` 即走它,整窗不动)——撤销路径没有用它,用了最粗的整窗重建。

**即**:列表数据刷新被实现为「整窗销毁重建」,而非就地更新条目;窗口几何无记忆。两处叠加 = 用户看到的「退出重启 + 位置漂移」。

## 2. 整改方向

| # | 方向 | 说明 |
|---|------|------|
| ①(倾向) | **撤销/清空走块级就地刷新** | 复用 `_render_block` 既有路径(与搜索过滤同形态),整窗不销毁;条目行移除有/无动画均可,窗体几何天然不动 |
| ② | 若坚持整窗重建 | 销毁前 `win.geometry()` 记忆、重建后同几何恢复 + `update_idletasks` 后再显示,消除闪烁——但相比①是补丁式修法 |

**范围提示(不顺手改)**:同文件 `on_clear`(全部清空)同样调 `refresh()`,同缺陷;修复时一并覆盖。

## 3. 验收口径(要点,测试设计另立)

- 撤销单条/清空会话后:**窗口 `geometry()` 逐分量不变**(同一 `root` 上窗前窗后对地址值断言);
- 窗口**不发生 destroy/create**(可以窗口对象身份或 exists 状态断言);
- 条目列表内容随撤销正确更新(回归既有功能);
- 关联单 ISS-0071(弹窗落位脱离统一几何)不同,本单只管「撤销引发的整窗重建与位置丢失」。

## 4. 约束

- 不改撤销的安全语义(tombstone/审批口径);本单纯 UI 行为;
- 与 ISS-0071 的几何统一整改**不合并**,但落位修复时不得再引入整窗重建;
- 实现走 SDD P1→P2→P3。

## 6. 测试设计(v0.3,P1 前置)

### 6.1 公开入口(设计定义)

| 入口 | 契约 |
|------|------|
| `whitelist_window.refresh_view(state, base, root, on_remove, on_clear)` | 模块级。`state["win"] is None` → `build_window` 建窗+`WM_DELETE_WINDOW` 注册+存入 state;否则 → `state["win"]._manager.set_data(...)` **就地刷新,窗不销毁不重建** |
| `_ManagerUI.set_data(entries, display_map=None)` | 数据**整表替换**(`_entries`/`_dmap` 换引用,非逐键改)+ `render()` |
| `whitelist_window._fetch_whitelist(base)` | GET `/whitelist` → `(entries, dmap)`;异常返回 `({"static":{},"session":{}}, {})`——既有容错语义原样迁移,非新增降级 |
| `main()` | 接线改调 `refresh_view`(闭包 refresh 删除) |

几何不变量的证明结构:窗口对象**未销毁**(断言 destroy 零调用+对象身份)⇒ Tk 几何天然保留——机制蕴含,不另钉数值;真机肉眼验收记手工测试记录(仓库惯例:单元替身+真机手工)。

### 6.3 守门核对

- **R1 装配**:main() 接线 refresh_view=真机手工验收面(管理窗口撤一条,窗不动);单元测 refresh_view 本体。
- **R5 终效应**:断言全部打替身直出(labels 列表/destroy 调用记录/state["win"] 对象身份),无中间转换。
- **R6 双向映射**:验收口径§3「geometry 不变/不 destroy-create/条目正确更新」→ TC-01/02(机制蕴含+直出);「on_clear 一并覆盖」→ TC-02;容错回归 → TC-04;set_data 契约 → TC-05/06。孤儿核对:无用例映射不到的验收项(几何数值项由机制蕴含+手工面覆盖,已在§6.1 说明)。
- **R7 失效原因**:全部用例为正向断言,零 `pytest.raises`;若实现仍整窗重建 → destroy 计数/对象身份立即红,不会借道假绿。替身 stub 为第 4 处内联拷贝——既有「替身散落」坏味道(cleancode 族)不顺手重构,新文件内注明。
