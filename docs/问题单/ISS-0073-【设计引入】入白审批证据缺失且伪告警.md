# ISS-0073：【设计引入】入白审批证据缺失且伪告警

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0073 |
| 标题 | 要求人类裁决"永久信任某进程"，却无目标实拍、无定位依据，且以"目标无法前置"伪告警掩盖缺证据事实 |
| 严重级 | **中高**（人类裁决权被削：在信息不全的情况下要求授权） |
| 状态 | 建单待评审 |
| 提出 | 2026-09-11（手工测试 D-03~09 现场目击，sdfang 截图） |

## 1. 现场实证

sdfang 截图 `Snipaste_2026-09-11_12-08-23.png` 直读，弹窗正文：

> 进程 seeyou.exe（显示名来源：窗口标题）当前未经本地授权（请求动作 attach）。本次会话允许 = 重启前有效（会话级，不落盘）；永久加入 = 写入白名单长期有效，可随时在白名单管理中移出（**实拍存疑：目标无法前置，未截图**）

弹窗窗口区**无任何目标画面**——只有警示色条、标题、说明文字、三个按钮。人类被要求对「西柚加速器」做永久授权裁决，而屏幕上没有它长什么样的任何依据。

## 2. 根因（机制层）

### 2.1 截图必空——`attach` 过闸时绑定尚不存在，这是结构性的

`tools/__init__.py:135-166` 的 `attach` 是**先过闸、后建绑定**：

```python
decision = ctx.enforcement.submit(
    OperationRequest(tool="attach", params={"process": w["process"]},
                     binding_token=None))          # ← 此刻无绑定
...
rec = ctx.bindings.create(...)                       # ← 绑定在过闸之后才建
```

而闸二的入白审批这样取图（`enforcement.py:153-155`）：

```python
decision = self._approvals.request_enroll(
    proc, desc, fp, image_path=self._capture_target(binding, request),
    target_rect=binding.window_rect if binding else None)
```

`binding` 为 `None` → `target_rect` 为 `None`（**这是第二个根因，见 §2.2**），
`_capture_target(None, ...)` 走无绑定分支——但该分支**并非直接放弃**，
而是按进程名反查窗口并尝试取证（`enforcement.py:350-371`）：

```python
proc = str(request.params.get("process", "")) if request else ""
if proc:
    all_cands = self._executor.find_windows(process=proc, include_hidden=True)
    onscreen = [w for w in all_cands if w.get("visible", True) and ...]
    if onscreen:
        return self._shot_verified(onscreen[0])      # ← 前置+无遮挡校验后才拍
    if all_cands:
        ctypes.windll.user32.ShowWindow(all_cands[0]["hwnd"], 9)   # 还原隐藏窗
        return self._shot_verified(all_cands[0])
```

**所以取图链是通的，失败发生在更下游的"前置+无遮挡"四步校验**
（`_shot_verified`，`enforcement.py:379-398`——用户钦定的"前置→验证最前→
验证无遮挡→才截图"）：

```python
for _attempt in range(2):
    activate(hwnd)                          # 尝试前置
    if self._center_belongs(rect, hwnd):    # 中心点顶层须为自身
        return self._executor.capture_approval_shot(rect)
self._capture_note += "（实拍存疑：目标无法前置，未截图）"
return None
```

> **引文更正（v0.4 核实）**：上段为简化引文，与 `enforcement.py:396-409` 真实代码
> 有出入——差的那处恰是 §2.5 的发现。真实代码见 §2.5。

**现场判定：西柚加速器窗口中心点处的顶层窗口不是它自己**，两次重试均未通过 →
按 fail-closed 不给图。这条 fail-closed 方向**本身是对的**（宁可无图也不给错图，
`ISS-0020 D` 立意），本单不推翻它。

**真正的问题有两层**（原稿误把两层合成一层，此处更正）：

- **第一层（可修）：`_shot_verified` 的"中心点归属"判据对**合法窗口**过于严苛。**
  中心点被任何**子窗口**、**同进程其他窗口**、或**系统浮层**（输入法、云盘悬浮球、
  屏幕取色器一类常驻 topmost 小组件）压住，即判定失败——而这两种情况下目标窗口
  其实是可见、可截图、可辨认的。判据用的是 `WindowFromPoint` 单点，对
  "部分遮挡"零容忍，但**部分遮挡恰恰是人类最需要看图的场景**。
- **第二层（本单主体）：失败被呈现为"无法"，而非"未取"，且人类拿不到兜底判据。**
  系统明明有 `hwnd` 与 `rect`（`_describe_enroll` 拿到的 `request.params` 或
  `find_windows` 结果里就有），却因 `binding is None` 把 `target_rect` 也丢了，
  最终人类手上只剩一句"实拍存疑"。**有据可给而未给**，这才是削人类裁决权的那一刀。

### 2.1b 授权主体错位：人类审的是**软件**，系统给的是**窗口**（本单最高层根因）

**〔v0.5 定案，源自 sdfang §4 Q3 裁定〕** 上面两层都是"怎么把窗口证据给得更好"的
技术问题；本层是**对象错误**——再给得更好也救不回来。

裁定原话要点：**应该站在软件的角度——人类审核的是"AI 有没有操作这个软件的权限"，
不是什么"AI 有没有操作某个窗口的权限"。以西柚为例，西柚有很多人类看不见的窗口，
可对于人类来说，西柚只有一个窗口，他们感知不到那些你能感受到的隐藏窗口。**

据此得出三条设计约束，本单后续所有措辞与取图动作均须服从：

1. **授权主体是软件（进程/exe），不是窗口。** 白名单条目、审批对象、撤回对象
   自始都是进程（`policy.whitelist` 以进程名为键），**窗口只是软件的一个呈现面**。
   证据面若以"窗口"为叙事单位，就把人类拖进了一个他感知不到的抽象层。
2. **证据必须落在人类可感知的维度上。** 隐藏窗、最小化窗、幽灵窗——人类感知不到，
   **呈现它们即等于要求人类审一个看不见的东西**，这正是 ISS-0073 自身反对的形态
   （把系统内部状态当证据给人看）。**v0.4 曾把 `include_hidden=True` 的枚举结果
   列为候选清单，该方向已被本条裁定证伪并撤销。**
3. **同进程多窗口是软件内部结构，不是授权面。** 人类对"西柚"的心智模型是**一个**
   应用；弹窗里列"另有 3 个窗口"是把实现细节当成裁决信息，制造噪声而非证据。

**由此推翻 v0.4 的 §2.5 附带项**：`:378` 那个 `ShowWindow(hwnd, 9)` 无条件还原
隐藏窗，不只是"未报账的副作用"——它是**从托盘里把一个用户从未打开、从未见过面的
窗口拽到前台再拍照，要求人类为其背书**。这比列进清单更严重。
**处置：删除该还原动作**。隐藏窗不取证、不置前；如实陈述"该软件当前无可见窗口，
未截图"。**人类看不到的东西，不进人类裁决面。**

**审计面与人类裁决面分离**：窗口级明细（含隐藏窗）可以留审计供事后回溯，
但**不进弹窗**——弹窗只承担"人类此刻能感知到的证据"。

### 2.2 "目标无法前置"是伪告警——把"我方校验没过"说成了"目标不给置前"

该措辞（`enforcement.py:397`）把一次**我方的判据未通过**，叙述成**目标的抵抗**。
文字上"目标无法前置"读作"我们想置前，它不肯/办不到"，而实际上：

1. `activate(hwnd)` 是**真的调了**的（这点原稿写错，此处更正）；
2. 失败点是**紧随其后的中心点归属校验**，不是激活动作本身；
3. 更要命的是：**`ShowWindow(hwnd, 9)`/`activate` 会把目标窗口拉到前台**——
   为了取证而抢焦点，在 `attach` 这个语义下是**越权副作用**（见 §2.4.3）。
   **〔v0.4 定案更正〕**：此判读已被 sdfang 在 §4 Q2 推翻——MCP 工具本就是
   "让 AI 接管电脑"的，不存在与人共用鼠标键盘的场景，**置前取证不算越权**，
   反而是透明性（人类看得见 AI 在看哪个窗口），与人类自身操作习惯一致。
   本条第 3 点降级为"**副作用须报账**"，不作"越权"论。

于是同一句话同时犯两个错：**归因错误**（是"校验未过"，不是"无法前置"）与
**掩盖副作用**（为取证抢过焦点，报告里只字未提）。

### 2.5 置前结果被丢弃——`_shot_verified` 单方面撕毁 fail-closed 契约

**（v0.4 新发现，实证如下）**

`enforcement.py:396-409` 真实代码：

```python
for _attempt in range(2):
    activate = getattr(self._executor, "_activate_if_needed", None)
    if callable(activate):
        activate(hwnd)                                    # ← 返回值被丢弃
    else:
        ctypes.windll.user32.ShowWindow(hwnd, 9)          # ← 硬编码 SW_RESTORE
    if self._center_belongs(rect, hwnd):
        self._capture_note += "（已前置实拍）"
        return self._executor.capture_approval_shot(rect)
self._capture_note += "（实拍存疑：目标无法前置，未截图）"
return None
```

两侧契约对比：

| 位置 | 契约 |
|------|------|
| `core.py:924-931` `_activate_if_needed` | docstring：**"返回是否已处前台（fail-closed：写路径调用方必须检查）"**；`return bool(self._probe.activate(hwnd))` |
| `probe.py:108-142` `activate` | AttachThreadInput + SetForegroundWindow + BringWindowToTop，≤3 次短退避重试，**最终失败 `return False`（ISS-0017 A：绝不成功假象）** |
| `enforcement.py:399` `_shot_verified` | **`activate(hwnd)` 不带赋值，返回值直接丢弃** |

即：**生产者一头的 fail-closed 契约是完整实现的，断在消费者这一头。** 后果是
"置前失败"与"置前成功但中心点仍被别人压着"在代码里**不可区分**，被合并叙述为同一句
伪告警"目标无法前置"。这与 §2.2 是**同一根因的另一半**——§2.2 说归因错，
本条说**归因所需的那个事实，从一开始就没被读**。

同函数内另有两处同类问题（均属本单要重写的函数体，不另开单）：

- `enforcement.py:403` 兜底分支**硬编码 `ShowWindow(hwnd, 9)`**，绕开 `ISS-0041`
  确立的"按执行时刻窗口状态选命令"（`IsIconic`→RESTORE／`IsZoomed`→SHOWMAXIMIZED／
  其余→SHOW）。取证路径因此**不受 ISS-0041 修复的覆盖**。
- `:378` 的隐藏窗还原：**〔v0.5 处置升级，见 §2.1b〕** 原判为"无条件还原、未报账"，
  现据 Q3 裁定改为**删除该还原动作**——隐藏窗不取证、不置前、不进人类裁决面。
  （其"无条件"缺陷随之消失，无需再议。）

**附带实证（记入待查，不顺手改）**：`probe.py:64` 把枚举结果的 `"visible"` 字段
**硬编码为 `True`**，`include_hidden=True` 时同样如此；全仓唯一读点
`enforcement.py:369` 的 `w.get("visible", True)` 因此**恒真**——"可见在屏优先"这个
过滤条件当前**实际不生效**。本条与 Q1/Q3 均相关（两者都以"可见性"为判据），
但根因在枚举层，不在本单函数体内，故只登记不动。

### 2.4 真实风险

1. **盲批**。人类按显示名判断。显示名来自进程窗口标题或版本信息，**AI 可控**——`窗口标题` 可被任意程序设为任意字符串。人类看到的"西柚加速器"四个字，不构成对目标进程的独立确证。
2. **AI 友好面反向恶化**。工具=物理层、判断归 AI 的裁定在这里被绕开：系统**替人类**下了一个"校验没过所以不截图"的判断，并把结论以"目标无法前置"的形式呈现给人类——人类无从知道这个结论来自单点判据、还是目标真的不可见。
3. **为取证抢焦点：定案为"不算越权，但须报账"**（§4 Q2，v0.4 定案）。原稿按"越权副作用"论，**已推翻**——MCP 工具定位就是 AI 接管电脑，无人机共用场景；置前取证是对人类透明（看得见 AI 在看哪个窗口），与人类操作习惯一致。保留的义务只有两条：**① 文案与审计如实声明"已置前取证"；② 置前成败必须如实呈现**（§2.5：现状连成没成都丢了）。
4. **裁决不可复核**。审计事后回溯时，人类当时看到的是什么？——只有文字，无图。事后申诉无依据。

## 3. 整改方向（待评审细化）

| # | 方向 | 说明 |
|---|------|------|
| A | **判据放宽（Q1 已定案 ②+③）**：中心点单点归属 → **五点采样（四角+中心），过半归属即出图**，且不论通过与否均如实标注遮挡状态 | 目标仍占据大部分面积时应给出实拍，并如实标注遮挡情况；单点判据对"部分遮挡"零容忍，而那恰是最需要看图的情形 |

**约束**：

**Q5 备选（存档，已否决）**：① 仅明示（**采纳**）；② 明示 + 默认焦点强化在"拒绝"（否决——**待核实现状**一项随之关闭，见 T3 去向）；③ 明示 + 无实拍时禁用「永久加入」（否决，代价提示如下，存档以备将来若现场反馈"人类仍被误导"时重启）。

**Q5 的代价提示（③ 已否决，仅存档）**：人类只剩「本次会话允许」这一条临时通路，每重启批一次；恢复长期授权的唯一出口仍为 **ISS-0072 Q1 既定通路**——人类在白名单管理窗口中手动操作（可走通，但多三步）。常年取不到图的软件（全屏独占/DRM/双屏错位）会落到这条路上。**否决理由再述**：该代价落在"常年取不到图的软件"这一少数群体上，而 ③ 的收益（防人类误点）在无实拍已显著明示的前提下**无法证实**——用可证实的代价换不可证实的收益，不划算。
