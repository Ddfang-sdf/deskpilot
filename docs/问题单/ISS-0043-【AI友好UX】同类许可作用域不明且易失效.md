# ISS-0043：【AI友好/UX】"此后同类允许"作用域不明且对重绑目标近乎失效

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0043 |
| 标题 | "此后同类允许"不展示作用域(同绑定令牌+本次会话),用户合理预期"以后别弹"却反复弹;且许可键为绑定令牌——TTL 重绑/重新 attach/daemon 重启/桌面 hwnd 易变全部使之失效 |
| 严重级 | **中**(UX 预期与机制错位;桌面类高频目标上会话许可近乎无用) |
| 状态 | **已关闭(A 层文案+B①许可键 hwnd+tool,均由 ISS-0053 收敛落地;B②持久许可不实施——未获授权;考古发现 esc 之痛真因是 ISS-0019 豁免面静默降级,见 ISS-0053)** |
| 提出 | 2026-09-08(sdfang 实证:多次点"此后同类允许"仍反复弹窗;代码取证 approval.py:102-108) |

## 1. 背景(实证)

2026-09-08 测试期间,桌面 esc(危险键类)反复触发 L3 审批,用户每次点
"此后同类允许"仍反复弹。代码机制:
`approval.py:102-105` —— approve_session 签发 window_session 令牌,
键=(tool, **binding_token**);闸四 `session_scope_of(tool, binding_token)`
比对。失效三连环:
① 每次 attach 产生新绑定令牌(TTL 600s/重新 attach)→ 旧许可查不到;
② 令牌仅存 daemon 内存 → daemon 重启全灭;
③ 桌面 Progman hwnd 易变(131500→65896→132264→65890 实测),
连"同窗口"前提都不稳。
另:弹窗按钮文案只有"此后同类允许",**未展示作用域**——预期管理失败
(approval_dialog.py:183 注释写明"本窗口,本次会话",但 UI 不可见)。

## 2. 整改方案(两层,A 层直改,B 层评审)

| 层 | 内容 | 性质 |
|----|------|------|
| A | **作用域可见化**:审批弹窗在"此后同类允许"按钮附近明示"仅本次会话·此窗口绑定有效(daemon 重启/重新绑定后需重批)"——预期与机制对齐 | 文案级,低风险 |
| B | **许可键评审**:①会话许可键从 binding_token 改为 hwnd+tool(重绑不失效,桌面 TTL 场景可用);②是否提供"持久同类许可"(跨会话,写入 policy.local.yml)——**涉安全语义变更,必须 sdfang 评审**,禁止直接实现 | 设计评审 |

### 约束

- A 层不改任何判定逻辑;B 层未评审不动代码;
- 测试设计(五要素)于各自评审通过后产出。
