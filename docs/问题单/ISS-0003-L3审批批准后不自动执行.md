# ISS-0003：L3 审批批准后不自动执行，执行依赖 AI 重试

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0003 |
| 标题 | L3 审批"批准一次"后操作不自动执行，须 AI 原样重试才落地；批准无执行回执，存在 TOCTOU 窗口 |
| 严重级 | 中（可用性/交互缺陷。注：提出时疑为"安全漏洞、确认形同虚设"，经源码核对不成立——闸门有效，见 §2 分析） |
| 状态 | 已关闭（2026-08-21 验收通过：201 测试全绿；实盘拒绝/超时/批准三路径同步闭环，批准即同调用执行、目标窗口关闭） |
| 提出 | 2026-08-21（A 机实盘：MCP 全量手工测试，用户批准 alt+f4 后记事本未关闭） |

## 1. 问题现状

1. **批准后"没反应"**：AI 发起 L3 操作（alt+f4 关闭记事本）→ 弹审批窗 → 用户点
   "批准一次"→ 窗口未关闭，无任何后续动作。用户视角等同"确认无效"。
2. **实际链路**：闸四为 fire-and-forget（详细设计 §2.4 既定设计）——弹窗同时立即返回
   NEEDS_APPROVAL；人类批准后审批通道按操作指纹在服务端内部签发一次性令牌
   （令牌不经 AI，INV-4）；**须 AI 以完全相同参数重试**，闸四查证指纹并消费令牌后才执行。
3. **TTL 过期即作废**：approval_ttl 默认 60 秒。实盘：用户批准后 AI 未在 60 秒内重试，
   重试时已 NEEDS_APPROVAL（重新弹窗）——批准动作静默失效，用户不知情。
4. **TOCTOU 窗口**：批准时的目标状态与 AI 实际重试执行时的状态可能已变化
   （如同一窗口内容已被修改），指纹只绑定工具+参数+目标窗口，不绑定目标内容状态。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **执行触发留在 AI 侧** | 审批通过后 daemon 只签发令牌，不持有挂起操作的调用上下文，也没有"批准即执行"路径；执行与否、何时执行完全取决于 AI 是否/何时重试。 |
| R2 | **无执行回执** | 批准 →（AI 重试）→ 执行，全程无面向人类的确认反馈；AI 不重试时批准静默落空。 |
| R3 | **TTL 与人工节奏不匹配** | 60 秒 TTL 内须完成"人批准 + AI 重试"两个独立动作；任一延迟即过期，且过期无提示。 |

**安全定性（对用户疑虑的正式答复）**：确认动作**并非形同虚设**——不批准则操作
永不执行（fail-closed）；AI 无法自我批准、无法伪造令牌、改任一参数指纹即失效
须重新批准、令牌一次性消费。"批准后才执行"不等于"审批无效"，当前缺陷的方向是
**可用性**（批准可能落空），不是安全性（未批准不会执行）。

## 3. 整改方案

### 3.1 总体

改 fire-and-forget 为**同步阻塞审批**（2026-08-21 老板定夺）：AI 发起 L3 调用后，
强制层挂起该调用并弹出审批窗，等待人类裁决（≤ approval_ttl）：

- **批准** → daemon 直接执行该挂起操作，执行结果作为本次调用的响应原路返回；
- **拒绝/超时** → 以明确错误码返回（告知 AI 人类已拒绝/超时），操作永不执行。

AI 自发起后完全退出决策与执行环路——无重试、无令牌感知；授权记录（指纹绑定、
一次性、限时）仍在服务端内部流转，INV-4 保持。

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | 闸四改同步等待：挂起完整调用上下文（工具+参数+目标）；审批通道回调直接驱动执行层按挂起参数执行，结果作为原调用的响应返回；NEEDS_APPROVAL 重试路径整体移除 |
| B | 拒绝/超时返回明确错误码（人类拒绝与超时区分），审计记录裁决与执行/未执行结果 |
| C | 传输层配套：httpd remote_call 超时与 MCP 客户端超时须 > approval_ttl（当前 remote_call 30s < 默认 60s，必须调整）；明确写锁在人类决策期间的持有语义（串行即 fail-closed，可接受） |
| D | 弹窗冷启动延迟优化：onefile 子进程解压需数秒，占用人等窗、窗等裁决的预算——评估常驻弹窗进程或预热机制 |
| E | TOCTOU 收窄：执行前复核目标窗口 hwnd 一致性，目标已变则拒绝执行并记审计 |

### 3.3 约束（fail-closed 保持）

- 不批准不执行、授权不经 AI、一次性、参数不可变更——四条不变量全部保持
- 阻塞等待上限 = approval_ttl，超时即拒绝（禁止无限挂起）
- 同步执行仅针对"本次批准的指纹"，不得泛化为会话级放行

## 4. 测试方案

### 4.1 单元

| 用例 | 断言 |
|------|------|
| 批准即执行（单次调用闭环） | 模拟批准通道批准 → 一次 call_tool 直接返回执行成功；执行层收到完全相同参数；无第二次调用介入 |
| 拒绝返回错误 | 模拟拒绝 → 本次调用返回拒绝错误码；执行层零调用；审计含裁决事件 |
| 超时返回错误 | 模拟通道超时 → 返回超时错误码；执行层零调用 |
| 参数不可漂移 | 挂起参数与执行参数逐字段一致（执行层收到的指令 = 发起时的请求） |
| 目标变更拒绝 | 裁决与执行之间 hwnd 失效/变更 → 拒绝执行并记审计 |

### 4.2 集成验收

- 全量 pytest 绿
- 实盘：一次 alt+f4 调用 → 弹窗点"批准一次" → 窗口随即关闭，且**本次调用直接返回成功**（无需任何重试）；点"拒绝"→ 本次调用返回拒绝错误，窗口保留
