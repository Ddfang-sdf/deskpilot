# ISS-0022：按键可发现性——KEY_UNKNOWN 带清单与"未执行"明示，浏览器组合键收录策略

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0022 |
| 标题 | 按键许可表对 AI 不可见（ctrl+t 被拒逼出像素绕行）;KEY_UNKNOWN 文案未声明执行语义，已致一起"报错但已执行"误报 |
| 严重级 | **中**（体验 + 错误语义消歧；含一项策略决策点） |
| 状态 | **实现完成,457 用例全绿(唯一红=ISS-0018 哈希另案),待实盘验收** |
| 提出 | 2026-09-03（外部 40 次调用实录反馈 + 审计 seq 60 实证） |

## 1. 问题现状

1. **许可表不可见**:`key=ctrl+t` 返回 KEY_UNKNOWN（审计
   audit-20260903.jsonl seq 60),AI 无任何渠道知道哪些键可用——
   错误不带清单、无查询工具、工具描述未列，只能试错或退回像素点击
   （实录：50 秒后被迫 click "+"钮坐标绕行）。
2. **错误语义模糊致误报**：外部 AI 被拒后下一张截图看到新标签，
   误判"报错但动作已执行"，指控 fail-closed 失效。**已取证证伪**
   （enforcement.py:194-199 闸三先于派发；seq 60 拒绝 0ms 无证据图；
   拒绝与截图间零写操作）——但文案只说"未收录",未明示"未执行",
   歧义是误报的土壤。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **按键表是策略内部数据** | AI 运行时无可见渠道（错误/查询/描述三缺） |
| R2 | **KEY_UNKNOWN 未声明执行语义** | "未收录"≠"未发送任何按键",AI 可与"已执行"混淆 |
| R3 | **收录策略未覆盖浏览器场景** | ctrl+t/ctrl+l 等浏览器高频组合未收录，逼出像素绕行 |

## 3. 整改方案

| 项 | 内容 |
|----|------|
| A | **KEY_UNKNOWN message 扩展**:`按键未收录（fail-closed，本次未发送任何按键）: {key}。当前可用 L2=[…] L3=[…]`——清单由 policy 键表直出，单行紧凑（≤400 字符） |
| B | **key 工具描述补**: "按键须在许可表内；未收录返回 KEY_UNKNOWN 并列出现行可用键；拒绝时不发送任何按键" |
| C | **收录策略扩展（✅ 2026-09-03 sdfang 批准全收 L3）**:`ctrl+t`(新标签)、`ctrl+n`(新窗口)、`ctrl+l`(地址栏)、`ctrl+tab`/`ctrl+shift+tab`(切标签)、`ctrl+r`(刷新)入 `policy.yml` 键表 `l3_controlled`(policy.yml:59-64)。批准理由(已记录)：与 ctrl+w/alt+tab 同属窗口/标签/焦点生命周期族；键语义随应用漂移只能按最坏解释归类;ctrl+l 是"导航到任意 URL"的唯一闸门;KEY_UNKNOWN 拒收会把 AI 逼进无审批的像素暗道,收录 L3 反而纳入审批+审计 |

### 约束

- 清单必须由 policy 键表**直出**（禁止另维护一份副本，单源）;
- C 项只动 `policy.yml` 键表（配置层）+ dist 同步 + 哈希一致测试照常；
- message 前缀"按键未收录（fail-closed）"不变（向后兼容），追加部分
  以句号分隔。
