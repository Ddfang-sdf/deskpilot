# ISS-0054:【设计引入】图标三源装配按序对齐——自定义排列下 UIA 与 PIDL 枚举序分叉,装配全灭

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0054 |
| 标题 | DesktopIconAssembler 假设 UIA 列表与 IFolderView PIDL 枚举**同序**(索引对齐+首项虚拟一致性检查);桌面一旦被手动整理/自定义排列,两视图顺序分叉 → 「序对齐失败」INTERNAL_ERROR,list_desktop_icons 整体不可用,F5 刷新不归位 |
| 严重级 | **中**(核心感知能力在常见桌面状态下全灭;REQ-002 交付能力的潜伏假设,桌面编辑后触发) |
| 状态 | **已修复(方向①按名归并:sdfang 批准进 v0.3.6;TC-54-01~04+真机乱序桌面 icons09/10 转绿)** |
| 提出 | 2026-09-10(v0.3.6 发布阻塞排查中实机发现:sdfang 清理桌面后装配失败;今晨同机 31 图标装配曾正常) |

## 1. 背景(实证链)

| 时刻 | 桌面状态 | 装配结果 |
|------|---------|---------|
| 2026-09-10 09:xx | 31 图标(默认/整齐排列) | ok,回收站首项双视图一致,source 归并正确 |
| 2026-09-10 下午 | sdfang 清理/重排后 23 图标 | INTERNAL_ERROR「序对齐失败:首项虚拟一致性——uia='回收站' 而 shellview 有路径 '微信.lnk'」;F5 后仍败 |

机制:UIA ListView 项序≈可视网格序;IEnumIDList 枚举序随 PIDL 内部次序
——默认排列下两者恰好一致,**自定义排列/编辑后分叉**。装配器按索引对齐并
用"首项应为虚拟回收站"做对齐校验,序一岔即全灭(fail-closed 本身没错,
错在对齐假设)。

## 2. 整改方向(待评审)

| # | 方向 | 说明 |
|---|------|------|
| ①(倾向) | **按名归并**:PIDL 路径文件名去扩展名 ↔ UIA display 名归并进 source;索引仅用于 LVIR 图形矩形(同窗同进程同源,序天然一致);重名(罕见)fail-closed 附指引 | 根除序假设 |
| ② | 首项检查放宽为存在性检查(回收站可在任意位),其余仍索引对齐 | 治标:序分叉下 source 仍会错配 |
| ③ | 失败错误加 AI 自愈指引(「桌面视图编辑中,稍后重试」) | 对瞬态有用,对本例(持续分叉)无效 |

### 约束

- 归并不许错配(source 安错图标比没有更糟——拿不准就 null+明示);
- 数量不一致仍 fail-closed(装配诚实原则不动);
- 测试设计(五要素)评审后产出:核心用例——替身三源乱序(回收站不在首位)
  → 按名归并正确(直出);重名 → 拒绝+指引(直出)。
