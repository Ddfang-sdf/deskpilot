# ISS-0018：路径与配置一致性（截图绝对路径 / policy 单源化）

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0018 |
| 标题 | screenshot 返回相对路径导致客户端被迫全盘扫描定位文件；dist\policy.yml 与 repo policy.yml 双轨漂移（90s 审批时限未生效实证） |
| 严重级 | **中**（客户端体验断点 + 配置漂移已实际咬人：60s/90s 实证） |
| 状态 | **已关闭**（2026-09-02 验收通过：3 用例先红后绿 + 全量 413 全绿；dist 与 repo 策略哈希一致；截图绝对路径生效） |
| 提出 | 2026-09-02（fresh Claude"全目录扫描超时定位 audit 目录"实证；dist 60s vs repo 90s 实证） |

## 1. 问题现状

1. **截图返回相对路径**：`screenshot` 返回 `audit\shots\...` 相对路径，
   客户端不知道基准目录，被迫全盘扫描定位（fresh Claude 原话"全目录
   扫描超时了。用 PowerShell 快速定位 deskpilot 服务的 audit 目录"）。
2. **策略双轨漂移**：frozen daemon 优先读 exe 同目录 `dist\policy.yml`，
   而开发修改的是 repo 根 `policy.yml`——`approval_ttl` 改 90 只进了
   repo,dist 仍是 60（2026-09-01 弹窗倒计时 60s 实证：生产从未生效）。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **返回路径相对化** | `_save_shot` 只产出相对路径，基准目录语义只存在于服务端，客户端无从解析 |
| R2 | **策略双真源** | repo policy.yml（开发改）与 dist\policy.yml（运行读）各自为政，无同步机制无漂移检测，必然漂移 |

## 3. 整改方案

### 3.1 总体

**路径绝对化（客户端零猜测）；策略单源化（repo 为唯一真源，构建/同步强制一致）。**

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | **screenshot 返回绝对路径**：`_save_shot` 产出路径按审计目录基准解析为绝对路径返回（width/height/coord_space 等字段不变）。 |
| B | **policy 单源化**：repo 根 `policy.yml` 为唯一真源；构建期同步进 exe 同目录（本地构建即时同步一次并纳入构建脚本/流水线校验）；启动审计已含策略指纹（ISS-0012 C），据此可核对运行文件与真源一致性。 |
| C | **文档**：INSTALL.md 明确"policy.yml 由构建同步产出，手改会被下次构建覆盖"。 |

### 3.3 约束

- 绝对路径解析失败不得静默（fail-closed 报错而非回退相对路径）。
- 不自建第二策略源；流水线产物策略必须经哈希一致性校验。

## 4. 测试方案

### 4.1 单元/集成（先行）

| 用例 | 断言 |
|------|------|
| 截图绝对路径 | screenshot 返回 path 为绝对路径（Path.is_absolute 直出）且文件存在 |
| 真源一致 | 同步后 file_sha256(repo policy.yml) == file_sha256(dist\policy.yml)（数据层直出） |
| 流水线同步步骤 | release.yml 含 policy.yml 拷贝/校验步骤（YAML 直出） |

### 4.2 集成验收

- 全量 pytest 绿
- fresh Claude 复测：截图返回路径可直接打开，无需扫描
