## 1. 现场实证

**代码事实**（实测命令见 §4）：

| 位置 | 事实 |
|------|------|
| `deskpilot/executor/core.py:72` | `self._som_cache: dict[int, dict] = {}` —— 初始化 |
| `deskpilot/executor/core.py:343` | `self._som_cache[i] = {...}` —— **唯一写入点**，逐键赋值 |
| `deskpilot/executor/core.py:567` | `entry = self._som_cache.get(int(som_id))` —— 唯一读取点 |
| 全文搜索 `_som_cache.clear` / `.pop` / 整表赋值 | **零命中** —— 缓存**从不清理**，无逐出、无重建 |

**失效机制只有一条**：`core.py:568-569` 的三重判定
（`entry is None` / `entry["hwnd"] != hwnd` / `self._clock() > entry["expires"]`）。
即**只有 60 秒过期**会让编号失效；"本次取图没给出这个编号"**不构成失效**。

**触发链**：

1. 第一次取图，窗口有 10 个可交互元素 → `_som_cache[1..10]` 全部登记，过期时刻 = 当刻+60s；
2. 窗口布局变化（切换标签页 / 面板折叠 / 列表换行 / 分辨率变化）后**再次取图**，
   本次只有 3 个可交互元素 → `_som_cache[1..3]` 被**覆盖**，`[4..10]` **原样留着**；
3. 第二次取图的图与响应只列 1~3 号。AI 若仍持第一次的图（或误用记忆中的编号）
   调 `click_element(som_id=7)`；
4. `_som_cache[7]` 命中，`hwnd` 一致，未到 60s → **通过校验**；
5. 走 `_resolve_unique_element(root, name=旧名, automation_id=旧Id)` —— 若该元素
   在新布局下**仍存在**（只是不再属于本次可交互集合，例如变成了零面积或被禁用），
   解析成功 → **点击到该元素**，返回 `status: "ok"`。

**后果**：AI 以为点了第 7 号（新图上是别的东西或不存在），实际点了另一个元素，
且**没有任何信号提示它用的编号已作废**。这是工作纪律明令禁止的**静默降级**形态：
错误动作以成功回报。

## 2. 根因（机制层）

**缓存的生命周期被设计为"跨调用累积"，而编号的生命周期是"单次取图"。**

`_som_cache` 的键是**序号**（`1..N`），值是**该序号在某一刻指向的元素**。
序号空间由**每次取图的条目数**决定（`get_clickable_map` 里
`enumerate(interactable, start=1)`），而缓存却是**跨取图的长期字典**。
两者生命周期错配：序号的含义每次取图都会整体重排，缓存却假定序号含义稳定。
于是"N 变小"这一常见事件必然留下**含义已过期但未过期（时间上）**的条目。

**为什么一直没暴露**：既有 5 条 SoM 用例（`tests/test_m3.py`）覆盖的是
过期（推进时钟 61s）、跨窗（换 hwnd）、命中、空窗——**没有一条是"两次取图、
第二次条目更少、用第二次没给出的编号点击"**。测试设计的场景集缺了
"缓存与本次清单的一致性"这一维度，所以缺陷在纯 UIA 空间潜伏至今。

**REQ-003 为何把它放大**：引入 detect 后条目数**每次调用都会变**（检测结果
随画面波动），"N 变小"从偶发变成高频。因此 REQ-003 功能设计 FD-05 已把
"每次取图整表替换"定为本单的处置口径——但**缺陷本体在纯 UIA 空间已存在**，
不是 REQ-003 引入的，故按范围控制纪律**单独建单**，REQ-003 只在其交叉面
清单里引用本单。

## 3. 影响面

| 面 | 影响 |
|----|------|
| AI 侧 | 持过期编号点击 → 命中错误目标且报 ok；无自诊断线索，违反"错误必可自愈" |
| 安全面 | **不越闸**：仍受绑定校验（hwnd 必须匹配）与既有四道闸约束，不构成越权路径；影响是**准确性与可诊断性**，不是权限 |
| 既有测试 | `tests/test_m3.py` 5 条不受影响（成因不同，见 §2）；`tests/test_clicktarget_iss44.py` 的 som_id/control_type 互斥不受影响 |
| REQ-003 | 其功能设计 FD-05 提供同一处置；本单是**该口径的独立动因**，两单互指 |

**验收用例（红→绿）**：

| # | 场景 | 断言 |
|---|------|------|
| 1 | 取图 A（3 元素）→ 取图 B（5 元素）→ 用 B 的编号 5 点击 | 命中 B 的第 5 个元素（整表替换后编号按新表解析） |
| 2 | 取图 A（5 元素）→ 取图 B（3 元素）→ 用 B 未给出的编号 4 点击 | **显式 ELEMENT_NOT_FOUND**（含取图指引），**零点击**（替身计数为 0） |
| 3 | 取图 A（5 元素）→ 取图 B（3 元素）→ 用 1~3 点击 | 命中 B 对应元素（新表生效，非旧表） |
| 4 | 取图 A → 推进时钟 61s → 任意编号 | 既有过期行为不变（回归） |

**断言出处**：用例 1/3 断言点击替身收到的元素标识（由 `_invoke_element` 调用面直出）；
用例 2 断言异常码与替身调用计数（由 `_click_element` 返回值/异常与替身计数直出）。

**修复方向（待方案评审，本单不定实现）**：`get_clickable_map` 内以**局部新表
构建完毕后整表替换** `self._som_cache`（含 REQ-003 的 detect 诊断表同规矩）。
