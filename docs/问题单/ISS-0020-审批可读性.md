# ISS-0020：审批可读性——"我对要审批的命令一无所知"

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0020 |
| 标题 | 审批弹窗内容不可读：内容型操作主标题零内容（命令文本埋在 8px 灰字）；无绑定审批一律无图（入白/attach/launch)，用户"一开始都不知道是审批啥的" |
| 严重级 | **高**（审批是可理解性依赖的人机裁决——看不懂在批什么，批准权形同虚设） |
| 状态 | **已关闭**（2026-09-02 验收通过：7 用例先红后绿 + 全量 434 全绿；主标题带内容/无绑定反查实拍+全屏退化/取图失败留痕全部落地） |
| 提出 | 2026-09-02（sdfang 实盘：审批终端操作时对命令一无所知；两个 attach 弹窗均无图） |

## 1. 问题现状

1. **主标题零内容**：type_text/set_clipboard 等内容型操作，主标题只有
   "输入文本「目标」"——命令文本只在 8px 灰色技术底注的参数摘要里
   （`enforcement._TOOL_ACTIONS` + `_describe` 实证），审批决策不可读。
2. **无绑定必无图**：`_capture_target` 规则 `binding is None → None`
   （实证），三类审批天然无图：入白（闸二早于绑定）、attach（批准后
   才建绑定，sdfang 批的两个终端 attach 均无图）、launch_app（目标尚不存在）。
   取图异常同样静默 None（无日志）。
3. **底注上限不明**：参数摘要为全量拼接，64K 输入可撑爆布局。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **主标题按动作类型生成、不带参数** | `_TOOL_ACTIONS` 静态动作短语，内容参数仅进技术底注 |
| R2 | **取图只认绑定** | `_capture_target` 只从 binding 取矩形；审批发生在绑定前的场景（入白/attach/launch）一刀切无图 |
| R3 | **失败静默** | 取图异常 `except → None`，无任何留痕 |

## 3. 整改方案

| 项 | 内容 |
|----|------|
| A | **内容进主标题**：type_text/type_element/set_clipboard 主标题带截断文本（≤60 字，超长以 … 结尾并标注"共 N 字"）；click/drag 带坐标；key/launch 现有语义不变 |
| B | **底注完整参数**：参数摘要上限 500 字，超出截断并标注总长 |
| C | **无绑定反查实拍**：无绑定时按请求目标进程 find_windows 反查，命中即拍该窗口；反查不到退化全屏并在底注标注"无目标实拍，此为全屏上下文" |
| D | **取图失败留痕**：异常写审计事件"审批取图失败"（不再静默） |

### 约束

- 文本截断不改变操作本身语义（截断仅用于展示）。
- 反查失败/取图失败不得阻断审批流（但必留痕）。

## 4. 测试方案（TC-READ-01~07）

| 用例 | 断言 |
|------|------|
| READ-01 type_text 主标题含文本 | headline 含命令文本（直出） |
| READ-02 超长截断 | headline ≤63 字、以 … 结尾、含"共 N 字"（直出） |
| READ-03 set_clipboard 含摘要 | headline 含前 60 字与总长（直出） |
| READ-04 click 含坐标 | headline 含 (x, y)（直出） |
| READ-05 key/launch 回归 | "按下 alt+f4"/"启动应用"在主标题（直出） |
| READ-06 无绑定反查 | 按进程反查命中 → 返回该窗口实拍路径（直出） |
| READ-07 取图失败留痕 | 审计含"审批取图失败"事件、返回 None（直出） |
