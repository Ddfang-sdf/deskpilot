# ISS-0029：删除 ALL_REASON_CODES 死代码登记册

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0029 |
| 标题 | `errors.ALL_REASON_CODES` 全库零消费且漏登 TOOL_TIMEOUT——死代码;sdfang 裁定删除(不接线) |
| 严重级 | **低**（代码卫生;消除"有登记册"的误导性安全幻觉） |
| 状态 | **建单,待评审** |
| 提出 | 2026-09-04（ISS-0023 勘察发现;sdfang 裁定:废代码提单删除） |

## 1. 问题现状

`deskpilot/errors.py:41` 定义 `ALL_REASON_CODES` frozenset(意图为错误码
总登记册),全代码库无任何消费方(实证:仅定义处一处引用),且漏登
ISS-0009 引入的 TOOL_TIMEOUT。存在即制造"错误码被登记守护"的假象。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **守护从未接线** | 登记册创建时无消费方,后续演进无人维护,与真实错误码集合脱节 |

## 3. 整改方案

| 项 | 内容 |
|----|------|
| A | 删除 `ALL_REASON_CODES` 定义(sdfang 裁定:不接线、直接删) |
| B | 增加负向守卫测试:断言 `not hasattr(deskpilot.errors, "ALL_REASON_CODES")`——防止死代码复活 |

### 约束

- 错误码常量本身全部保留(运行期在用),只删登记册集合;
- 不新增任何"错误码合法性"运行时校验(已裁)。

## 4. 测试设计(五要素)

| 用例 | 场景 | 前提 | 步骤 | 预期结果 | 断言代码 |
|------|------|------|------|----------|----------|
| TC-RM-01 | 登记册不存在 | — | `hasattr(deskpilot.errors, "ALL_REASON_CODES")` | False（当前 True→红,删除后绿） | hasattr 直出 |
| TC-RM-02 | 全库无引用 | — | 全量回归 | 全绿（无 import 断裂） | 套件通过 |

装配守门:R1 无装配;R2 无打桩;R3 hasattr 形态断言;R4 路径变迁=
errors.py 删段;R5 终效应=TC-RM-01 转绿。
