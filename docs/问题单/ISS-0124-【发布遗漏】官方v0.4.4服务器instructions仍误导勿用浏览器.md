# ISS-0124:【发布遗漏】官方 v0.4.4 服务器 instructions 仍误导「勿用本服务操作浏览器」

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0124 |
| 标题 | 官方 v0.4.4 已交付浏览器翻译层，却仍在 MCP initialize 中注入「浏览器任务勿用本服务」旧说明；REQ-008 修复未进入发布包 |
| 严重级 | **中**(AI 路由误导：浏览器能力实际存在，服务器级说明却要求 Agent 避开，可能导致浏览器任务被放弃或错误改道) |
| 状态 | **源码整改已完成，待官方新版发布与实包复核** |
| 提出 | 2026-11-13 Kimi Code 接入官方 v0.4.4 后，用户要求核查服务器注入 instructions |

## 1. 实证链

1. 从官方 GitHub Releases 下载并校验 `deskpilot-v0.4.4-windows-x64.zip`，安装至 `C:\tools\deskpilot`；未使用本地源码打包。
2. 以独立 MCP stdio 客户端对官方 exe 执行 `initialize`，服务器实际返回：

   > 本服务操作 Windows 桌面与原生应用窗口(截图/元素树/键鼠);浏览器标签页、网页、DOM 元素的任务请使用浏览器专用工具,勿用本服务(本服务截不到网页,只能截真实桌面)。

3. 同一官方服务器 `list_tools` 实际返回 32 个工具，包含 `browser_snapshot` 与 `browser_get_rect`；`screenshot` 实调成功。说明浏览器能力存在，限制性说明与产品能力矛盾。
4. 发布提交 `02b23d2`(v0.4.4)的 `deskpilot/mcp_server.py` 仍内联上述旧文案；REQ-008 修复提交 `e0ba68f` 晚于该发布，且未包含于任何既有 tag。

## 2. 根因

这是**发布遗漏**，不是浏览器执行层失效：

- REQ-005 已在 v0.4.4 交付浏览器感知与定位工具；
- 服务器级 instructions 旧句在 REQ-008 中才完成纠正、单源化和生产装配接线；
- v0.4.4 发布后未再发行包含 REQ-008 的官方包，导致用户实际安装到的初始化说明仍是旧版。

## 3. 已落整改

REQ-008 已完成源码整改，本单不重复改写正确文案：

- `deskpilot/i18n.yml` 的 `mcp.instructions` 改为正确路由：网页内容先经 `browser_snapshot` / `browser_get_rect` 感知和定位，再使用既有键鼠工具行动；
- `deskpilot/mcp_server.py` 的 `Server(..., instructions=...)` 改走 `i18n.mcp_instructions()`，移除内联旧句；
- `tests/test_mcp_instructions_req008.py` 已有 TC-R8-06 旧句零残留、TC-R8-07 生产装配相等、工具名真实存在等约束；
- `tests/test_boundary_iss15.py` 已有生产 `build_server().instructions` 含 `browser_snapshot` 的回归钉。

## 4. 发布与验收要求

1. 下一官方版本必须包含 REQ-008 修复；不得以本地打包文件替换官方安装包冒充整改完成。
2. 对下一官方发布 exe 做真实 MCP `initialize` 复核：
   - 不得出现「勿用本服务」「本服务截不到网页」或等效的错误禁用指引；
   - 必须明确包含 `browser_snapshot` / `browser_get_rect` 的网页感知、定位路由；
   - stdio 与 daemon 接入形态返回同一说明。
3. 用全新 MCP 客户端会话做浏览器冷启动验收：要求 Agent 读取网页内容时，应主动选择 `browser_snapshot`，不得因服务器说明放弃或改找不存在的外部浏览器工具。
4. 实包复核通过后，本单方可关闭；当前已安装的 v0.4.4 仍保持本单所记旧行为。
