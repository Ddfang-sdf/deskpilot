# ISS-0033：【修改引入】超时链一致性

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0033 |
| 标题 | 客户端 90s 超时 < 新预算 95s(整 TTL 审批以连接失败回报,临期批准在客户端报失败后仍执行);L1 可升级路径仍 15s 预算(attach/终端绑定入白审批 90s 必超);预算测试 4 替身打集成标签 |
| 严重级 | **高**(A2/A3 使 ISS-0024 修复不闭环,「报错但动作可能已执行」以客户端侧形态复现) |
| 状态 | **实现完成,全量 515 过 9 跳过,待实盘验收** |
| 提出 | 2026-09-04(code-review 15 条之超时域,【修改引入】自 ISS-0024) |

## 1. 认账

ISS-0024 只改了 daemon 内预算决议,**没有把全链超时点枚举一遍**——客户端侧
`remote_call` 的 90s 常量、静态 L1 的升级路径都被留在时间链之外。根因=交叉面
枚举缺失(§2.1),不是技术难度。

## 2. 整改项

| # | 修复 | 约束 |
|---|------|------|
| A2 | 新增纯函数 `client_timeout(policy) = approval_ttl + 15`;stdio 调用点用它传 `remote_call(timeout=...)`;`remote_call` 删掉硬编码 90 默认(缺参即调用点 bug,显式必传) | 禁止再出现独立于策略的魔法超时 |
| A3 | `resolve_budget`:L1 与 L2 同档 approval_ttl+5(attach/request_remove/scroll 等 L1 写类同样可升级);L0 不变 | 覆盖"一切可升级路径"而非逐工具特判 |
| C2 | TestBudgetIntegration → **TestBudgetAssembly**:去 integration 标记(降入默认套件,装配全替身本就无桌面副作用),docstring 列明真实部件(HttpDaemon/Enforcement/Binding/Approval 链)与替身清单(SlowApproveChannel/FakeExecutor/FakeProbe/FakeClock)及断层面(HTTP 响应体) | 标签按三层定义判定,不含糊 |
