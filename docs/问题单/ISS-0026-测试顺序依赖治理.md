# ISS-0026：测试顺序依赖治理——用例必须独立自洽

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0026 |
| 标题 | `test_image_reference_kept_on_window` 单跑必挂、全量靠前序残留通过——测试间相互依赖;引入随机序防护机制 |
| 严重级 | **中**（测试可信度:假绿掩盖真回归;开源贡献者单跑遇假失败) |
| 状态 | **建单,待评审** |
| 提出 | 2026-09-04(sdfang 指出"测试之间相互依赖也不对";09-02 即发现该例未根治) |

## 1. 问题现状

单跑 `tests/test_whitelist_iss12.py::TestEnrollDialog::
test_image_reference_kept_on_window` 必挂:`Too early to create image:
no default root window`(实证 09-02,三连挂);全量顺序跑通过——它借用
了前序测试残留的 tk 默认根窗口。**假绿依赖执行顺序**,违反用例独立原则。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **测试未自建环境** | 用真实 tk.PhotoImage 却未建立独立根窗口,依赖 pytest 顺序执行时前序用例留下的 `_default_root` |
| R2 | **无顺序依赖检测机制** | 无随机序执行(如 pytest-randomly)暴露此类隐依赖,顺序绿长期掩盖 |

## 3. 整改方案

| 项 | 内容 |
|----|------|
| A | **测试自治**:该用例改注入替身 PhotoImage 类(记录实例),断言"窗口对象持有引用"(原设计意图)落在替身上——零真实 tk、零根窗口依赖,与 ISS-0025 零副作用原则一致 |
| B | **随机序防护**:引入 pytest-randomly,CI 全量随机序执行;本地默认保持顺序(体验),CI 负责抓顺序依赖。落地后若暴露其他隐依赖,一并修自治 |
| C | **规范入册**:SDD 测试设计硬规则补一条"用例间零依赖:任何用例单跑必须绿" |

### 约束

- 断言强度不减:替身 PhotoImage 计数等价于原"引用未丢"意图(原意图
  是防 GC 回收,替身验证"窗口持有该引用对象"成立);
- 随机序仅 CI,不改变开发者本地默认体验;
- 不借机改产品代码(本单纯测试卫生)。

## 4. 测试设计(五要素;本单自身用例)

| 用例 | 场景 | 前提 | 步骤 | 预期结果 | 断言代码 |
|------|------|------|------|----------|----------|
| TC-DEP-01 | 单跑独立绿 | 无(不依赖任何前序) | `pytest <该用例单条>` | 通过,零 RuntimeError | 退出码 0(系统外表面) |
| TC-DEP-02 | 替身语义等价 | 假 PhotoImage 记录实例 | 调 build_window(image_path=假图) | 窗口对象持有替身实例(引用未丢) | `isinstance(win._approval_photo, FakePhotoImage)`(直出) |
| TC-DEP-03 | 随机序全量绿(CI) | pytest-randomly 已装 | CI `pytest tests -q`(随机序) | 全绿(排除已知另案:基准/哈希) | CI 通过状态 |

装配守门:R1 替身注入不触真 tk;R2 单元层只替 tk.PhotoImage 构造缝;
R3 引用属性形态断言;R4 路径变迁=pyproject 增 pytest-randomly 依赖;
R5 终效应=单跑退出码 0(TC-DEP-01)。
