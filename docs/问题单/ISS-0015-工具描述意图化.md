# ISS-0015：工具描述意图化——24 个 MCP 工具描述为模板废话

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0015 |
| 标题 | 24 个 MCP 工具的 description 全是同一句模板（"DeskPilot 桌面操作工具 X(级别 Ly)"），模型拿到清单无法自助正确使用工具；实测 Agent 绕开工具链改写脚本 |
| 严重级 | **高**（MCP 的核心表面可用性缺陷：工具存在≈不存在；每个接入的模型都要靠猜） |
| 状态 | 已批准（2026-09-01 sdfang 批准并指示立即实现） |
| 提出 | 2026-09-01（sdfang 现场指正：Agent 找西柚窗口不用 find_window/attach，自己写 uiautomation 临时脚本——两问"是描述有问题还是没暴露能力"） |

## 1. 问题现状

1. **描述为模板废话**：`mcp_server.py:218-221` 工具清单描述由
   `f"DeskPilot 桌面操作工具 {name}（级别 {level}）"` 统一模板生成。
   24 个工具描述里没有：这工具干什么、何时该用、参数语义、返回结构、
   与上下游工具怎么串联。
2. **实证（用户现场目击两连）**：Agent 需要"在桌面找到某应用窗口"时，
   不选现成的 `find_window`（L0）/`attach` 链路，改写临时 Python
   （uiautomation/mss）脚本完成同一任务——能力存在，但描述没有让模型
   知道"该用它、怎么用"。
3. **组合链不可知**：桌面操作的天然链路（find_window → attach →
   get_ui_tree → click_element / key）在描述层完全不可见，模型只能逐个
   工具名猜语义。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **描述从代码视角生成** | 按"名字+级别"拼串，而非按"使用者视角"写（意图/时机/契约）；模板化生成等于没写 |
| R2 | **描述无一致性校验** | 描述与实现脱钩无人审——测试只校验工具数量与参数模式，不校验"描述是否表达了实现" |
| R3 | **缺组合引导** | 核心操作链（找窗→绑定→读树→操作）没有在任何描述中出现；模型无从得知工具间的调用顺序约定 |
| R4 | **缺领域边界声明（多 MCP 共存路由失败）** | 源码取证：agent-browser 描述清晰聚焦浏览器（mcp.rs:"Capture a screenshot…"/"Click an element…"），deskpilot 描述失语且从不声明"Windows 桌面/应用窗口，非浏览器页面"——同名动词（screenshot/click）竞争时模型必然选描述清晰但领域错误的一方（2026-09-01 连续多次误调 agent-browser 实证） |

## 3. 整改方案

### 3.1 总体

**描述是 MCP 的第一界面**：为 24 个工具逐个写意图化描述，与参数模式
同处维护、受测试约束——让任何模型拿到清单就会用。

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | **意图化描述四要素**（每工具）：① 用途一句话（动词开头，说人话）；② 何时用（典型触发场景）；③ 关键参数与返回结构（指名字段）；④ 组合链（与上下游工具的调用关系，如"先用 find_window 定位，再 attach 绑定"）。**外加第零要素：领域限定词**——每条描述以"Windows 桌面/应用窗口（非浏览器）"定界，多 MCP 共存时给模型路由依据（R4）。 |
| B | **描述注册为TOOL_SCHEMAS 一等字段**：每工具在 `TOOL_SCHEMAS` 增 `description` 节，与参数模式同处维护（不再由模板拼接；list_tools 直接取用）——描述与实现同一文件、同一评审面。 |
| C | **描述质量测试**：每个工具描述 含用途动词、含组合引导关键词、**含领域限定词**、非模板串（`"桌面操作工具" not in description`）、长度 ≤200 字；注册表与 TOOL_LEVELS 键集一致。 |
| D | **核心链路文档化**：README 工具清单段按链分组（感知/绑定/操作/管理），与描述呼应。 |

### 3.3 约束

- 只改描述与文档，不动任何工具行为与参数。
- 描述以中文为主、术语与 README 一致；≤200 字/条。
- inputSchema 不变（客户端兼容）。

## 4. 测试方案

### 4.1 单元（先行）

| 用例 | 断言 |
|------|------|
| 注册完整性 | 每个 TOOL_LEVELS 键在 TOOL_SCHEMAS 均有非空 description（直出） |
| 非模板化 | 所有描述不含 "桌面操作工具" 模板串（直出） |
| 含组合引导 | find_window/attach/get_ui_tree/click_element 描述均含组合链关键词（如 "attach"/"绑定"）（直出） |
| 长度约束 | 每条 ≤200 字（直出） |

### 4.2 集成验收

- 全量 pytest 绿
- list_tools 实读：返回的每个工具 description 与注册表一致、inputSchema 不变
- Agent 黑盒抽检：给模型工具清单+任务"找到记事本窗口并读取其界面元素"，模型应自行选择 find_window→attach→get_ui_tree 链（观察项，非硬断言）
