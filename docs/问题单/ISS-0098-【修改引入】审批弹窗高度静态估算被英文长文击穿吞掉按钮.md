## 0. 认账(修改引入)

REQ-007 界面国际化(18f0d07/49d6238)把弹窗文案迁到 i18n.yml,英文文本
长度约为中文 1.5~2 倍;迁移时只实测验收了**常规审批窗**(L3 按键,描述一
行),**漏了入白审批窗**(描述为长段落)的英文实测——「有 UI 改动必看效
果」在入白面破防。静态高度估算是既有代码,但击穿是本次修改引入的可见缺
陷,按修改引入认账。

## 1. 实证(双截图直读)

- 我的实拍(assets 抓取,480×374 窗):标题+大头照+6 行英文描述后,
  `Auto-deny in …` 仅剩半行,Deny/Session/Permanent 三按钮**整体消失**;
- sdfang 截图(Snipaste_2026-09-20_19-26-03.png):同一窗,同一裁切位,
  按钮区空白。

## 2. 根因(机制层)

`deskpilot/approval_dialog.py:84` 在**布局发生之前**定死窗高:

```python
hint_h = 0 if enroll else 18
height = _HEIGHT + hint_h + (img_h + 8 if photo_im is not None else 0)   # 216+0+158=374
...
win.geometry(f"{_WIDTH}x{height}+{x}+{y_start}")                          # line 100,内容还没建
```

正文 Label(headline/detail)按 wraplength=416 动态折行,英文入白描述
实测折 6 行(中文约 3 行),正文比估算高 ~60px。pack 几何管理器按序分配
空间,先装的吃满后,**晚装的控件(倒计时 line 140、按钮行 line 160)拿
不到空间被裁出可视区**。窗高自始至终没有按真实排版重测——这就是「吞按
钮」的机理,任何超长文案(任意语言)都会触发,英文只是第一块敲门砖。

## 3. 整改(技术细节,自主推进授权下采纳最优解)

**先排版后量尺**:内容全部 pack 完 → `update_idletasks()` →
`winfo_reqheight()` 取真实需求高 → 以实测高重算 toast_placement 落位并重
设 geometry,再做滑入。此时窗在屏底缘外侧(y_start=rb),重设不可见。
`_HEIGHT` 降为下限地板(防空描述塌缩),不再承担估算职责。

- 单改动点=build_window 收口处;滑入/倒计时/三态逻辑不动;
- 上限护栏:实测高 > work_area 可用高时按可用高截断(fail-closed,
  不顶出屏外);
- 常规审批窗(非 enroll)同一代码路径,一并受益;冻结卡/白名单窗为固定
  短文案+固定窗,交叉面复核见 §5。
