| 问题单号 | ISS-0095 |
| 标题 | 白名单管理窗在异机(0.4.1 冻结形态)打开超过 1 分钟,本机秒开;打开链上无任何计时日志,无法定位慢在哪段——先补观测面,再按证据定整改 |

## 1. 打开链逐段拆解(代码实证,冻结形态 v0.4.1)

| 段 | 做什么 | 出处 | 开销画像 |
|----|--------|------|---------|
| ① 拉起 | 托盘 on_manage → `subprocess.Popen([deskpilot.exe, --whitelist-manager, base_url])`——**新起一个 onefile 进程**:111MB 自解压到 %TEMP%\_MEIxxx + 杀软实时扫描解压物 | main.py:210-226 | **每次开窗都付全价**;慢盘/杀软机可达数十秒(冻结形态独有,源码形态无) |
| ② 单例 | `focus_existing_or_exit("DeskPilot 白名单管理")` 找已有窗 | whitelist_window.py:792 | 毫秒级 |
| ③ 拉数据 | GET /whitelist(本机 HTTP,5s 超时) | whitelist_window.py:746-765 | 取决于 daemon 侧(见④) |
| ④ daemon 侧 | 对静态+会话白名单**每个进程**跑 `app_display_name`+`app_description`(注册表/版本信息/MUI/AppX 清单/开始菜单 .lnk/Get-StartApps powershell 子进程) | httpd.py:255-268 | daemon 启动时 `warm_caches(parallel=True)` 已暖(main.py:484-486);**暖失败/被打断/缓存冷则每进程秒级、串行累加** |

**嫌疑排序(机制层,待异机取证坐实)**:A=①onefile 自解压+杀软扫描(冻结形态每开必付);B=④暖缓存失效后冷解析串行累加;C=④中 powershell 子进程被企业策略/性能拖至超时;D=⑤可忽略。

## 2. 现有日志缺口(如实清点)

| 面 | 现状 |
|----|------|
| daemon stderr | 只有启动行,无开窗计时 |
| audit JSONL | 无「管理窗打开」事件、无 /whitelist 耗时、无分段计时 |
| 管理窗子进程 | **零日志**(stderr 随 Popen 丢弃) |

**结论:目前没有任何日志能监控这个过程——慢在哪一段纯属不可观测。**

## 6. 诊断结论(2026-09-22 诊断回填;代码测绘 v0.4.2 源码,链路同 v0.4.1)

### 6.1 打开链全链测绘(file:line 级)

| 段 | 做什么 | 出处 | 耗时画像 |
|----|--------|------|---------|
| ① 拉起 | 托盘 on_manage → `_open_manager_for` → `Popen([sys.executable, "--whitelist-manager", base_url])`(env 剥 `_MEIPASS2`);冻结形态=**新 onefile 进程对(引导父+应用子)**:106MB(111,057,367 字节,实测)自解压到 `%TEMP%\_MEIxxx` + 杀软对 exe 本体与解压物(rapidocr ONNX 模型、uiautomation DLL、UPX 压缩段——`deskpilot.spec` `upx=True`)实时扫描 | main.py:211-227;deskpilot.spec | **每次开窗付全价;Python 启动前发生,进程内不可观测**;慢盘/企业杀软机可达数十秒~分钟级(冻结形态独有) |
| ② 分发 | `run_deskpilot.py:21-24` → import `deskpilot.whitelist_window`——**仅拖 tkinter/i18n/monitors,不进 main.py 重依赖**(pyautogui/uiautomation/mcp 均不进口) | run_deskpilot.py:21-24 | 亚秒级 |
| ③ 单例 | `focus_existing_or_exit` = `FindWindowW` 标题匹配,已存在则聚焦退出 | whitelist_window.py:160-168,786-787 | 毫秒级 |
| ④ 拉数据 | GET /whitelist,urllib `timeout=5`;**超时/失败→静默回退空表,窗口照开** | whitelist_window.py:729-737,740-759 | **对「弹出耗时」贡献被封顶在 ~5s**;超过则症状变为「秒开但空窗」,与「>1 分钟才弹出」非同症 |
| ⑤ daemon 装配 | /whitelist 端点逐条目 `app_display_name`+`app_description` | httpd.py:255-268 | 暖态毫秒级(本机实测 0.082s);冷路径见 6.2-B |
| ⑥ 建窗 | `tk.Tk()`+withdraw→fetch→`build_window`→mainloop | whitelist_window.py:781-813 | 毫秒级 |
| i18n | 目录加载 = `_MEIPASS/deskpilot/i18n.yml` 一次性 yaml 解析 | i18n.py:35-53 | 毫秒级 |

⑤的缓存面细分(appnames.py 实证):`warm_caches`(main.py:461-462 → appnames.py:288-304)daemon 启动时并行暖四源(`_package_index`/`_startapps_map`/`_start_menu_map`/`_uninstall_map`);**未暖/零缓存面**:
- `_running_procs`(appnames.py:109-136):首调才建,EnumProcesses+逐进程 OpenProcess/QueryFullProcessImageNameW,进程级一次性;
- `_file_string` 版本信息(appnames.py:563-600):**零缓存**——每次 /whitelist 请求、每条目最多 3 次 `GetFileVersionInfoW`(display 的 FileDescription + desc 的 FileDescription/CompanyName);白名单 exe 路径落在断连网络盘/可移动介质时单次可阻塞数十秒(但受④ 5s 封顶,只表现为空窗);
- `_resolve_ms_resource` SHLoadIndirectString(appnames.py:542-558):描述路径零缓存;
- `_start_menu_map`(appnames.py:163-188):`rglob("*.lnk")` 在漫游配置 APPDATA 下走网络盘 + COM `WScript.Shell`;
- `_startapps_map`(appnames.py:357-384):`powershell Get-StartApps` 子进程,**已自带 3s 超时封顶**。

### 6.2 分钟级耗时候选排序(带证据与验证法)

| 排序 | 候选 | 证据 | 异机验证法 |
|------|------|------|-----------|
| **A1** | ①onefile 自解压 + 杀软逐文件扫描解压物(每开必付) | 本机实测总 3.3s 中 /whitelist 仅 0.082s、Tk 毫秒 → ~3.2s 全是①+解释器引导;异机(机械盘/企业杀软/UPX 启发式深度扫描)放大至 30~90s 可达分钟级。**唯一能达到分钟级的段** | O5 分段差值实测(见 6.3);异机连续开两次对比首开(区分 IO 主导 vs 杀软主导:杀软每次全扫,IO 二开暖) |
| **A2** | 杀软对 106MB 未签名 exe 本体的进程创建时扫描 | exe 未签名每次发布新构建=低声誉二进制(与 ISS-0094 §4.4 B-2 同族);UPX 段加重启发式 | 异机 Defender/杀软 Operational 日志;临时加排除目录对比实验 |
| B | ⑤daemon 冷解析串行累加(网络盘 exe GetFileVersionInfoW 阻塞等) | 代码证据如上;**被④ 5s 超时封顶,症状是空窗非慢窗**——与报障症状不符,降级次要 | O3 埋点数据回拍 |
| C | ⑤中 powershell 子进程被企业策略拖慢 | appnames.py:366-370 已 3s 超时封顶 | 同上 |
| D | ⑥Tk 首初始化/③FindWindowW/i18n | 毫秒级,本机实测含在总耗时内不可分辨 | 排除 |

**结论:「>1 分钟才弹出」≈ A1+A2(onefile 形态固有开销 × 异机盘速/杀软放大);④⑤段的慢只可能导致「空窗」,不可能导致「慢窗」。**

### 6.3 观测面补齐细化(在 §3 O1~O4 上落埋点名/位置/落点)

| # | 埋点名 | 位置 | 输出 | 要点 |
|---|--------|------|------|------|
| O1 | 「管理窗拉起」(base_url) | main.py `_open_manager_for` Popen 前 | daemon audit JSONL | daemon 侧时钟=拉起时刻 |
| O2 | 「管理窗分段计时」boot_ms(进程入口→单例检查完)/tk_init_ms/fetch_ms(+entries_n+fallback 标志)/build_ms/total_ms | whitelist_window.main() 内 `time.monotonic` 分段(781-813 各行) | **子进程 stderr→受管目录滚动日志文件**(Popen 处加重定向;写失败静默跳过,fail-closed 不阻断开窗) | 与 O1 同机时钟对齐即得全链分段;**不需新增 HTTP 端点** |
| O3 | 「白名单数据装配」(dur_ms, n, slow=[proc@ms…]) | httpd.py:255-268 分支计时;逐条目超 200ms 留进程名 | daemon audit JSONL | 坐实/排除 B 段 |

### 6.4 本机实测(2026-09-22,dist v0.4.2 冻结形态,daemon pid 25024 在线)

- 方法:杀净既有管理窗进程(仅余 daemon 父子对),`DESKPILOT_LOCALE=en dist/deskpilot.exe --whitelist-manager http://127.0.0.1:9420`,100ms 轮询进程 `MainWindowTitle` 至「DeskPilot Whitelist Manager」出现。
- 结果:**首开 3.36s、二开 3.23s**(含 onefile 解压+引导);GET /whitelist 暖态 **0.082s**。
- 判读:本机 ~3.3s ≈ 纯①段;与「本机秒开」诉述一致。**本机无法复现分钟级**——异机差异假设:机械盘/低速 SSD、企业杀软对 `_MEI` 解压物逐文件扫描、UPX 启发式仿真、106MB 未签名 exe 每次创建全量扫描、漫游配置文件;与 ISS-0094 §4.4 B-2(未签名新构建被杀软重点对待)同族。
