# ISS-0010：截图与临时文件统一管理 + 时空双阈值清理

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0010 |
| 标题 | 截图无限累积且保存路径散落：须统一受管目录 + 时间阈值与空间阈值联动的清理机制（最旧先清、在场文件免疫） |
| 严重级 | 高（磁盘无界占用 + 用户感知到不该感知的垃圾文件） |
| 状态 | **已关闭**（2026-08-29 验收通过：257 用例全绿） |
| 提出 | 2026-08-29（实盘使用反馈） |

## 1. 问题现状

1. **无限累积**：审计截图（每次写操作 before/after 两张、SoM 标注图、审批实拍、
   感知截图）只增不删，磁盘占用无上限（与 ISS-0008-C4 同根，本单给出完整治理设计）。
2. **路径散落、用户看到垃圾**：当前有四类互不知情的写入点，且**两个坑直接落在用户视野里**：

| 写入点 | 位置 | 实证 | 问题 |
|--------|------|------|------|
| 审计截图 | `<audit_dir>/shots/YYYYMMDD/*.png` | `policy.yml:84` 的 `audit_dir: ./audit` 是**相对路径**，随各进程 cwd 解析 | daemon 从 dist 起 → `dist\audit\`；客户端从仓库根起 → `deskpilot\audit\`——**同机多套审计目录并存**（本机实测两套都在） |
| MCP 客户端图片落盘 | `<仓库根>/mcp_shot_<ts>.png` | `scripts/mcp_call.py:150` 写 REPO_ROOT | **垃圾文件直接落在用户的工作目录里**（开发/联调时满屏 mcp_shot） |
| 审批通道临时文件 | `<exe 上级目录或 cwd>/deskpilot-approval-*.{desc,result}` | `approval_ui.py:33-46` result_root 随形态漂移 | 又一处用户视野内的散落物 |
| 冻结状态/请求/锁文件 | `<audit_dir>/estop-*` | freeze_notify | 同上随 cwd 漂移 |

3. **没有"当前使用"概念**：任何未来清理机制若一刀切按时间删除，可能误删
   刚生成、正被引用（审批弹窗待展示、MCP 响应未回传、回放未读取）的截图。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **路径解析锚点缺失** | audit_dir 相对路径无统一锚定规则，各进程按各自 cwd 解析，天然多套并存；approval/客户端落盘各自为政，没有"唯一受管目录"概念。 |
| R2 | **生命周期管理缺失** | 截图只有生产者没有清理者；无时间阈值（留存多久）、无空间阈值（最多占多少）。 |
| R3 | **无"在场保护"语义** | 文件与被引用状态之间没有关联（弹窗展示中/响应回传中/回放窗口期），清理策略若不知"当下"，就会误伤在用文件。 |

## 3. 整改方案

### 3.1 总体

**一个受管目录 + 一个清理者 + 两类阈值 + 一条在场保护线。** 所有写入点统一锚定到
同一受管目录；清理者按"超龄即清、超量按龄清"运行，近窗口期文件绝对免疫。

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | **受管目录统一锚定**：`audit_dir` 相对路径改为相对**策略锚点**解析——冻结形态锚定 exe 所在目录、源码形态锚定 policy.yml 所在目录；解析结果在服务启动时打印审计事件。存量散目录（dist\audit、仓库 audit）启动时惰性并入受管目录（移动而非复制，失败仅告警）。 |
| B | **写入点全部归队**：审计截图保持 `<audit_dir>/shots/YYYYMMDD/`；mcp_call 图片落盘改 `<audit_dir>/shots/client/`；审批临时文件改 `<audit_dir>/approval/`；冻结状态文件已在 audit_dir 不动。所有路径经同一个 `AuditPaths` 纯函数产出（单点生成，消除散落）。 |
| C | **清理者（Janitor）**：daemon 启动时跑一遍 + 之后按 `cleanup_interval_seconds`（默认 3600）定时跑；纯函数核心 `plan_deletions(files, now, max_age_s, max_bytes, grace_s) -> list[Path]`：① mtime 早于 `now - max_age_s` 必删；② 再按 mtime 从最旧到最新累计体积，超过 `max_bytes` 的部分按龄删除；③ **mtime 晚于 `now - grace_s`（默认 600s）的文件永远保留**（在场保护，覆盖弹窗展示/响应回传/即时回放窗口）。 |
| D | **策略项**（policy.yml `audit` 节，均有默认，缺失即默认）：`shots_max_age_days: 14`、`shots_max_bytes: 2147483648`(2GB)、`cleanup_grace_seconds: 600`、`cleanup_interval_seconds: 3600`。策略加载即锁定（INV-9 不变）。 |
| E | **观测**：每次清理写一条审计事件（删除 N 个文件、释放 M 字节、当前占用）；清理异常不影响服务（告警后继续）。 |

### 3.3 约束

- 清理只动 `shots/`（含 client 子目录）与超龄 approval 临时文件；**审计 JSONL 日志不在本单清理范围**（合规留存语义不同，如需另议）。
- 在场保护线为硬约束：grace_s 内文件即使超量也不删。
- 锚定迁移对存量目录失败不阻断启动（fail-open 于迁移、fail-closed 于配置）。

## 4. 测试方案

### 4.1 单元（先行）

| 用例 | 断言 |
|------|------|
| 锚定解析 | 冻结形态相对 audit_dir → exe 目录；源码形态 → policy.yml 目录；绝对路径原样通过 |
| 超龄必删 | 构造 mtime 为 15 天前的文件 → 在删除集；13 天前的不在 |
| 超量按龄删 | 总 3GB/上限 2GB → 删除集按 mtime 从最旧起恰好删到 ≤2GB |
| 在场保护 | mtime 为 5 分钟前的文件即使超龄（构造）且超量也绝不出现在删除集 |
| 归队路径 | AuditPaths 产出的截图/客户端/审批三类路径均位于受管目录下且彼此隔离 |
| 清理观测 | 执行后审计事件含删除数与释放字节数（持久化 JSONL 直读） |
| 迁移 | 存量散目录文件被移入受管目录；目标已存在时不覆盖（保留新者） |

### 4.2 集成验收

- 全量 pytest 绿（现有 222 + 新增）
- 实盘：连续产生截图 → 受管目录外（仓库根/dist 根）零新增垃圾文件
- 实盘：调小阈值触发一次定时清理 → 仅超龄/超量文件消失，最近 10 分钟内截图全部在场；服务与弹窗链路无影响

## 6. 接口定义（SDD 公开入口；测试只允许调用以下入口）

### janitor（新增模块 `deskpilot/janitor.py`）

| 入口 | 签名 | 语义 |
|------|------|------|
| `plan_deletions` | `(files: list[tuple[Path, float, int]], now: float, max_age_s: float, max_bytes: int, grace_s: float) -> list[Path]` | 入参为 (路径, mtime, 字节) 三元组：① mtime < now-max_age_s 必删；② 再按 mtime 从旧到新累计体积，超 max_bytes 部分按龄删；③ **mtime ≥ now-grace_s 的文件永不出现在删除集**（在场保护） |
| `run_janitor` | `(audit_dir: str, now: float, max_age_s: float, max_bytes: int, grace_s: float, audit_log=None) -> dict` | 执行一轮清理（shots/ 含 client 子目录 + approval/ 超龄临时文件），返回 {"deleted": N, "freed_bytes": M, "current_bytes": C}；audit_log 非空时写审计事件；单个文件删除失败不中断 |

### AuditPaths（新增模块 `deskpilot/audit_paths.py`）

| 入口 | 签名 | 语义 |
|------|------|------|
| `resolve_audit_dir` | `(configured: str, policy_path: str \| None = None) -> Path` | 相对路径锚定：冻结形态锚 `Path(sys.executable).parent`；源码形态锚 `Path(policy_path).parent`（无 policy_path 回退 cwd）；绝对路径原样 |
| `AuditPaths` | `AuditPaths(audit_dir: str)`，属性：`shots` / `client_shots` / `approval` | 三类受管子目录路径（均为 Path，惰性 mkdir） |

### policy（策略项，§3.2-D）

| 入口 | 签名 | 语义 |
|------|------|------|
| `Policy.shots_max_age_days` | `float`，默认 14.0 | 截图留存天数 |
| `Policy.shots_max_bytes` | `int`，默认 2147483648 | 截图空间上限（字节） |
| `Policy.cleanup_grace_seconds` | `float`，默认 600.0 | 在场保护窗（秒） |
| `Policy.cleanup_interval_seconds` | `float`，默认 3600.0 | Janitor 定时周期（秒），0=禁用定时（仅启动时跑） |

### TkApprovalChannel / mcp_call（写入归队）

| 入口 | 签名 | 语义 |
|------|------|------|
| `TkApprovalChannel.__init__`（行为变更） | 追加 `audit_paths: AuditPaths \| None = None` | 提供时临时文件落 `audit_paths.approval`；缺省保持 result_root 原行为（兼容） |
| `scripts/mcp_call.py` 图片落盘（行为变更） | — | `mcp_shot_*.png` 改存 `<audit_dir>/shots/client/`（经 AuditPaths 锚定） |
