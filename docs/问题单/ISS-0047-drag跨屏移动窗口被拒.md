# ISS-0047：drag 终点校验窗口矩形——跨屏/越窗移动窗口被拒

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0047 |
| 标题 | drag 的 end 点经 _check_point 校验绑定窗口矩形(core.py:631-633),移动窗口类拖拽的终点合法地在窗外(跨屏移动必越窗)→ OUT_OF_BOUNDS 被拒;双屏下窗口拖拽不可用 |
| 严重级 | **中**(双屏/窗口移动场景阻断;sdfang 双屏实测发现) |
| 状态 | **已修复(方案A:TC-47-01~06 绿;R7 绿态失效原因核对过——拒绝信息点名显示器矩形)** |
| 提出 | 2026-09-09(双屏实测:最大化记事本拖向副屏被拒) |

## 1. 背景(实证)

2026-09-09 双屏测试:绑定主屏记事本(rect [0,48,1920,1080]),drag 终点
(2880,300) 在副屏 → `OUT_OF_BOUNDS: 落点在绑定窗口矩形外`。
机制:`_drag` 对 start/end 双点均调 `_check_point(hwnd, ...)`——该校验的
语义是"防误射(不写出绑定窗口)",但**移动窗口**的拖拽终点合法地位于
窗口当前矩形之外(窗口正被移走)。两类拖拽语义被混为一谈:
内容拖拽(文本/图标,内容不出窗)与窗口拖拽(标题栏拖动,终点可在
虚拟桌面任意处)。

## 2. 整改方案

| 项 | 内容 |
|----|------|
| A | drag 终点校验改为**虚拟桌面全域**(monitors 并集):start 仍在绑定窗内(起点防误射不变),end 允许虚拟桌面任意点,end 越出虚拟桌面 → OUT_OF_BOUNDS(fail-closed 保留) |
| B | 文档明示两类拖拽语义(内容拖拽/窗口拖拽)与各自的边界语义 |

### 约束

- start 点校验不变(窗口内起点仍是防误射本职);
- fail-closed 不削弱:终点越出虚拟桌面全域仍拒绝;
- 测试设计(五要素)于评审通过后产出:核心用例——绑定主屏窗,drag 终点
  副屏坐标 → 放行(替身直出);终点越出虚拟桌面 → 拒绝(直出)。
