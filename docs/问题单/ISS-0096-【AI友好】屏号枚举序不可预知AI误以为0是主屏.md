# ISS-0096:【AI友好】屏号枚举序不可预知——AI 误以为 0=主屏,猜两次才截对

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0096 |
| 标题 | `screenshot(scope=screen, screen=N)` 的屏号是 OS 驱动枚举序——本机实测 `[0]=右屏(非主屏)`、`[1]=左屏(主屏)`,与「0=主屏」的心智模型相反;AI 看左主屏连截两次右屏才猜对,白烧往返 |
| 严重级 | **中**(AI 友好/可用性:感知入口的语义不可预知;非安全缺陷) |
| 状态 | **P3 完成待验收**(2026-09-18;sc01~sc04 绿;全量回归 852 绿) |
| 提出 | 2026-09-18 sdfang 报障:「AI 想要看左侧主屏,结果输入 0 截了两次图,发现截到的是右侧屏,然后才尝试 1,才截到左侧屏」「易用性不好,AI 误以为 0 就是主屏」 |

## 1. 实证(本机直读)

```
enum_monitors() 当前返回:
  0: rect=(1920,-1,3840,1079)  is_primary=False   ← 右屏
  1: rect=(0,0,1920,1080)      is_primary=True    ← 左屏=主屏
```

屏号语义现状(ISS-0083):屏号 = enum_monitors 清单下标;清单序 = mss/Win32
枚举序(驱动顺序,无主屏优先约定)。`is_primary` 标记今起为 Win32 真查
(ISS-0057)。

## 2. 根因(机制层)

枚举序没有面向调用方的语义保证——AI 拿到的是驱动注册顺序这一实现细节,
而不是「哪个屏是哪个」的认知模型。感知面语义不可预知 = AI 只能猜。

## 3. 整改方向(自主推进授权下采纳最优解)

**枚举序确定性重排**:`enum_monitors()` 返回前排序——**主屏第一,其余按
rect 左缘从左到右**(横坐标相同按上缘)。契约升级为:「屏号 0=主屏,
1..N-1 从左到右」;fullscreen 的 monitors 字段同序(同一清单)。

- 单一改动点=enum_monitors 收口处(消费方 screen_of_point/rect、
  toast_placement、screenshot 全不受影响或受益);
- 描述随代码:screenshot 描述补屏号语义(受 ISS-0015 ≤200 闸门约束);
- ISS-0083 文档翻页(屏号语义保证入档)。

## 4. 测试设计(五要素)

| # | 场景 | 前提 | 步骤 | 预期 | 断言 |

## 5. 约束

- 既有行为面(screen_of_point/rect 按内容归属、toast_placement 按屏 dict)
  与序无关,不得回退;
- fullscreen 的 monitors 字段与新序一致(同一清单);
- 越界屏号 fail-closed 语义不变(ISS-0083);
- 实现走 SDD P1→P2→P3。
