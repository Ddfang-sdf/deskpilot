# ISS-0083:【AI友好】screenshot 把取图范围交给 AI 自裁——缺按屏入口,region 成默认路径致系统性截小

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0083 |
| 标题 | `screenshot` 的 `scope` 三值中,`fullscreen`/`window` 由工具查矩形、AI **只报目标**;`region` 则由 AI **直接供 `[l,t,r,b]` 绝对坐标**。二者语义不同却平级并列、无引导,于是"AI 自行划边界"成了最容易被选的一档,表现为**每次都截一小块还要据此下结论**。另有双屏场景缺按屏入口:`fullscreen` 取 `monitors[0]` 外接矩形,错位排列的双屏会拍进**不存在的黑色区域** |
| 严重级 | **中**(AI 感知面:直接决定 AI 拿到多少世界;且"图小→据小图判断"是**静默错误判断**而非报错,AI 自己无法察觉) |
| 状态 | **已整改**(2026-09-15 SDD 全绿;评审通过 ①+②:sdfang 2026-09-14) |
| 提出 | 2026-09-13 sdfang 口述:"每次AI截图,总是喜欢截一小部分,然后他又很蠢,觉得就只有这么点内容" |

## 1. 现象与证据

### 1.1 sdfang 的观察

> "每次AI截图,总是喜欢截一小部分,然后他有很蠢,觉得之后这么点内容。我在想,我们要不直接控制截图固定尺寸,每次都截图全屏,对于双屏,ai只需要关心对哪个屏幕进行截图"

### 1.2 机制层:三档 `scope` 的**性质不同**,却无区分

`deskpilot/executor/core.py:163` `screenshot(scope, rect, window, ocr)` → `_resolve_region`(core.py:1040):

| `scope` | 矩形从哪来 | AI 供什么 | 有无"裁得太小"的可能 |
|---------|-----------|----------|-------------------|
| `fullscreen` | `sct.monitors[0]`(虚拟桌面外接矩形) | 无 | **无** |
| `window` | `probe.rect_of(hwnd)` | 窗口标识 | **无** |
| `region` | **照抄 AI 传的 `rect`** | **绝对坐标 `[l,t,r,b]`** | **有,且是唯一致病源** |

**关键结论**:病根不是"允许局部截图",而是**"允许 AI 自己划边界"**。AI 能说出"目标"的地方就不该让它供绝对坐标。这条规则同时解释了为什么 `window` 档从未出问题。

### 1.3 双屏:`fullscreen` 的外接矩形含虚空

`_resolve_region("fullscreen")` 取 `sct.monitors[0]`,即**所有屏幕的外接矩形**。双屏错位时(如 1920×1080 主屏 + 1920×1080 副屏但副屏整体下移 200px),外接矩形为 1920×1280,其中 **1920×200 是任何显示器都不存在的空白**:

- 该区域**永远点不到任何东西**;
- 却照拍进图像块、照耗视觉 token;
- AI 还可能把它当成"一片空白的界面区域"来解读。

而 `monitors.py` 早就备好了逐屏几何:`enum_monitors()`(monitors.py:10,**mss 优先跳过 `[0]` 聚合项、Win32 兜底、含负坐标**)、`screen_of_point`(monitors.py:76)、`screen_of_rect`(monitors.py:90)。`fullscreen` 返回时也已附 `coord_space="virtual_desktop"` 与每屏 `rect`(core.py:176-180)。

**即:按屏取图所需的全部原料都在,只缺一个入口。**

### 1.4 现状盘点(实测)

- **已有且可用**:`fullscreen` 档(坐标空间已声明)、`monitors` 逐屏矩形、`screen_of_point`/`screen_of_rect` 纯工具;
- **缺失**:①"按屏取图"的显式入口(AI 只能自己从每屏 `rect` 里减偏移再拼 `region`,**这一步正是它算错或偷懒的入口**);②`region` 档的**定位说明**(它现在于 schema 描述中是平级选项,读起来与 `fullscreen` 同权重)。

### 1.5 为什么"AI 该自己懂"这个思路不成立

按项目既有裁定 —— **工具=物理层,判断归 AI**(`mcp-tool-physical-layer-ruling`)—— 此处**不冲突**:屏幕归属不是判断,是**物理事实**;把事实的查询推给调用方,不叫"让 AI 判断",叫**工具没做完**。真正属于 AI 判断的是"我用这张图干什么"(布局理解/找控件/精读文字),这些仍归它。

## 2. 依赖核查(sdfang 追问"为什么必须保留区域截屏、哪些功能依赖它")

**结论:`screenshot` 的 `region` 档,系统内零依赖。**

- `screenshot` 的**唯一调用方**是 MCP 工具分发 `deskpilot/tools/__init__.py:73`;`deskpilot/` 内部**无任何调用**。
- 其余"按区域取图"的功能走的是**另一条内部路径**,与这个枚举值无关:

| 消费方 | 位置 | 区间从哪来 |
|--------|------|-----------|
| `ocr(source)` | core.py:266-268 | `source` 收**路径**、**区域 dict 直通**或 `(l,t,r,b)` |
| `template_match(scope)` | core.py:300 | 独立形参,`scope` 是 `("rect",)` 一个矩形 |
| `get_clickable_map` | core.py:354 | 由**绑定窗口矩形**产出 |
| `click_text` 实拍 | core.py:791 | `_resolve_region("window", None, hwnd)` |
| 审批实拍 | enforcement.py:349 | 内部自算 |

它们共用的是内部原语 `_capture(region_dict)`(core.py:559)——**区域取图在代码里是根基,不会消失**。消失的只是**对外暴露的那个枚举值**。

**但删掉它仍有代价(能力损失,非依赖断裂)**:

1. `ocr(source=<区域>)` 的对称入口消失 → 只能先存图再传路径,**每次多一次磁盘往返**;
2. `screenshot(region, ocr=True)` 的 tight crop 精读消失 → 小图送 OCR 的**精度与耗时均优于全屏**;
3. 无法不绑窗口地临时观察一个局部。

**裁定**(sdfang 2026-09-13):**保留 region**。按 fail-closed 原则,不应用"删能力"的方式解决"引导"问题——那会把 AI 的坏习惯变成系统的残废。

## 3. 根因(机制层)

**AI 的感知面存在一个「自由裁量档」,且它与「目标档」平级并列、无引导。**

三条 `scope` 里,`region` 让调用方直接提供绝对坐标——这是**把工具的判断责任推给了调用方**。而 schema 描述未标明任何一档的定位用途(`mcp_server.py:46-51` 只有 `"required": {"scope": ("enum", [...])}` 与 `conditional`,描述文字未区分三档性质),于是 AI 按"最省事/最贴近直觉"选 —— 选中的正是唯一有裁量空间的那档。

**与 ISS-0084(键盘分类器)同源**:两处都是**把工具该做的判断交给调用方**——键盘那边表现为"每个新键都要手工登进白名单",这边表现为"每次取图都要 AI 自己划边界"。同一根因,两处发作。

## 4. 整改方向

### 4.1 提案(倾向)

**保留 `region`,但把"默认"从 AI 身上拿走。** 两条:

| # | 动作 | 说明 |
|---|------|------|
| ① | **新增按屏取图档** | AI 只说"屏几",工具用 `monitors` 里的 `rect` 取该屏。双屏场景从"AI 自己算偏移"变为"报屏号" |
| ② | **`region` 从"平级选项"降为"显式意图"** | 描述里写明其用途是**精读/局部核对**,并让返回值**可见覆盖比**——`virtual_rect` 已有(core.py:171-173),补一个"本图占虚拟桌面比例"即可让 AI 自己看见"我这次只看到 8% 的屏幕" |

如此:**全屏/按屏是默认路径,`region` 是刻意行为**。保留能力、改变引导,不删东西。

### 4.2 备选(已否决)

| # | 方向 | 否决理由 |
|---|------|---------|
| ① | 文档里劝 AI 用全屏 | 无强制力,白名单式"选择自由"必然被误用,回到原状 |
| ② | 删掉 `region` 档 | 见 §2:三项能力一并消失。以删能力解决引导问题,方向错 |
| ③ | 硬钉固定尺寸,只留全屏 | 同②,且 `fullscreen` 在错位双屏下含虚空(§1.3),硬钉反而放大该缺陷 |

### 4.3 待钉的形态(实现细节,自决范围,此处仅登记以免漂移)

- 新档的 `scope` 取值名与"屏号如何表达"(建议 `screen` + `screen` 参数,取值 `0` 或 `1` 或 `primary`/`secondary` 形态待定);
- 按屏截图的 `virtual_rect` 即该屏 `rect`,`coord_space` 仍为 `virtual_desktop` —— **坐标空间不新增**,AI 送点击时无需换算法;
- 覆盖率展示字段的键名与口径(建议 `coverage` 或 `screen_fraction`,分母 = 虚拟桌面外接矩形面积)。

## 5. 验收口径与测试设计要点

1. **按屏取图**:给定多屏几何,`scope=screen` 取指定屏 → 断言返回的 `virtual_rect` **逐分量等于** `enum_monitors()` 中该屏的 `rect`(含负坐标屏的用例);
2. **越界屏号 fail-closed**:屏号超出 `enum_monitors()` 长度 → **显式报错**,禁止静默回退到全屏或主屏(静默降级);
3. **`fullscreen` 与按屏的差异可见**:错位双屏几何下,`fullscreen` 的 `virtual_rect` 面积 **>** 任一单屏面积 —— 证到"外接矩形含虚空"是**已存在的事实**而非本单新引入;
4. **`region` 能力不退化**(回归):`screenshot(region, ocr=True)` 与 `ocr(source=(l,t,r,b))` 逐条保持原行为;
5. **覆盖率字段**:`region` 档返回值携带覆盖率,其值 = `region` 面积 ÷ 虚拟桌面外接矩形面积(此处需**实数断言**,不得只断"键存在");
6. R6 双向映射:本单需求条目 ↔ 上述用例双向可查,无孤儿。

## 6. 约束

- **不删 `region`**、不改其语义、不改 `coord_space` 的既有取值;
- `ocr` / `template_match` / `get_clickable_map` / `click_text` **零改动**;
- 新增档的越界行为必须 fail-closed(§5.2),不得静默回退;
- 文档三同步:描述 / schema / 测试；
- 本单只到"建单+测试设计",实现走 SDD P1 红 → P2 核对 → P3 绿。
