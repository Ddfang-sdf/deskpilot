## 1. 根因(实证链)

### 1.1 文档裁决原文

`docs/需求/REQ-002-桌面图标感知/REQ-002-桌面图标感知-功能设计.md:138`

```
| FD-02 | 合并键为枚举索引而非 display | 同名图标(两个 WeLink 实证)以名合并必然错位;
索引是三路共同的物理序(A-2 校验兜底) |
```

同文档 `:130` 亦立口径:`序对齐校验 | 实现期三路 item0=回收站 口径断言`。

### 1.2 实装结论相反

`deskpilot/executor/desktop_icons.py` 的 `DesktopIconAssembler.assemble(region=None)`:

- 归并键 = `_norm_icon_name(display)` —— **以名归并**,与 FD-02 相反;
- 虚拟项特判 `_VIRTUAL_FIRST_NAMES = {"回收站", "recycle bin"}`,**名称驱动**(与"索引驱动"相反);
- FD-02 担心的"同名必然错位"在实装里**并未靠错位解决,而是靠拒绝**:重名触发 fail-closed 分支 `归并失败:图标重名歧义`;无匹配来源触发 `归并失败:图标 {display!r} 无匹配来源`。

即:**FD-02 的顾虑被承认(同名不可靠),但选了对策完全不同的路**——FD-02 选"绕开名字用索引",实装选"用名字但拒绝歧义"。

### 1.3 谁是对的

ISS-0054 的实证已裁定:**索引路线不成立**。FFA 序分叉证据——sdfang 清理/重排桌面后 23 图标,`首项虚拟一致性——uia='回收站' 而 shellview 有路径 '微信.lnk'`,F5 后仍败,`list_desktop_icons` 整体不可用。索引对齐的物理序前提(`A-2`)在自定义排列下不成立。

故 FD-02 的**理由已被推翻,而条文还在**。
