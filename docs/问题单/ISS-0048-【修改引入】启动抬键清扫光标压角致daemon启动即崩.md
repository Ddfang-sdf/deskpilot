# ISS-0048：【修改引入】启动抬键清扫光标压角致 daemon 启动即崩

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0048 |
| 标题 | REQ-001 启动抬键清扫未容错 pyautogui FAILSAFE——光标位于屏幕角落时,启动清扫的 mouseUp 触发 FailSafeException 穿透 Executor.__init__,daemon 启动即崩 |
| 严重级 | **高**(修改引入——最严重最低级;启动路径崩溃=服务不可用) |
| 状态 | **已修复(测试全绿+真机活实证)** |
| 提出 | 2026-09-09(双屏实测连环发现:sdfang 甩角测试后光标压角,daemon 重启即崩,启动崩溃栈实证) |

## 1. 认账

REQ-001 我在 Executor.__init__ 加的启动抬键清扫(三键幂等 mouseUp)
**没有容错 pyautogui.FailSafeException**。实证(2026-09-09 启动崩溃栈):
光标压在 (0,0) 角落 → 清扫的 mouseUp → pyautogui failSafeCheck 抛
FailSafeException(光标位于角落时拒绝任何调用)→ 穿透构造 → daemon
启动即崩。光标压角=甩角急停后的自然状态——清扫与甩角语义撞车,
我引入的。修改引入,我负全责。

## 2. 整改方案

| 项 | 内容 |
|----|------|
| A | 启动抬键清扫逐键容错 FailSafeException:光标压角时该键清扫被 pyautogui 拦截,**记审计「清扫被 FAILSAFE 拦截」并继续**——启动不得崩 |
| B | 语义钉:启动期 FAILSAFE 不映射冻结(光标压角≠用户急停意图,启动时无用户意图) |

### 约束

- 清扫语义不变(三键幂等);容错只拦 FAILSAFE,其余异常仍透出;
- 测试设计(五要素):核心用例——替身 mouseUp 抛 FailSafeException,
  构造 Executor 不崩+审计拦截事件(直出);正常路径回归(三键抬起+审计)。

## 3. 验证证据(2026-09-09)

- P1 红:test_mouse16b 替身 mouseUp 抛 FailSafeException → 构造穿透(确认);
- P3 绿:tests/test_mouse_req01.py 26 过;全量回归 598 过/17 跳过/2 错误
  (2 错误=benchmark_iss8 依赖在线 daemon,时 daemon 因压角冻结未起,非代码回归);
- **真机活实证**:光标压 (0,0),重打包 exe 启动 --daemon——
  审计 seq 5「启动抬键清扫」+ seq 6「启动抬键清扫-FAILSAFE拦截:光标压角拦截 3 键」,
  启动完成,/health 200(0.3.5)。旧 exe 同条件必崩。
- 修复后暴露同根因链下一层:压角启动后甩角电平再冻结 → ISS-0049。
