## 1. 根因(实证链)

**机制层**:ISS-0054 落地时**新增了测试文件**(`tests/test_iconsmerge_iss54.py`),但**未回流 REQ-002 测试设计**——测试设计的 §0 映射、§2 用例表、计数三者都停在 ISS-0054 之前。这与 ISS-0054 只写"待评审→已修复"、未列下游文档清单是同一根因(与 ISS-0076/0077 同源)。

## 2. 三处失准(逐点实证)

### 2.1 TC-ICONS-04 步骤 ↔ 预期自相矛盾

`docs/需求/REQ-002-桌面图标感知-测试设计.md:41`

| 列 | 原文 |
|----|------|
| 场景 | 序对齐-首项虚拟一致性 |
| 步骤 | UIA 首项回收站而 ShellView 首项有路径 |
| 预期结果 | INTERNAL_ERROR 停手;禁止错位合并 |
| 断言代码 | 异常码直出 |

实装 `tests/test_desktop_icons_req02.py:105`:

```python
def test_icons04_obsolete_first_item_check(self):
    """TC-ICONS-04 已废除(ISS-0054):首项序对齐检查机制被按名归并取代;
    该场景(回收站位有路径源)新语义下正常归并,fail-closed 由
    TC-54-02(重名歧义)/TC-54-03(实体无源)承接。保留此注释作废除记录。"""
    a = _assembler(_FakeUia([("回收站", CELL_A), ("微信", CELL_B)]),
                   _FakeListView([G_A, G_B]),
                   _FakeShellView([r"C:\X\回收站.lnk", r"D:\微信.lnk"]))
    items = a.assemble()                      # 新语义:不再误判序对齐失败
    assert items[0]["display"] == "回收站" and items[0]["source"] is None
    assert items[1]["source"] == r"D:\微信.lnk"
```

**函数名 `..._obsolete_first_item_check`,docstring 明写"已废除",body 断言正常归并**——而设计文档的"预期结果"仍是 `INTERNAL_ERROR 停手`。步骤描述的场景与实装用例的场景**是同一个**,预期结论**相反**。

**这是最危险的一类失准**:测试设计说"应报错",实装说"应正常"——按铁律"私改测试迁就实现"属高频反模式,而此处**反向发生了**:测试改了(正确,因机制变了),设计文档没跟上,于是文档看起来像是实现违反了设计。

### 2.2 TC-ICONS-01 用例名与设计矛盾(原"计数过期"一说已实测否定)

`:8` `| 状态 | 已实施(tests/test_desktop_icons_req02.py,16 用例全绿) |`

**实测:`grep -n "def test_" tests/test_desktop_icons_req02.py` → 16 条**,与状态栏"16 用例"**一致,计数无错**。§2 表内用例亦为 16 行。**本条原判有误,予以撤回。**

但实测比对暴露了另一处**真失准**——函数名与设计文档的机制描述矛盾:

| 位置 | 内容 |
|------|------|
| 设计文档 `:37` | `TC-ICONS-01 \| **三路按索引合并** \| 替身三路 \| assemble() \| 条目**按索引**逐字段对齐` |
| 实装 `test_desktop_icons_req02.py:84` | `def test_icons01_**merge_by_index**(self):` |

即:实装的 TC-ICONS-01 **函数名仍叫 `merge_by_index`(按索引合并)**,而该用例通过 → 说明其**断言的字段对齐在当前按名归并语义下依然成立**(替身三路同名同序时,两种归并键结果一致,用例无法区分机制)。**这是"断言无法区分机制"的用例强度问题**:ISS-0054 换了归并键,TC-ICONS-01 全绿但**没红过一次**——它对该机制变更免疫,属测试设计未覆盖的盲区(A-2 序分叉场景由 TC-54-01 承接)。

**处置建议**:TC-ICONS-01 的用例名与描述应改为"三路按名归并",并**补一条能区分机制的用例**(三路**同名不同序** → 按名归并仍正确);否则该用例永远无法为归并键变更提供回归保护。

### 2.3 孤儿用例(违反本文档自己的 R6 闸门)

`tests/test_iconsmerge_iss54.py` 含 TC-54-01~04 四条用例,覆盖 ISS-0054 引入的两条 fail-closed 分支:

| 用例 | 覆盖分支 |
|------|---------|
| TC-54-02 | `归并失败:图标重名歧义` |
| TC-54-03 | `归并失败:图标 {display!r} 无匹配来源` |

而 §0 映射表(`:12-20`)只映射了 `TC-ICONS-05/06a/11c` 到 ICONS-05,**`test_iconsmerge_iss54.py` 不被任何 REQ 文档引用**。

该文件 `:0` 自己立的规矩(完备性闸门①/R6):**"孤儿即漏"**——现被自己违反。
