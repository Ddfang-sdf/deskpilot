## 1. 认账

ISS-0025 把哈希守卫搬出 pytest 时承诺"由构建/CI 调用"——**承诺没落地**;
ISS-0030 挂 local 守望时没考虑"服务自身也是写入者"。两条都是"守护的接替者/
共存者验收"缺失,对应反模式「守卫搬走/删除后不验收接替者」。

## 2. 整改项

| # | 修复 | 约束 |
|---|------|------|
| B1 | _PolicyWatchThread 提取 `check_once()`(读 sha→比对→事件→刷新,可单测);增 `refresh(fp)` 线程安全刷新;WhitelistAdmin 增可选 `on_written` 回调,双文件落盘后触发;main 把回调接上 local 守望线程的 refresh | 内部写入永不产生"外部修改"假警;真外部改动仍即时留痕 |
| B6 | release.yml 打包后新增校验 step:`python -c "…verify_policy_sync('policy.yml','staging/policy.yml')…"` 失败即红;本地删除滞留的 release/policy.yml 陈旧产物(未被 git 追踪,属构建残留) | 守卫的真实调用点=CI,不是单测 |
