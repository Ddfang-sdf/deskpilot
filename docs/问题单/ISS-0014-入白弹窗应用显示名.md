# ISS-0014：入白审批弹窗只显进程名，用户看不懂在批什么

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0014 |
| 标题 | 入白审批弹窗文案为裸进程名（calc.exe），用户无法判断"这是个啥软件"；须显示用户可读的应用显示名（无窗口实拍时的最低可理解性） |
| 严重级 | **中**（审批是可理解性依赖的人机裁决——看不懂在批什么，批准权形同虚设；功能链路本身正常） |
| 状态 | 待评审（方案待 sdfang 审核） |
| 提出 | 2026-08-31（sdfang 手工验收 ISS-0012/0013 时目击："我都不知道这是个啥软件"） |

## 1. 问题现状

1. 入白审批弹窗标题为「AI 请求操作新应用『calc.exe』」（`enforcement.py`
   `_describe_enroll`）：裸进程名无任何用户可读信息。calc.exe / ApplicationFrameHost.exe
   这类名称普通用户无法映射到"计算器 / 应用宿主"。
2. launch_app 路径无绑定窗口，弹窗无实拍缩略图，进程名是**唯一**识别线索——
   线索不可读 = 裁决不可理解。
3. attach 路径有绑定窗口标题可用（`BindingRecord.window_title` / 实况标题），
   但当前文案同样只用进程名，浪费了现成线索。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **文案只写了技术标识** | ISS-0012 §6 接口定义写"含进程名"，实现按字面落地；进程名是机器标识不是人话，违背审批描述"人话层+技术底注"的两段式原则（详细设计 §8.7 审批描述） |
| R2 | **显示名解析能力缺位** | 没有"进程名 → 应用显示名"的解析入口：exe 版本信息 FileDescription / 窗口标题两条现成数据源都未利用 |

## 3. 整改方案

### 3.1 总体

**主名用显示名，技术名留底注**：弹窗主标题显示应用显示名（取不到回退进程名），
进程名保留在技术底注行——可理解性与可审计性兼得。

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | **显示名解析纯函数**（新模块 `deskpilot/appnames.py` 或并入 monitors 同级）：`app_display_name(process: str, window_title: str = "") -> str`。解析序：① window_title 非空 → 返回窗口标题（attach 路径，最贴近实况）；② 按进程名解析 exe 全路径（PATH/App Paths），读版本信息 FileDescription（ctypes GetFileVersionInfoW + VerQueryValueW，不引第三方依赖）；③ 全部失败 → 返回进程名本身（fail-closed 文案不失信息）。 |
| B | **入白文案改两段式**：`_describe_enroll` 主标题 = `AI 请求操作新应用「{显示名}」`；底注 = `进程 {proc}（{显示名解析来源}）+ 三态含义说明`。launch_app 走 ②③，attach 走 ①。 |
| C | **常规 L3 审批顺带核查**：`_describe` 的 plain_target 已是窗口标题（attach 系）✓；launch_app 的 headline 为 `启动应用 {app}` 同为裸名——同用 A 解析改善（同源改法，不新增机制）。 |

### 3.3 约束

- 解析全失败必须回退进程名（禁止空串/异常阻断审批流——文案层 fail-closed）。
- 版本信息解析不得引入新第三方依赖（ctypes 直读）。
- 解析耗时有界（单进程 < 100ms；解析失败不阻塞闸流）。
- 只改文案层，不动裁决逻辑与弹窗协议。

## 4. 测试方案

### 4.1 单元（先行）

| 用例 | 断言 |
|------|------|
| 窗口标题优先 | app_display_name("whatever.exe", "无标题 - 记事本") → "无标题 - 记事本"（直出） |
| FileDescription 命中 | app_display_name("calc.exe")（本机真实计算器）→ 含 "Calculator" 或 "计算器"（数据层：系统真实版本信息直出） |
| 未知进程回退 | app_display_name("no-such-app-xyz.exe") → "no-such-app-xyz.exe"（进程名原样，直出） |
| 空标题走解析 | app_display_name("calc.exe", "") → 同 FileDescription 路径 |
| 入白描述两段式 | _describe_enroll 主标题含显示名、底注含进程名（字符串直出） |
| 耗时上界 | 单次解析 < 100ms（clock 直出） |

### 4.2 集成验收

- 全量 pytest 绿
- 实盘：触发 launch_app calc.exe → 弹窗主标题显示「计算器」（或 Calculator），底注含 calc.exe（R5 终效应：截图/目击为证）
