# ISS-0052:daemon 启动期首个 /call 瞬态 500——启动竞态待诊断

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0052 |
| 标题 | daemon 启动后数秒内首个 /call 返回 HTTP 500(非结构化错误体),立即重试即恢复;与待查②(daemon 间歇性无响应)疑为同族启动竞态,需专项诊断 |
| 严重级 | **低**(瞬态自愈,重试即过;但 500 非结构化——AI 拿到裸 HTTP 错误而非错误码,违背 AI-first 可诊断) |
| 状态 | **建单,待诊断** |
| 提出 | 2026-09-10(ISS-0049 活实证期间:daemon 启动 ~15s 后首个 move 调用 HTTP 500,立即重试 ok=True) |

## 1. 背景(实证)

2026-09-10 11:42,daemon(--daemon)启动约 15s 后:
- 首个 /call(move)→ **HTTP 500 Internal Server Error**(urllib HTTPError,
  非结构化 JSON 错误体);
- 立即重试同调用 → ok=True;此后 /health、move、get_cursor 全正常。
- 与手工测试记录待查②(daemon 间歇性 /call 挂起自愈,/health 仍活)
  疑为同族:启动期初始化竞态(组件装配未完成时 /call 已可达)。

## 2. 待诊断方向(评审后定)

| # | 方向 |
|---|------|
| ① | /call 在装配完成前应**拒绝服务式应答**(结构化 STARTING_UP 错误码+retry_after_ms 指引),而非裸 500——AI 可自愈重试 |
| ② | 启动次序:HTTP 监听应在全部组件就绪后再绑(或就绪探针门控 /call) |
| ③ | 与待查②的间歇性挂起合并诊断(同抓线程快照) |

### 约束

- 先诊断后方案;本条只锁定"裸 500 必须结构化"(AI-first 底线);
- 复现路径已实证:重启 daemon 后 ~15s 内发 /call。
