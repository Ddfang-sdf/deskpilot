# ISS-0074：【文档】错误码登记册与实现漂移（附录 A 缺登 5 码 + 计数声明三处失真）

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0074 |
| 标题 | 错误码登记册（详细设计附录 A）与 `errors.py` 实有常量漂移——5 个原因码从未登记，计数声明散落三处且互相矛盾，测试设计说明书 §2.5 的"附录 A 每码至少一条用例"覆盖门因此口径失真 |
| 严重级 | **中**（文档/门禁级：不影响运行时行为，但使"错误码全覆盖"这一质量门失去可判定性；AI 侧可发现性受损——未登记码在详细设计中检索不到） |
| 状态 | 待整改 |
| 提出 | 2026-09-11（ISS-0072 P2 核对时发现，按范围控制纪律记入待查清单 ⑫，现转正建单） |

## 1. 现场实证

**计数三处不一（实测命令见 §4）**：

| 出处 | 声明 | 实测 |
|------|------|------|
| `deskpilot/errors.py:3` | 原"（19 个原因码）" | 文件实有 **26** 个常量（**已由 ISS-0072 P3 去除该计数自述**，见 §3.1 改动 5） |
| `docs/功能设计说明书.md:219` | 原"全量 20 个错误码见详细设计说明书附录 A" | 附录 A 实有 **21** 行（**已由 ISS-0072 P3 去数字**，见 §3.1 改动 4） |
| `docs/详细设计说明书.md` 附录 A | 无行数/计数声明（仅变更记录 v0.5 历史行称"全量 20 码"） | 实有 **21** 行 |

**附录 A 缺登 5 码**（逐字实测：`errors.py` 常量集合 − 附录 A 行键集合）：

| 未登记码 | 引入单 | 出处 |
|----------|--------|------|
| `ELEVATION_REQUIRED` | ISS-0017 | `errors.py:30` |
| `WINDOW_OCCLUDED` | ISS-0017 | `errors.py:31` |
| `TOOL_TIMEOUT` | ISS-0009 | `errors.py:36` |
| `OCR_TEXT_NOT_FOUND` | ISS-0021 | `errors.py:38` |
| `OCR_AMBIGUOUS` | ISS-0021 | `errors.py:39` |

`TOOL_TIMEOUT` 另有旁证：`errors.py:40-41` 的 ISS-0029 注释记录"原 `ALL_REASON_CODES`
登记册……漏登 `TOOL_TIMEOUT`，已按 sdfang 裁定删除"——登记册被删，附录 A 未接棒。

## 2. 根因（机制层）

**错误码有两个权威来源，但只有一个是机器可校验的，另一个靠人手同步。**

`errors.py` 是运行时唯一权威（26 个模块级常量，`deskpilot/*.py` 直接 import 使用）；
详细设计附录 A 是人类/AI 的检索面与测试设计的覆盖基准（`测试设计说明书 §2.5`：
"附录 A 每个错误码至少一条用例"）。两者之间**没有任何自动一致性校验**，
同步全靠"加码时记得回填"这一口头纪律。

历次加码单（ISS-0009/0017/0021/0023/0039）都在代码侧正确落地（常量 + 使用 + 测试），
但回填附录 A 这一步无人检查、也无测试守卫——于是漂移静默累积到 5 码。
计数声明比行数更早失真：加行的人改了表、没改散落三处的文字计数，
而三处计数又分属三个文档、三种措辞（"N 个原因码"/"全量 N 个错误码"/"全量 N 码"），
无单源。

**为什么这是缺陷**：ISS-0072 的 TC-72-14 试图断言"文档已同步"时，第一版断言
`assert "20 个错误码" in 详细设计说明书` 直接失败——不是因为它写错了字，而是因为
**这个基准值本身已失真且无处可核对**。一个不可核对的基准，等于覆盖门没有基准。

## 3. 整改方案（待评审）

### 3.1 改动点

| # | 位置 | 改动 |
|---|------|------|
| 1 | `docs/详细设计说明书.md` 附录 A | 补齐 5 行（`ELEVATION_REQUIRED` / `WINDOW_OCCLUDED` / `TOOL_TIMEOUT` / `OCR_TEXT_NOT_FOUND` / `OCR_AMBIGUOUS`），产生方/含义/给 AI 的引导三列须与实现实际行为一致（逐码读源码取，不臆造） |
| 2 | 附录 A 表尾 | 加单源声明行"本表即错误码登记册（全量 N 码，与 `deskpilot/errors.py` 常量逐码对应）"——N 由行数手工同步（见改动 3 的守卫③） |
| 3 | 新增 `tests/test_errors_registry.py` | 双向守卫：① `errors.py` 常量集合 ⊆ 附录 A 行键集合（新增码必须回填）；② 附录 A 行键集合 ⊆ `errors.py` 常量集合（删码必须删行，防死登记）；③ 附录 A 行数 == 表尾"全量 N 码"声明值 |
| 4 | `docs/功能设计说明书.md:219` | 计数改为不写死的表述（"见详细设计说明书附录 A"）——**取"去掉数字"**，消除第二处需要同步的计数。**ISS-0072 P3 已顺带完成**（本单复核即可，不重复改） |
| 5 | `deskpilot/errors.py:3` | 文件头原有的"（N 个原因码）"自述——**ISS-0072 P3 已按"最小诚实"整句去除**（改述为"本文件不自述数量"）。原方案的守卫④（文件头 N == 常量数）随之**取消**：被守卫对象已不存在，守卫无的放矢；数量单源归附录 A 表尾一处 |

**改动 4/5 的来源说明**：这两处本属本单范围，因 ISS-0072 的 TC-72-14 在 P2 核对时
必须以"不写死数字"的方式断言文档同步，遂在当时按 sdfang 裁定的"最小诚实"一并落地。
本单接手时须**复核**其现状（`grep` 确认两处均无硬数字），而非重做；若复核发现回归，
在本单修。原先设想的三处计数收拢为一处（附录 A 表尾），守卫项由 4 条减为 3 条。

### 3.2 约束

- **只改文档与新增守卫测试，不改任何运行时行为**（`errors.py` 仅动第 3 行注释数字）。
- 五码的"产生方/含义/引导"三列必须**读源码逐码取证**（`ELEVATION_REQUIRED` 见
  `enforcement.py` 闸二写前提权边界；`WINDOW_OCCLUDED` 见遮挡判定；
  `TOOL_TIMEOUT` 见超时预算；`OCR_*` 见 `executor/textclick.py`），禁按码名望文生义。
- 变更记录中的历史行（如详细设计 v0.5 "全量 20 码"）**是历史存档，不得修改**——
  守卫只校验当前表尾声明与附录 A 行数，不校验变更记录。
- ISS-0072 的 TC-72-14 已按"最小诚实"改为自洽断言（附录 A 行数 == 表尾声明），
  本单改动 2 加声明行后该用例的 `assert declared` 前置成立，两单互不冲突。

## 4. 测试设计（五要素）

层级：**集成**（允许 import，禁 mock；断言在文件数据层——附录 A 解析结果与
`errors.py` 常量集合，均为被测对象自身产出）。

| 用例 | 场景 | 前提 | 步骤 | 预期结果 | 断言代码 |
|------|------|------|------|----------|----------|
| TC-74-01 | 实现码未登记 | 仓库现状 | 解析附录 A 行键集合 A 与 `errors.py` 常量集合 C | C ⊆ A | `assert C - A == set()` |
| TC-74-02 | 死登记（有行无码） | 同上 | 同上 | A ⊆ C | `assert A - C == set()` |
| TC-74-03 | 附录 A 行数与表尾声明不符 | 同上 | 取附录 A 数据行数 n，解析表尾"全量 N 码" | n == N | `assert re.search(r"全量 (\d+) 码", 附录A表尾).group(1) == str(n)` |
| TC-74-04 | 功能设计说明书写死计数（防回归） | 同上 | 读 `功能设计说明书.md` 强制层拒绝码段 | 不出现"全量 N 个错误码"硬数字 | `assert not re.search(r"全量 \d+ 个错误码", func)` |
| TC-74-05 | `errors.py` 头部重新长出计数自述（防回归） | 同上 | 读 `errors.py` 首行 docstring | 不出现"N 个原因码"硬数字 | `assert not re.search(r"\d+ 个原因码", head)` |

R6 需求↔用例映射：`errors.py` 常量全集 → TC-74-01/02；附录 A 表尾声明 → TC-74-03；
「计数不得散落」这一不变量 → TC-74-04（功能设计）+ TC-74-05（`errors.py` 头部）
两处反向守卫；无孤儿。

R7 失效原因核对：TC-74-01/02 **不得**写成 `assert C == A` 一条了事——
两向失败原因不同（漏登 vs 死登记），合并后定位不出方向，违反 R7。
