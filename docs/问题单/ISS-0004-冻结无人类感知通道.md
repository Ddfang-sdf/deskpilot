# ISS-0004：急停冻结/解冻无人类感知通道（冻结提示弹窗）

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0004 |
| 标题 | 冻结发生时人类无感知、解冻成功无反馈：需冻结提示弹窗（立即解冻 / 稍后提醒，滑入滑出动画，热键解冻自动消窗） |
| 严重级 | 中（安全机制的人因缺口：冻结是 fail-safe 兜底，但人类不知道它发生了，也不知道何时恢复） |
| 状态 | 已关闭（2026-08-21 验收通过：201 测试全绿；实盘冻结弹窗滑入/热键消窗/按钮解冻/稍后提醒重弹全链路通过） |
| 提出 | 2026-08-21（A 机实盘：MCP 手工测试期间，冻结/解冻的效果用户只能"问 AI"确认） |

## 1. 问题现状

1. **冻结无通知**：甩角/热键触发冻结后，人类无任何感知——唯一的"现象"是 AI 的写操作
   开始被拒，而人类可能根本没在看 AI 会话。实盘（ISS-0002）冻结持续约 15 小时才被发现。
2. **解冻无反馈**：人类按 F11 或跑 `--reset` 后，没有任何手段确认解冻成功，只能问 AI
   或去翻审计 JSONL。
3. 现有"人类通知"设计（详细设计 §11.2 功能 3"触发后…通知人类"、§11.5 输出项"人类通知：
   声音或弹窗（M3 前可为日志）"）从未落地为可用通道——日志不是通知。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | 通知通道未实现 | estop 置位/复位只写审计，无任何进程外通知动作；设计中的"通知人类"停留在文字。 |
| R2 | 状态纯内存，无进程外可读视图 | 冻结标志只有持有进程自己知道（ISS-0002 已确认无跨进程共享），外部弹窗进程无从观察状态变化。 |

## 3. 整改方案

### 3.1 总体

新增**冻结提示弹窗**（独立子进程，Tk toast 形态）：冻结置位时滑入弹出；提供
"立即解冻 / 稍后提醒（默认 180 秒）"两个选项；保留热键解冻，弹窗提示该热键；
任何来源解冻成功，弹窗滑出自动消失。冻结与解冻由此都有人类可见的事件边界。

### 3.2 核心机制：文件邮箱（状态与请求双向同步）

弹窗是独立进程，与 estop 持有进程（daemon 或本地直跑形态）之间需要一个跨进程通道。
选择**纯文件邮箱**（不引入新网络依赖，常驻/本地两种形态统一）：

```
estop 持有进程（owner）                     弹窗子进程（dialog）
─────────────────────                      ─────────────────────
写 <audit_dir>/estop-state.json  ──轮询──▶  每 250ms 读状态文件
  {"frozen":bool,"seq":n,
   "source":str,"ts":...}
读 <audit_dir>/estop-reset.req   ◀──写入──  "立即解冻"点击时写
（由甩角轮询线程 50ms tick 兼任检查）          {"seq":n}
```

- **状态文件 estop-state.json**：owner 在每次置位/复位时原子重写（先写临时文件再
  rename，防读到半截）。`seq` 单调递增（每次状态变化 +1）。owner 启动装配时先写一次
  `frozen:false`（清掉上一进程残留，防陈旧冻结态误导弹窗）。
- **解冻请求 estop-reset.req**：弹窗"立即解冻"写入 `{"seq": <其响应的状态 seq>}`。
  owner 消费条件：**`req.seq == 当前 state.seq` 且当前 frozen=true**，满足则执行
  `_reset("冻结提示弹窗")` 并删除请求文件；不满足（陈旧请求，如旧弹窗对着新一轮冻结）
  直接丢弃删除——防止"旧弹窗的解冻请求误解冻新冻结"。
- owner 侧检查点并入既有甩角轮询线程（50ms tick 顺带 stat 一次，开销可忽略）；
  stdio 瘦代理无监听线程也无 estop 所有权，天然不参与（ISS-0002 归属规则不变）。

### 3.3 弹窗进程状态机（算法核心）

```
                 owner  spawn（冻结置位时，单例守卫）
                   │
                   ▼
            SLIDE_IN（240ms 滑入）
                   │
                   ▼
        ┌────── SHOWN（显示中，250ms 轮询状态文件）──────┐
        │          │                │                   │
  点"立即解冻"  点"稍后提醒"      轮询发现 frozen=false   │
  写 reset.req   │            （热键/CLI/HTTP 解冻）     │
        │        ▼                │                   │
        │   SLIDE_OUT → SNOOZED ◀─┘                   │
        │   （隐藏不退出，deadline=now+180s）           │
        │        │                                    │
        │   SNOOZED 轮询：now≥deadline 且仍 frozen     │
        │        │──▶ SLIDE_IN（重新弹出）             │
        │        │   若已解冻 ──▶ SLIDE_OUT → 退出     │
        ▼        ▼                                    ▼
   继续轮询 frozen=false ──▶ SLIDE_OUT（240ms 滑出）──▶ 进程退出
```

规则细化：

1. **单例**：owner 置位时先查 `<audit_dir>/estop-dialog.lock`（内含弹窗 pid 与最后
   心跳）；pid 存活则不重复 spawn（甩角连发/热键连按只弹一次）。弹窗每 1s 刷新心跳。
   已知限制：弹窗在 SNOOZED 期崩溃则本轮不再提醒（下一次冻结置位会重新拉起），
   列入附录待评审，不做 owner 侧看门狗（50ms tick 里做进程存活检查代价不值）。
2. **稍后提醒**：点击后滑出隐藏但**进程不退出**（避免重新拉起的一次性解压延迟）；
   180 秒默认值写入 policy estop 节（`freeze_remind_interval`，缺省 180），到点仍冻结
   则重新滑入；期间解冻则滑出收尾（窗已隐藏则直接退出）。
3. **解冻殊途同归**：热键 F11、`--reset`、POST /estop/reset、弹窗"立即解冻"四条路径
   全部汇聚到 estop `_reset`（既有设计），状态文件翻转后弹窗在 ≤250ms 内感知并滑出
   消失——"热键解冻弹窗自动消失"由状态轮询天然保证，无需额外信号。
4. **弹窗内容**：
   - 标题：DeskPilot 急停；正文："DeskPilot 已冻结：AI 的写操作已全部拒绝
     （EMERGENCY_STOP），L0 只读工具不受影响"；触发来源与时间（读状态文件 source/ts）
   - 按钮：[立即解冻]　[稍后提醒（180s）]
   - 提示行："也可随时按 Ctrl+Shift+F11 直接解冻，本窗口会自动消失"
5. **动画（对称原则）**：出现=滑入，消失=滑出，方向相反、时长一致（240ms）。
   从主屏右缘外滑入至右上角（右边距 16px、上边距 48px）；`root.after(16)` 驱动
   约 60fps，ease-out 三次方缓动：`x(t) = x_start + (x_target - x_start)·(1-(1-t)³)`；
   滑出为同一曲线反向，结束销毁窗口。窗体 `overrideredirect(True)` + 置顶，
   不抢输入焦点（避免打断人类当前键鼠操作——弹窗只读点击，不抢键盘）。
   多显示器只弹主屏（M3 前接受，列入待评审）。

### 3.4 进程形态与装配

- 复用 onefile 分发模式：`deskpilot.exe --freeze-notify <audit_dir>`（打包入口
  run_deskpilot.py 增分支，与 --approval-dialog 同构）；非冻结形态
  `python -m deskpilot.freeze_dialog`。
- EstopMonitor 增可选 `on_state_change(frozen, source)` 回调（置位/复位 choke point
  已有，钩子零侵入）；main 装配 FreezeNotifier：回调里写状态文件 + 置位时单例 spawn。
- 弹窗 spawn 也须剥离 `_MEIPASS2`（approval_ui 已有同款教训，复用其 env 处理）。

### 3.5 约束（fail-closed 保持）

- 弹窗是**通知层**，不是安全闸：弹窗崩溃/被杀不影响冻结语义（冻结标志仍在 owner 内存，
  写操作照常拒绝）；解冻权仍只属于本地人类通道四条既有路径
- 状态/请求文件只承载布尔与序号，不接受任何指令参数，防伪造语义最小化
  （本地文件写权限等价于本地人类，威胁模型 §0 不变）
- 复位组合键永不进许可表等既有约束不变

## 4. 测试方案

### 4.1 单元

| 用例 | 断言 |
|------|------|
| 状态文件随置位/复位翻转 | 触发急停 → estop-state.json frozen=true 且 seq+1、source 正确；复位 → frozen=false；文件原子可读（无半截 JSON） |
| 解冻请求消费守卫 | req.seq 匹配且 frozen → 执行复位并删文件；req.seq 陈旧 → 丢弃不执行；未冻结时请求 → 丢弃不执行 |
| SNOOZED 重提醒判定 | 注入测试时钟：点稍后提醒 → 179s 不弹、180s 且仍 frozen → 重弹；期间解冻 → 不重弹且进程退出 |
| 单例守卫 | lock pid 存活时二次置位不再 spawn；pid 死亡（陈旧 lock）→ 允许 spawn |
| 热键解冻→弹窗收尾 | 模拟状态文件 frozen=true→false 翻转 → 弹窗逻辑进入 SLIDE_OUT 并退出（窗口句柄销毁） |
| 动画参数 | 滑入/滑出位移曲线互为反向（同参数表驱动），时长一致 240ms |

### 4.2 集成验收（实盘）

- 甩角/热键冻结 → 弹窗滑入，内容含触发来源与热键提示 → 点"稍后提醒"→ 滑出，
  180s 后仍冻结则重新滑入 → 点"立即解冻"→ 弹窗滑出消失，写操作恢复
- 再次冻结 → 按 Ctrl+Shift+F11 → 弹窗 ≤1s 内滑出自动消失，写操作恢复
- 杀掉弹窗进程 → 冻结语义不受影响（写操作仍拒绝）；再次触发冻结 → 弹窗重新拉起
