# ISS-0028：急停甩角驻留阈值 200ms→1000ms

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0028 |
| 标题 | 鼠标滑至角落停留 200ms 即触发急停冻结,正常操作频繁误触(实证多次),产生"狼来了"效应消解冻结信号可信度 |
| 严重级 | **低**（体验调参;sdfang 拍板阈值 1000ms） |
| 状态 | **建单,待评审** |
| 提出 | 2026-09-04（sdfang 误触实证并裁定:阈值改为 1s） |

## 1. 问题现状

`policy.yml` estop.corner_hold_ms=200。鼠标自然甩到屏幕角落短暂停留
即全冻结+弹卡片;09-02 以来 sdfang 本人已多次误触,对冻结提示麻木。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **驻留阈值过低** | 200ms 小于人类正常甩鼠标到角落的自然停顿时长 |

## 3. 整改方案

| 项 | 内容 |
|----|------|
| A | `policy.yml` estop.corner_hold_ms: 200 → 1000 |
| B | 测试装配 `tests/conftest.py` make_policy 默认同步 1000（与策略单源一致） |
| C | dist\policy.yml 同步（追加式修改,保护 seeyou 入白行） |

### 约束

- 急停响应变慢是接受面（1000ms 仍远快于人类察觉"该停"的决策时延);
- 阈值语义/触发逻辑不动,只改数值。

## 4. 测试设计(五要素)

层级:单元（FakeClock 直出）+ 策略加载（直出）。

| 用例 | 场景 | 前提 | 步骤 | 预期结果 | 断言代码 |
|------|------|------|------|----------|----------|
| TC-COR-01 | 新阈值加载(单元) | 标准 policy.yml | 加载策略 | corner_hold_ms==1000 | 策略对象字段直出 |
| TC-COR-02 | 999ms 不触发(单元) | FakeClock;鼠标已入角 | 推进 999ms | 未冻结 | `estop.is_frozen()==False`（直出） |
| TC-COR-03 | 1001ms 触发(单元) | 同上 | 推进 1001ms | 冻结 | `estop.is_frozen()==True`（直出） |
| TC-COR-04 | 装配默认同步(单元) | conftest make_policy() | 取默认策略 | corner_hold_ms==1000 | 字段直出 |

装配守门:R1 全替身(FakeClock);R2 单元层零打桩;R3 字段/方法直出;
R4 路径变迁=policy.yml 数值、dist 同步、conftest 默认;R5 终效应=冻结
标志翻转(TC-COR-02/03)。
