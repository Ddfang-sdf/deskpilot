# ISS-0011：Release 断档与安装指导缺失

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0011 |
| 标题 | 用户在 GitHub 找不到新 exe（v0.3.0 有 tag 无 release 产物），且缺乏可照做的安装集成指导；发布全手工无自动化 |
| 严重级 | 高（分发链路断：新用户装不上/装错旧版；集成方无法自助落地） |
| 状态 | 待评审（方案待 sdfang 审核） |
| 提出 | 2026-08-29（实盘反馈：找不到 exe、没有安装指导） |

## 1. 问题现状

1. **Release 断档**：Releases 页最新产物是 **v0.2.0（2026-08-17）**；
   v0.3.0 已打 tag 但**没有对应 release 与 exe 附件**。用户能下载到的版本缺失：
   常驻 daemon（ISS-0001）、急停复位通道（ISS-0002）、L3 同步审批（ISS-0003）、
   冻结通知弹窗（ISS-0004/0005）、冻结单例与解冻修复（ISS-0006），
   以及新主页与文档。下载旧版即踩已修问题。
2. **发布全手工**：仓库**无任何 CI 工作流**（`.github/workflows/` 不存在），
   exe 构建、打包、上传、发布说明全靠人肉，注定再次断档。
3. **安装指导不成体系**：README 只有"下载 + MCP 指向 exe"三步，缺：
   daemon 常驻形态怎么装怎么用（ISS-0001 的核心价值用户感知不到）、
   开机自启、policy.yml 怎么按自家环境改、各客户端配置样例汇总、
   装完怎么验证、升级怎么升、常见坑（杀软误报/端口占用/policy 缺失/内网离线）怎么办。
   集成使用方（含内网环境）无法自助完成落地。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **发布无自动化** | 打 tag 与出 exe 之间没有流水线，发不发、何时发全看人记不记得，结构性断档。 |
| R2 | **安装指导没有按用户旅程组织** | 文档按"仓库视角"写（有什么），不按"集成方视角"写（从下载到跑起来的每一步与每步的验证）。daemon 这个新形态没有任何落地指引。 |
| R3 | **缺一键化入口** | 没有任何脚本把"下载→落位→注册→（可选）自启"串起来，集成方只能手抄零散命令，出错不可复现。 |

## 3. 整改方案

### 3.1 总体

**tag 即发布（自动化）、安装按旅程成文（指导书）、一键可复现（脚本）。**
先补发当前断档，再上流水线防再犯，最后把安装指导写成可照做的文档。

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | **补发断档 release**：以当前 main（v0.3.0 + ISS-0006）构建 exe，发 `v0.3.1` release：exe+policy.yml 打包 zip、SHA256 校验文件、发布说明（含与 v0.2.0 的差异摘要）。 |
| B | **GitHub Actions 发布流水线**：`release.yml`——推 `v*` tag 触发：windows-latest 装 Python 3.13 → `pip install -e . pyinstaller` → `pyinstaller deskpilot.spec` → 拷贝 policy.yml → 打 zip → 生成 SHA256 → `gh release create`（正文取 `release/RELEASE_NOTES.md` 模板，附流水线生成的校验值）。无 tag 不跑；产物即流水线产物，杜绝人肉上传。 |
| C | **安装指导书 `docs/INSTALL.md`**（README 顶部放显眼入口）：按旅程分章——① 下载与校验（release 页/校验和核对）；② 落位（目录约定、policy.yml 必须同目录）；③ 注册到客户端（Claude Code / Claude Desktop / Cursor / 通用 stdio JSON 四段可直接复制）；④ 常驻 daemon（启动、验证 /health、开机自启两种方式：启动文件夹与计划任务）；⑤ policy.yml 定制（白名单/按键/急停/审计目录，各字段示例）；⑥ 验证清单（截屏/取光标/元素树三连）；⑦ 升级（替换 exe + 何时需要重启 daemon）；⑧ 常见问题（杀软误报加白、9420 占用、policy 未找到、内网拷贝分发、审批窗不弹）。 |
| D | **一键安装脚本 `scripts/install.ps1`**：参数化（-InstallDir、-WithDaemon、-AutoStart、-Client claude-code/cursor/all）；行为：下载或就地使用 zip → 解压落位 → 注册 MCP（对应客户端）→ 可选启动 daemon 与写自启 → 打印验证结果；幂等（重复执行结果一致），失败带明确退出码。 |
| E | **README 下载入口强化**：徽章区加"下载最新 exe"直达链接（releases/latest）；安装段落改为三步摘要 + 指向 INSTALL.md。 |

### 3.3 约束

- 流水线构建必须与本地构建同规格（同一 deskpilot.spec、同一 Python 版本）；产物先在 PR 触发器上做干跑验证再启用 tag 触发。
- 发布说明模板化（版本、变更摘要、SHA256、最低系统要求），不允许空白正文上线。
- install.ps1 的注册行为必须与手工 `claude mcp add` 完全等价（复用同一命令，不发明新注册方式）。

## 4. 测试方案

### 4.1 单元/干跑（先行）

| 用例 | 断言 |
|------|------|
| 流水线语法 | actionlint / 干跑通过；zip 产物含 exe+policy.yml+SHA256 三件套 |
| 校验值 | 流水线产出的 SHA256 与产物实际哈希一致（重算比对） |
| install.ps1 幂等 | 同参数连跑两次：目录内容一致、注册表项不重复、退出码 0 |
| 客户端注册 | 执行后 `claude mcp list` 出现 deskpilot 且指向安装目录 exe |
| 发布说明模板 | 渲染结果含版本号/校验值/系统要求三要素，无缺项 |

### 4.2 集成验收

- 干净 Windows 环境（VM 或沙箱）按 INSTALL.md 从零照做 → 三连验证全过，不查任何额外资料
- 打一个测试 tag → 流水线自动产出 release，下载 zip 校验通过、exe 可启动
- 内网情景模拟（断 GitHub）：拷贝 zip 到目标机 → 按指导书完成落地（无需外网）
