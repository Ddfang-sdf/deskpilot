# ISS-0105:【修改引入】读回选读通道假阳性——空文档+焦点落空时剪贴板残留请求文本致假命中

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0105 |
| 标题 | ISS-0100 C 引入的读回通道③(选读 ctrl+a/ctrl+c)在「目标文档为空 ∧ 焦点不在编辑区」组合下失效:粘贴落空后,选读在标签条上空操作,剪贴板里残留的是**桥刚写入的请求文本本身**,`text in current` 子串比对假命中——报「读回校验一致」ok:true,而文档实际为空;fail-closed 被自身选读通道绕过 |
| 严重级 | **高**(写操作正确性:ISS-0100 同一信任面的漏网组合;已实盘实证) |
| 状态 | **建单待评审**(2026-09-22 ISS-0104 P1 实证抓出;改法待 sdfang 裁定) |
| 提出 | 2026-09-22 tests/test_typefocus_iss104 P1 逃逸口实证:空文档+SetFocus TabItem 后 type_text 报 ok「读回校验一致」,文档实为空(UIA 直读) |

## 1. 实证(机制层)

- 前提:Win11 记事本空文档,焦点经 UIA SetFocus 置于 TabItem(非编辑区);
- 序列:桥 pyperclip.copy(请求文本) → ctrl+v(焦点在标签条,落空) → 读回轮询:
  通道①②无值(空文档 TextPattern 返回空串) → 通道③ ctrl+a/ctrl+c(标签条上
  空操作,剪贴板未被改写) → pyperclip.paste() 读到**请求文本本身** →
  `text in current` 命中 → ok「读回校验一致」;
- 对照:文档非空时(W6 现场)通道②返回旧内容,正确拦下 TYPE_MISMATCH——
  假阳性只在「空文档+焦点落空」组合出现;ISS-0104(聚焦缺失)是本组合的
  触发面之一,两单交集但根因不同。

## 2. 根因(机制层)

选读通道的隐含假设:「ctrl+c 后剪贴板内容=目标应用选区内容」。焦点落空时
ctrl+c 是空操作,剪贴板保持桥写入的请求文本——**读回读到了自己写的副本**,
比对退化成自证。信任锚点错置(ISS-0093 同族形态):剪贴板内容不构成
「落地文本」的证明,除非能证明它被目标应用改写过。

## 3. 改法方向(待裁定,不自作主张)

- A. 选读前清空剪贴板(copy 空串/专属哨兵),ctrl+c 后内容仍是哨兵=选读失败
  (交重试/READBACK_UNAVAILABLE);哨兵被改写才进入比对——最小改动,自证
  路径封死;
- B. 选读前后校验剪贴板变化(内容或序列号 ChangeNotify):未变化=选读失败;
- C. A+B 复合(哨兵+变化校验)。
