## 1. 现象与证据(2026-09-16 内网实机,盘上文件全铁证)

**%LOCALAPPDATA%\DeskPilot 快照**(用户杀进程前取出,已存 origin/main:日志md):

| 文件 | 内容 | 含义 |
|------|------|------|
| estop-state.json | frozen:**true** seq=**15** 鼠标甩角 14:39:50 | 当天最后一次**成功落盘**的冻结 |
| estop-state.json.tmp | frozen:**false** seq=**16** 冻结提示弹窗 14:41:04 | **孤儿**——原子替换从未发生 |
| estop-reset-15.req | {"seq": 15} | **未被消费**的解冻请求(用户后续再点「立即解冻」所写) |
| owner.lock / daemon-heartbeat | pid 50960 role=**stdio** v0.3.7;11:53:25 拿锁,16:55:12 心跳仍新鲜 | 属主进程活着,功能已残(心跳是独立线程) |

**症状逐一对应**:
1. 「鼠标怼左上角一分钟不触发」「解冻无反应」= 甩角线程已于 14:41:04 死亡;
2. 「停掉 AI 仍隔一会自动触发冻结」= state 卡 frozen:true + 弹窗重提醒机制(freeze_dialog.py:98-101 should_remind、:305-316 周期滑出并 refresh_source)反复重放 14:39:50 的**旧**触发源——**零新触发**,seq 停在 15 未变为证;
3. 清场(杀全部进程+重启 Claude Code)后立即恢复 = 新属主启动写 frozen:false 清残留(main.py:183)——**恢复靠重启,不靠系统自愈**。

**代码实证**:
- main.py:149-158 `_corner_loop` 循环体(position/check_corner/check_reset_request/sync/sleep)**无 try/except**,任何异常 → 线程静默死亡;
- freeze_notify.py:57-67 `on_state_change`:写 tmp + os.replace;replace 异常**向上传播**、无重试、无审计、孤儿 tmp 不清理;
- freeze_notify.py:89-98 `check_reset_request`:N=S∧冻结 → **先 unlink req 再 dialog_reset**——reset 抛异常则请求已灭失;
- freeze_notify.py:100-108 `sync_local_with_shared_state`:单向(仅本地冻∧共享 false→复位);反向(本地未冻∧共享 true)无修正路径;
- estop.py:101-113 `_reset`:本地置位与共享写回是「半事务」——本地先行,共享失败无补偿。

**事故链推演**(每步有行号):14:41:04 用户点「立即解冻」→ 属主消费 req(unlink 先行,:89-98)→ dialog_reset 本地复位成功 → on_state_change 共享写回 os.replace **失败**(直接原因无法事后取证——共享冲突/杀软/多进程并发读皆有可能;**失败事实**由孤儿 tmp+陈旧 state 铁证)→ 异常沿 check_reset_request ← _corner_loop(无守卫)传播 → **线程死亡** → state 永久卡 frozen:true + 解冻消费死 → 弹窗按 remind interval(默认约 180s,freeze_dialog.py:332)周期重提醒 = 「自动触发」假象。

## 2. 根因(机制层)

1. **安全通道线程无存活守卫**:corner_loop 一线程兼三职责(甩角监测/解冻请求消费/共享同步),单点异常=三重失效,且死亡无留痕(与 ISS-0084「静默死亡无留痕」同族,本次是进程内线程级);
2. **共享写回是半事务**:本地内存态先提交、共享落盘后置,失败无补偿、无对账 → 劈叉不可恢复(违反 fail-closed:失败路径必须留痕且可自愈);
3. **解冻请求消费次序颠倒**:先灭失请求再执行动作,动作失败=请求永久丢失——文件邮箱协议应具 at-least-once 语义;
4. **同步协议单向**:卡死态(共享 true∧本地 false)无自愈通道,只能等重启。

## 3. 整改方向

| # | 方向 | 说明 |
|---|------|------|
| ① | **线程异常守卫** | _corner_loop(及 _hotkey_loop 消息循环)循环体 try/except:单轮异常 → 节流审计「甩角轮询异常」→ 继续循环;线程不许死 |
| ② | **写回健壮化** | on_state_change:os.replace 失败有限重试(如 3 次退避);仍失败 → 审计「共享状态写失败」+ 清理孤儿 tmp;写前预清同名旧 tmp |
| ③ | **消费次序修正** | check_reset_request:dialog_reset **成功后**再删 req;失败则 req 保留下轮重试(幂等性:_reset 未冻结时 no-op 且记审计,estop.py:101-106,天然幂等) |
| ④ | **双向对账** | sync 扩展:本地未冻 ∧ 共享 frozen:true → 重写共享 frozen:false(审计「共享状态对账修复」);卡死态在一个轮询周期内自愈,不依赖重启。**方向安全性论证**:属主协议(ISS-0084 owner.lock)保证单属主,state 只由属主 notifier 写(弹窗只写 req)——共享 true 必出自属主自身,属主本地内存态为权威,本地未冻 ⇒ 共享 true 即残留,修复安全;**禁止反向**(把共享 true 同步进本地=绕过人类解冻通道) |
| ⑤ | **观测补齐** | 线程存活、状态写失败、对账修复纳入审计事件类型(与 ISS-0084 心跳/遗嘱机制衔接,形态评审定) |

## 4. 测试设计(五要素;完整矩阵 P1 补齐)

**用例1(单元)复位异常不丢解冻请求**
- 场景:check_reset_request 消费 req 时 dialog_reset 抛异常
- 前提:tmpdir 真实 estop-state.json(frozen:true seq=N)+ estop-reset-N.req;estop 桩 dialog_reset side_effect=OSError
- 步骤:调用 check_reset_request
- 预期:req 文件仍在(下轮可重试);异常不上抛
- 断言:`(tmp/f"estop-reset-{N}.req").exists() is True`;调用不抛异常

**用例2(单元)共享写回失败不打死调用方、不留孤儿**
- 场景:on_state_change 的 os.replace 失败
- 前提:monkeypatch os.replace 抛 OSError;tmpdir 真实 state 文件
- 步骤:on_state_change(False, "测试")
- 预期:重试后仍失败 → 记审计、不上抛、孤儿 tmp 被清理
- 断言:函数正常返回;审计桩收到「共享状态写失败」事件;`(tmp/"estop-state.json.tmp").exists() is False`

**用例3(单元)corner_loop 单轮异常线程不死**
- 场景:_corner_loop 轮询中 position() 抛异常
- 前提:pyautogui.position 桩 side_effect=[Exception, (10,10), …](首轮异常后恢复);estop/notifier 桩
- 步骤:以线程运行循环(注入可停止时钟),跨 ≥2 轮
- 预期:线程存活,异常后继续轮询
- 断言:`t.is_alive() is True`;`estop.check_corner.call_count >= 1`(异常轮之后仍有调用)

**用例4(集成,真实文件邮箱)卡死状态自愈**
- 场景:共享卡 frozen:true,本地实例未冻结
- 前提:真实 audit_dir 写入 estop-state.json(frozen:true seq=N);EstopMonitor+FreezeNotifier 真实实例(本地 frozen=False);禁桩
- 步骤:调用 sync_local_with_shared_state;盘读文件
- 预期:共享文件被修复为 frozen:false;审计落「对账修复」事件
- 断言:`json.loads(state_path.read_text())["frozen"] is False`;审计文件含「共享状态对账修复」

**用例5(黑盒)端到端解冻链路**
- 场景:真实服务冻结后,经文件邮箱请求解冻
- 前提:服务运行(测试机),经触发通道进入冻结(共享 state frozen:true seq=S)
- 步骤:向共享目录写 estop-reset-S.req;等待 ≥2 个轮询周期
- 预期:state 变 frozen:false;req 被消费删除
- 断言:盘读 state `frozen is False`;`req 文件不存在`(断言全在系统外表面)

## 5. 约束

- 不改 estop-state.json / estop-reset-*.req 文件邮箱协议的文件名与字段语义(衔接 ISS-0084 §5);
- fail-closed 方向性:对账只许「本地未冻 → 修共享为 false」,**禁止**把共享 true 灌回本地(解冻仅人类通道:热键/CLI/弹窗);
- 任何失败路径必须审计留痕,禁止静默;
- 弹窗(freeze_dialog)提醒机制本身不改——③④落地后其行为自然恢复正常;
- 与 ISS-0091 成对:0091 修「误触发源」,本单修「触发后状态机灾难恢复」;两单可独立实施、独立验收。
