# ISS-0030：出厂策略与用户数据分离（policy.yml / policy.local.yml 双文件）

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0030 |
| 标题 | 永久入白写入出厂 policy.yml——升级/构建同步整文件覆盖即丢用户数据(seeyou 实证 09-02),且哈希守卫与用户写入不可共存;sdfang 裁定双文件方案 |
| 严重级 | **高**（用户数据安全:升级丢配置) |
| 状态 | **实盘验收完成**(2026-09-04:seeyou 迁入 local→出厂同步→daemon 双文件加载合并,/whitelist 实测含 seeyou、双轨指纹审计、attach 秒过零弹框) |
| 提出 | 2026-09-04（09-02 seeyou 入白被同步冲掉实证;sdfang 批准双文件方案） |

## 1. 问题现状

1. **用户数据与出厂文件同体**：永久入白由 WhitelistAdmin 原子写入
   `policy.yml`——同时它是出厂策略文件,升级/构建同步会整文件覆盖
   (09-02 同步冲掉 seeyou.exe 入白,sdfang 重新审批,实证)。
2. **哈希守卫与正常使用互斥**：repo==dist 哈希测试在用户首次入白
   即永久红(当前唯一红)——守卫与用户写入不可共存,暴露"文件职责
   未分离"。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **写入目标=升级覆盖目标** | 用户数据与出厂数据的持久化路径是同一文件 |
| R2 | **加载链单文件单层** | 无"出厂+用户"两层合并语义,无法让两类数据各居其位 |

## 3. 整改方案（双文件,方案已获 sdfang 批准）

| 项 | 内容 |
|----|------|
| A | **双文件布局**：`policy.yml`(出厂,运行期只读)+ `policy.local.yml`(用户数据,运行期唯一写入目标,首次运行自动创建空文件) |
| B | **加载合并**：base 加载后 local 覆盖——whitelist 条目按 process 合并(local 增删优先);**安全参数(keys/terminal_apps/timeouts/estop)仅 base 可定义,local 出现即加载报错+审计(fail-closed,用户文件无权放宽安全面)** |
| C | **写盘改道**：WhitelistAdmin 永久入白/撤回全部写 local,原子写(.bak)延续;base 永不运行时写 |
| D | **升级安全**：安装器/构建同步可自由整文件覆盖 base;local 永不触碰——升级后用户数据完好 |
| E | **指纹审计双轨**：base 变更=「策略文件被外部修改」事件(现语义);local 变更=「用户策略数据变更」事件(新) |
| F | **一次性迁移**：首启检测旧文件与出厂 base 的 whitelist 差异条目,迁入 local(审计「入白迁移」);迁移后 base 恢复出厂形态 |
| G | 构建期哈希守卫(ISS-0025 C)只守 base 同步;local 不入构建校验 |

### 约束

- local 无权放宽安全参数(键表/时限/急停/终端表)——单点安全红线;
- 白名单以外的任何"本地覆盖"需求一律拒绝(通用性:只有白名单是用户数据);
- NEVER_ENROLL 自保护不变;会话入白仍仅内存态。

## 4. 测试设计(五要素)

层级:单元(临时目录装配直出)为主,写盘断言在数据层。

| 用例 | 场景 | 前提 | 步骤 | 预期结果 | 断言代码 |
|------|------|------|------|----------|----------|
| TC-SP-01 | local 入白合并生效(单元) | 临时目录 base+local(local 含 x.exe) | 加载策略 | x.exe 在白名单 | 策略对象 whitelist 直出 |
| TC-SP-02 | local 撤回覆盖出厂(单元) | base 含 notepad,local 删 notepad | 加载策略 | notepad 不在白名单 | whitelist 键直出 |
| TC-SP-03 | local 安全参数被拒(单元) | local 含 keys 段 | 加载策略 | 报错+审计事件(fail-closed) | 异常+审计 JSONL(持久化直出) |
| TC-SP-04 | 入白只写 local(单元) | 两文件就位 | WhitelistAdmin.add_permanent(x) | base sha256 不变,local 含 x | file_sha256+文件内容(数据层直出) |
| TC-SP-05 | 升级覆盖 base 数据完好(单元) | 入白后 | 模拟安装器覆盖 base | local 未动,合并后 x 仍在白名单 | 重载策略 whitelist 直出 |
| TC-SP-06 | 迁移差异条目(单元) | 旧 base 含 seeyou,新出厂无 | 首启迁移 | local 含 seeyou+审计「入白迁移」 | local 内容+审计事件(直出) |
| TC-SP-07 | 双指纹事件(单元) | 两文件 | 各改其一 | 各自对应审计事件 | 审计 JSONL 事件名(直出) |

装配守门:R1 全替身+临时目录(无生产路径);R2 单元层零打桩;
R3 数据层形态断言(sha256/文件内容);R4 路径变迁=加载链(policy.py)、
WhitelistAdmin 写盘目标、首启迁移、指纹审计;R5 终效应=base 永不
变(TC-SP-04)+升级后数据完好(TC-SP-05)。

## 5. 施工接缝与自检校准点(v0.2 评审稿)

| 项 | 现场 | 改法 |
|----|------|------|
| 加载链 | policy.py load_policy(path) 单文件 | 增 `load_policy(path, local_path=None)`:base 校验照旧;local 存在时仅允许 `whitelist` 键(其余→PolicyError fail-closed);合并:local 条目 `max_level: null`=撤回出厂墓碑,其余覆盖/新增 |
| 写盘改道 | whitelist_admin.py WhitelistAdmin(policy_path, static, ...) _write_disk 写 self._path | 构造增 `local_path` + `base_whitelist`(出厂进程集);_write_disk:remove 且 proc∈base→local 写墓碑;否则 local 增删;base 永不写 |
| 主装配 | main.py:255-277 load_policy(str(policy_path)) + WhitelistAdmin(str(policy_path), ...) | local_path=同目录 policy.local.yml;无则创建空文件;merged 传 static;base 集传 base_whitelist |
| 迁移 | 新增 main.py `--migrate-policy <old> <new> <local>` 子命令:diff old/new whitelist,差额迁入 local+审计「入白迁移」;install.ps1 升级路径在覆盖 base 前调用 | TC-SP-06 直出 |
| 指纹审计 | main.py policy_sha256_audit/_PolicyWatchThread | 双轨:base 沿用现语义;local 独立指纹,变更=「用户策略数据变更」 |
| **自检校准** | dist 现状:seeyou.exe 在 base 中(用户数据混入) | 0025 落地后先跑 migrate(把 seeyou 迁入 local),dist base 恢复出厂——升级路径同步验证 |
