# ISS-0006：冻结弹窗多开重叠，解冻请求被错序消费

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0006 |
| 标题 | 冻结弹窗多次弹出、重叠展示；点一次"立即解冻"不生效，无法立即解冻 |
| 严重级 | **高**（急停/解冻是人类安全通道，失效=安全功能不可用） |
| 状态 | **已关闭**（2026-08-29 验收通过：222 用例全绿 + 实盘单弹窗/即点即解） |
| 提出 | 2026-08-29（实盘使用反馈） |

## 1. 问题现状

1. **弹窗多开重叠**：冻结（热键 Ctrl+Shift+F12 或鼠标甩角）触发后，屏幕右下角出现
   多个"DeskPilot 已冻结"弹窗互相叠压，而不是设计预期的单例 toast。
2. **解冻点击失效**：用户在重叠弹窗上点一次"立即解冻"，弹窗不消失、冻结不解除；
   需要点多次或改用 Ctrl+Shift+F11 才能解冻。
3. 期望行为：**无论冻结被触发多少次，屏幕上只有 1 个冻结弹窗；点"立即解冻"
   立即解冻，所有弹窗随即消失。**

## 2. 根因分析

先给出涉及代码位置：`deskpilot/freeze_notify.py`（owner 侧）、`deskpilot/freeze_dialog.py`
（弹窗子进程）、`deskpilot/estop.py`（冻结标志）、`deskpilot/main.py`（装配）。

| # | 根因 | 说明 |
|---|------|------|
| R1 | **解冻请求"先删后验"，多 owner 竞争下被错序丢弃**（解冻失效主因） | `FreezeNotifier.check_reset_request`（freeze_notify.py:54-67）对 `estop-reset.req` 的处理顺序是：**先 `req.unlink()`，后校验**（seq 匹配 ∧ estop.is_frozen）。当前存在多个持有 estop+notifier 的进程（常驻 daemon、daemon 离线期本地直跑的 stdio 实例、重复拉起的实例），每个进程的甩角轮询线程都以 50ms 周期竞争消费同一个 req 文件。先抢到 unlink 的进程若 seq 不匹配或自身未冻结，请求被**静默吞掉**，真正该复位的进程永远看不到它。用户视角：点一次没反应，再点可能碰巧被对的进程抢到才生效。 |
| R2 | **seq 计数器是进程内私有，跨进程语义错位**（R1 的放大器） | seq（freeze_notify.py:36,45）是各进程内存计数器，随各进程自身 `on_state_change` 次数自增。A 进程 seq=a7、B 进程 seq=b3 同时存在；弹窗读共享状态文件拿到的 seq 只是"最后一个写者"的值。守卫条件 `data["seq"] == self._seq` 在多进程下天然会落到错误进程上判定，制造大量"合法但被丢弃"的解冻请求。 |
| R3 | **弹窗单例守卫存在"启动窗口期"竞态**（多开主因之一） | 单例判定 `_dialog_alive()`（freeze_notify.py:71-77）依赖弹窗子进程每秒写 `estop-dialog.lock` 心跳，且首次心跳要等 Tk 装配完成（onefile 冷启动约 2~4 秒）。窗口期内 lock 不存在或超龄（LOCK_MAX_AGE=3s），owner 判定"无弹窗"继续 spawn。多个冻结边沿（多进程各自 estop 独立置位，或复位后快速再触发）在窗口期内叠加 → 多个弹窗子进程同时存活；它们随后互相给对方"续命"（共享心跳同一 lock），**永久共存叠压**。 |
| R4 | **estop 触发面在多进程并存时不收敛**（多开主因之二） | `estop._trigger` 的边沿守卫（estop.py:67-74）只在**单进程内**有效。daemon 在线时 stdio 瘦代理已跳过热键/甩角注册（main.py:177-183），但 daemon 离线时每个本地直跑实例都会起甩角轮询；且 daemon 自身重复启动没有"9420 端口已被占用"的防护。同一甩角手势可被 A、B 两个进程的独立 estop 各自捕获、各自 edge-fire、各自 spawn 弹窗 → 同一时刻 N 个弹窗。 |
| R5 | **解冻语义不全局**（体验放大器） | 解冻（无论热键还是弹窗请求）只复位执行它的那个进程的 estop 标志；共享状态文件虽是唯一事实源，但**没有进程会"看共享状态校正自己"**。于是出现"A 解冻了、B 仍冻结、B 的弹窗还在"的残留态，用户看到的是"点了还有下一个弹框"。 |

## 3. 整改方案

### 3.1 总体

四处收紧，语义归一：**弹窗单例跨进程强约束 + 解冻请求按归属消费 + 触发面单持有者
+ 解冻全局同步**。文件协议（状态文件/req/lock 格式）保持兼容，不引入新依赖。

### 3.2 整改项

| 项 | 内容 | 对应根因 |
|----|------|----------|
| A | **弹窗单例改为命名互斥体（named mutex）**：弹窗子进程启动先抢 `Local\DeskPilotFreezeDialog`（Win32 CreateMutex），抢到才建窗，抢不到直接退出；进程死锁自动释放（OS 语义，无残留）。owner 侧 `_dialog_alive()`/lock 心跳/`LOCK_MAX_AGE` 整体退役——单例判定不再依赖"心跳龄猜测"。 | R3 |
| B | **解冻请求先验后删 + 按归属命名**：`check_reset_request` 把 `unlink` 移到校验**之后**；不匹配/未冻结的进程读完后**放回原样**（不得删除），让真正归属的 owner 在下一拍拿到。req 文件名带 seq（`estop-reset-<seq>.req`），owner 只消费自己写过的 seq。 | R1 |
| C | **seq 跨进程归一**：seq 改为共享状态文件内的单调字段（每次状态重写原子自增，写者即递增者），各进程不再维护内存计数器；守卫语义"req.seq == 当前共享 seq"在多进程下成立。 | R2 |
| D | **触发面单持有者**：① daemon 启动时若 9420 已被占用则显式报错并非零退出（杜绝双 daemon）；② 文档明确"任何时刻只有一个进程起 estop 监听"（现状 stdio 瘦代理已跳过，保持并补回归测试）。 | R4 |
| E | **解冻全局同步**：各进程 50ms tick 增加一行校正——本地 `frozen=True` 但共享状态文件 `frozen=false` 时，本地立即复位并记审计（"复位-共享同步"）。一次解冻（任何来源）全局生效；残留的"下一个弹框"随状态翻转在 250ms 轮询内全部滑出。 | R5 |
| F | **弹窗点击乐观关闭（体验兜底）**：点"立即解冻"写完请求即乐观滑出（请求已写 = 将解冻）；若消费侧竞争导致未生效，弹窗进程的"仍冻结重提醒"机制会在下一提醒周期自然补一个弹窗，而不是让用户对着不消失的弹窗连点。 | R1 残余体验 |

### 3.3 约束（fail-closed 保持）

- 不削弱急停语义：任何来源的冻结仍立即拒绝写操作；整改只动通知/复位链路。
- 复位通道仍只属于本地人类（弹窗按钮 / F11 / CLI），AI 路径无任何新增复位能力。
- 文件协议向后兼容：旧版弹窗子进程遇到新版 owner 时按旧语义退化（多弹但不丢请求），不出现死锁。

## 4. 测试方案

### 4.1 单元（先行）

| 用例 | 断言 |
|------|------|
| 单例互斥 | 两个弹窗子进程并发启动 → 仅一个建窗，另一个立即退出码 0 |
| spawn 窗口期 | owner 不再做存活猜测：每次冻结边沿均 spawn（子进程互斥兜底）；连续 3 次触发 → 互斥测试保证屏幕仅 1 窗 |
| 先验后删 | 非冻结进程 tick 后 req 文件仍存在；冻结 owner tick 后 req 被消费且文件消失 |
| seq 共享自增 | A/B 交替写状态 → seq 单调递增无回退 |
| 全局同步复位 | owner-A 写 frozen=false 后，owner-B（本地 frozen=True）在 1 个 tick 内本地复位并留审计 |
| daemon 防重 | 9420 已占用时第二次 `--daemon` 启动 → 非零退出 + 明确报错 |
| 乐观关闭 | 点击后窗口立即进入滑出，请求文件内容未变 |

### 4.2 集成验收

- 全量 pytest 绿（现有 209 + 新增）
- 实盘 1：daemon + Claude stdio 客户端并存，甩角触发 → **屏幕只有 1 个弹窗** → 点一次"立即解冻" → 弹窗 0.5s 内滑出，estop 复位（再发起写操作通过）
- 实盘 2：连按 F12 → 复位 → 再按 F12 快速序列 3 轮 → 每轮始终单弹窗
- 实盘 3：弹窗展示中强杀 daemon 再重启 → 不出现"幽灵弹窗"与"解冻无门"

## 7. 相邻发现（非本单范围，建议另立问题单）

实盘验收中暴露：`Executor.move`（executor/core.py）直接调 `pyautogui.moveTo` 且无
FailSafeException 捕获；光标停在角落（甩角冻结后的典型状态）时 pyautogui 抛
FailSafeException，异常穿透 tools 层直达 HTTP handler，导致 /call 连接被砍
（客户端见 RemoteDisconnected 而非结构化错误）。建议另单处理：① 像素系调用统一
捕获 FailSafeException → EMERGENCY_STOP 结构化返回；② httpd handler 兜底
catch-all，任何未处理异常回 500 + 结构化错误码。

## 6. 接口定义（SDD 公开入口；测试只允许调用以下入口）

### freeze_dialog（弹窗子进程侧）

| 入口 | 签名 | 语义 |
|------|------|------|
| `SINGLETON_NAME` | `str`，初值 `"Local\\DeskPilotFreezeDialog"` | 命名互斥体名 |
| `acquire_singleton` | `(name: str = SINGLETON_NAME) -> bool` | 抢到互斥体并持有 → True；已被他进程持有或系统调用失败 → False（失败即不建窗） |
| `release_singleton` | `() -> None` | 释放互斥体；重复调用安全 |
| `reset_click_action` | `(state: str) -> str` | `"SHOWN"` → `"write_req_and_slide_out"`；其他 → `"wait"`（乐观关闭决策层） |
| `write_reset_request`（行为变更） | `(audit_dir: str, seq: int) -> None` | 写文件 `estop-reset-<seq>.req`，内容 JSON `{"seq": seq}` |
| `main()`（行为变更） | — | 启动先 `acquire_singleton`，False 立即以 0 退出；点击"立即解冻"写请求后立即滑出（乐观关闭），不再等待状态轮询 |

### freeze_notify（owner 侧）

| 入口 | 签名 | 语义 |
|------|------|------|
| `REQ_PREFIX` | `str`，初值 `"estop-reset-"` | req 文件名形为 `<REQ_PREFIX><seq>.req` |
| `on_state_change`（行为变更） | `(frozen: bool, source: str) -> None` | seq 改为共享状态文件内单调自增（跨进程不回退）；frozen=True 时无条件 spawn（单例由子进程互斥兜底）；原子重写状态文件不变 |
| `check_reset_request`（行为变更） | `(estop) -> None` | 扫描 `estop-reset-*.req`，设共享 seq 为 S、req 序号 N：N<S 删除（陈旧清理）；N=S ∧ estop 已冻结 → `estop.dialog_reset()` 并删除；N=S ∧ estop 未冻结且共享 frozen=false → 删除（已解冻请求作废）；N=S ∧ estop 未冻结且共享 frozen=true → **保留**（留给冻结中的 owner）；N>S → 保留 |
| `sync_local_with_shared_state`（新增） | `(estop) -> bool` | 本地 frozen ∧ 共享 frozen=false → 调 `estop.shared_sync_reset()` 并返回 True；否则返回 False |
| `LOCK_FILE` / `_dialog_alive` | 退役 | 单例判定不再使用（实现期删除调用；常量保留一个版本周期供排查） |

### estop

| 入口 | 签名 | 语义 |
|------|------|------|
| `shared_sync_reset`（新增） | `() -> None` | 冻结时复位并记审计（source="复位-共享同步"）；未冻结 no-op（含"复位请求-未冻结"审计，同 ISS-0002 约定） |

### httpd

| 入口 | 签名 | 语义 |
|------|------|------|
| `HttpDaemon.start`（行为变更） | `() -> None` | 端口被占用时显式抛 `RuntimeError`（信息含"已被占用"），禁止静默；正常路径行为不变 |
