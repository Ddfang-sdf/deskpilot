# ISS-0002：急停冻结后无法复位（状态在 daemon，复位通道旁落）

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0002 |
| 标题 | 急停触发后复位热键无效：冻结标志在 daemon 内存，复位热键被 stdio 代理抢占，且无 CLI/HTTP 备用复位通道 |
| 严重级 | 高（安全机制失效：急停只能冻、不能解，写操作长时间全拒） |
| 状态 | 已关闭（2026-08-21 验收通过：192 测试全绿；实盘甩角冻结 → F11 复位、--reset 复位双通道生效，瘦代理不再抢热键） |
| 提出 | 2026-08-20（A 机实盘：甩角冻结后 F11 复位无效，写操作被拒约 15 小时） |

## 1. 问题现状

1. **冻结正常触发，复位完全无效**：2026-08-20 08:22 鼠标甩角触发急停，此后所有写操作
   被强制层拒绝；人类多次按复位热键 Ctrl+Shift+F11 无任何效果，且无任何反馈线索。
2. **热键被错误的进程持有**：真正冻结的是常驻 daemon（PID 74144，持有 9420 端口，
   08-18 21:52 启动）；而复位热键被 08-20 22:33 启动的某个 stdio 瘦代理进程抢到——
   该代理自身未冻结，复位分支静默 no-op，复位信号永远到不了 daemon。
3. **人类没有任何备用复位手段**：设计承诺的"本地 CLI 命令复位"（INV-10）未落地，
   HTTP 服务只有 `GET /health` 与 `POST /call`，无复位端点。唯一出路是杀光全部
   deskpilot 进程重启 daemon（10 个进程 = 1 个 daemon + 3 个 stdio 会话共 4 对父子）。
4. **故障全程无痕可查**：复位 no-op 不记审计，无法从日志确认热键按没按、投递给了谁；
   daemon 启动时热键注册失败只有一条审计，不重试、不告警。
5. 时间线：08-18 21:52 daemon 启动（热键注册失败，审计 seq 2）→ 08-20 08:22 甩角冻结
   → 08-20 23:32 杀进程重启恢复（新 daemon 热键注册成功）。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **daemon 化只搬了状态，没搬复位通道** | ISS-0001 改造后真正生效的冻结标志在 daemon 进程内存（`deskpilot/estop.py:28`），stdio 代理的自有 EstopMonitor 形同虚设；但热键注册逻辑未随架构调整，状态与复位通道从此分家。旧单进程形态下"状态/热键/复位"天然同体，问题不暴露。 |
| R2 | **每个进程无条件抢全局互斥热键** | `deskpilot/main.py:121` 在所有启动路径（含只活几十秒的 stdio 代理）都启动 `_hotkey_loop` 注册 RegisterHotKey；该 API 全系统单持有者，谁先抢到归谁，daemon 启动稍晚即永久失去复位通道。 |
| R3 | **注册失败静默 return** | `main.py:58-60` 注册失败仅记一条审计即返回，不重试、不告警、不影响启动——daemon 从出生起就没有复位能力却照常服役。 |
| R4 | **复位 no-op 不记审计** | `estop.py:69-70` 未冻结时 `_reset` 直接 return，人类按热键的行为无痕，故障排查无据可依。 |
| R5 | **INV-10 承诺的 CLI 复位未落地** | `estop.py:43` 有 `cli_reset()` 方法，但全仓库唯一调用点是测试文件；无 `--reset` 命令行入口，HTTP 服务无复位端点——热键失灵即无出口。 |

## 3. 整改方案

### 3.1 总体

让复位通道重新对准状态所有者：热键归 daemon 独占（stdio 代理不抢），并补齐
热键之外的本地复位通道（HTTP 端点 + CLI 入口），兑现 INV-10；消除三处静默，
让"能不能复位"永远可查、可告警。

### 3.2 整改项

| 项 | 内容 |
|----|------|
| A | stdio 瘦代理启动时先探活 daemon（沿用 ISS-0001 探测逻辑）：daemon 在线则跳过热键注册与甩角轮询线程，消除抢锁（R1/R2 根因修复）；daemon 离线回退本地直跑时保持现状 |
| B | daemon 热键注册失败改为循环重试（间隔退避）+ 每次失败记审计 + stderr 显式告警，不许静默 return；长期失败应让运维可感知（R3） |
| C | 新增 `POST /estop/reset`（httpd，仅绑 127.0.0.1 不变）与 `deskpilot.exe --reset` CLI 入口（内部走该端点），兑现 INV-10 本地 CLI 复位（R5） |
| D | 复位 no-op 也记审计（`estop.py` `_reset` 未冻结分支记录"复位请求-未冻结"），热键按没按、送到了谁永远可查（R4） |

### 3.3 约束（fail-closed 保持）

- 复位通道仅限本机人类通道：HTTP 端点只绑 127.0.0.1，无鉴权设计不变（威胁模型 §0 不防作恶）
- 复位组合键永不进入任何按键许可表（INV 保持）
- 急停触发路径（热键/甩角）行为不变；stdio 代理跳过热键后，daemon 离线回退形态下代理仍须自注册，保证单进程形态复位能力不退化

## 4. 测试方案

### 4.1 单元

| 用例 | 断言 |
|------|------|
| 代理探活跳过热键 | daemon 在线时 stdio 装配不启动 _hotkey_loop（RegisterHotKey 未被调） |
| 注册失败重试 | RegisterHotKey 失败 → 按退避重试并逐次记审计，不静默 return |
| POST /estop/reset | 冻结态 → 复位成功并记审计；未冻结 → 返回未冻结并记审计 |
| --reset CLI | daemon 在线 → 经 HTTP 复位；离线 → 明确错误（不静默） |
| 复位 no-op 审计 | 未冻结时调用复位 → 审计含"复位请求-未冻结"记录 |

### 4.2 集成验收

- 全量 pytest 绿（现有 161 + 新增）
- 实盘：daemon 运行中拉起 stdio 代理 → daemon 审计无"热键注册失败"（代理不抢）→
  甩角冻结 → Ctrl+Shift+F11 复位生效（审计出现"急停复位"）→ 再冻结，用
  `deskpilot.exe --reset` 复位生效 → 全链路审计完整可查
