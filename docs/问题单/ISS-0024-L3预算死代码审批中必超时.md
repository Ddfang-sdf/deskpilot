# ISS-0024：L3 预算分支死代码——审批挂起中必 TOOL_TIMEOUT

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0024 |
| 标题 | 审批 90s 人裁决期间,外层 30s 预算先到期报 TOOL_TIMEOUT——"报错但动作已执行"真实存在(可靠性撒谎);L3 预算分支(approval_ttl+5)从未可达 |
| 严重级 | **高**（一致性:系统说失败≠真失败;AI 会重复发起→重复弹框,或误判任务烂尾) |
| 状态 | **建单,待评审** |
| 提出 | 2026-09-04(实盘 L3 Escape 测试 TOOL_TIMEOUT 取证 + 静态证据) |

## 1. 问题现状(大白话影响面)

1. **审批框还在,AI 已判死**:AI 发危险操作→弹框等你裁决(90s)。
   但 30s 一到,外层预算先到期,AI 收到 TOOL_TIMEOUT"处理中,请稍后
   重试"。你批准后操作照常执行——**AI 账本与真实世界分裂**。
2. **三种糟糕剧情**:①你批准且执行了,AI 不知道,重发→再弹框;
   ②AI 以为没干成,放弃后续步骤,任务烂尾;③恰好构成"报错但已执行"
   的真实版——上次外部误报证伪了,这次是真的(方向相反:安全闸完好,
   可靠性撒谎)。
3. **触发概率**:人审读描述+看图+思考超 30s 即中招。负责任审批本就
   该想这么久——长任务流几乎必踩(2026-09-03 实盘 L3 Escape 测试
   TOOL_TIMEOUT 即此因;当时仅见现象)。

## 2. 根因分析(带实证)

| # | 根因 | 实证 |
|---|------|------|
| R1 | `TOOL_LEVELS` 无任何 L3 成员(models.py:18-29),httpd._call_with_budget 的 `level=="L3"` 分支(httpd.py:125-127)永不可达 | 静态枚举:24+1 工具全部 L0/L1/L2 |
| R2 | 动态升级(eff→L3)发生在强制层内部,外层预算包装器看不到 | enforcement.py:130/143/214 三处 `eff = L3`(终端绑定/启动终端/危险键)均发生在 call_tool 深处,httpd 只能查静态表 |

## 3. 整改方案

| 项 | 内容 |
|----|------|
| A | **预算决议单源化**:新增纯函数 `resolve_budget(level, policy)`(models 或 httpd 模块级):`level=="L3"` 或 `level=="L2"(可升级写工具)` → `policy.approval_ttl + 5`;否则查 `TOOL_TIME_BUDGETS`。httpd._call_with_budget 改调此函数 |
| B | **判定依据**:全部 L2 写工具都可能动态升级(终端绑定/危险键/启动终端),其预算一律 approval_ttl+5——宁可慢报"挂起"(95s),不可审批中被误杀(30s)。精确预测升级需在 httpd 复制强制层规则,**违反单源原则,否决** |
| C | 挂起感知不回归:ISS-0009 进度报告(5s 间隔)照常,95s 超时才报 TOOL_TIMEOUT 的观感由进度通知兜底 |

### 约束

- L0/L1 预算不变(无升级路径);非写工具不变;
- 不得在 httpd 复制升级判定逻辑(单源铁律);
- 审批自身 ttl(90s)与其 APPROVAL_TIMEOUT 语义不动——本单只修外层预算与内层审批的赛跑。

## 4. 测试设计(五要素)

层级:单元(预算决议纯函数)+ 集成(真 daemon+慢审批通道,35s 实测)。

| 用例 | 场景 | 前提 | 步骤 | 预期结果 | 断言代码 |
|------|------|------|------|----------|----------|
| TC-BT-01 | L2 写工具预算=approval_ttl+5(单元) | policy(approval_ttl=90) | `resolve_budget("L2", policy)` | 返回 95.0 | 返回值直出 |
| TC-BT-02 | L0 不变(单元) | 同上 | `resolve_budget("L0", policy)` | 返回 5.0 | 返回值直出 |
| TC-BT-03 | L1 不变(单元) | 同上 | `resolve_budget("L1", policy)` | 返回 15.0 | 返回值直出 |
| TC-BT-04 | **审批 35s 完成不超时**(集成,判别性) | 真 daemon(port=0);FakeClock 注入审批(ttl 只走 1s);审批通道 sleep 35s 后 approve;绑定窗发 alt+f4 | HTTP POST /call key | **HTTP 200 且 result=ok**(旧预算 30s 必 TOOL_TIMEOUT,新预算 95s 通过——判别性) | 响应体 ok 字段直出 |
| TC-BT-05 | 审批超时仍走 APPROVAL_TIMEOUT(集成回归) | 同上但通道 sleep 到 ttl 到期(假钟推进 90s)后 timeout | /call key | `APPROVAL_TIMEOUT` 语义不变 | 响应体 error_code 直出 |

装配守门:R1 真替矩阵(TC-BT-04/05 真 daemon+真 HTTP+真强制层,仅
审批通道为 sleep 接缝——channel 本就设计注入缝,不 mock 产品函数);
R2 单元层纯函数零打桩;R3 响应体形态断言;R4 无持久化路径变迁;
R5 终效应=HTTP 响应体(35s 实测,判别新旧预算)。
