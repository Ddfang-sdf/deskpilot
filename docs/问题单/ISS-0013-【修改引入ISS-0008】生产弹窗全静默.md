## 1. 问题现状

1. **接线遗漏（根因点）**：`dialog_service.py:25` `self._factory = window_factory`，
   生产装配默认 `window_factory=None` → `_factory` 为 None；`_dispatch`
   （`:79`）调用 `None(kind, payload)` 抛 TypeError，被"弹窗异常不波及调用方"
   的 except **静默吞掉** → 窗口永不出现，无任何留痕。`_default_factory`
   方法存在但**从未被接线**。
2. **实盘实证链（2026-08-31 全程取证）**：
   - daemon 发起 `launch_app calc.exe`（入白审批）→ 60s 超时；desc 文件写出、
     **result 文件从未产生**（窗口从未运行倒计时）；
   - 常规 L3 审批（绑定记事本后发 alt+f4）同样无窗超时——**非入白特有**；
   - 截图实证：屏幕无任何弹窗；UIA 枚举顶层窗口无 DeskPilot 窗口；
   - 主线程直调 `_default_factory` 建窗成功、geometry 轨迹正常
     （480x216@(1424,752)）——**只有服务线程路径是死的**，排除建窗代码本身。
3. **历史实证**：2026-08-29 18:34 甩角冻结（estop-state.json seq 27）无任何
   冻结感知窗弹出，遗留冻结状态两天、用户不知如何复位——与本根因完全吻合。
4. **影响版本与形态**：ISS-0008（bb20c6b）起全部构建，**含已发布的
   v0.3.0 / v0.3.1**；daemon 与 stdio 全中（TkApprovalChannel / FreezeNotifier
   只要持有 dialog_service 就走线程路径，子进程弹窗路径被跳过）。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **装配接线遗漏** | `__init__` 未将 `_default_factory` 设为缺省（缺 `or self._default_factory`）；默认路径 `_factory=None`。 |
| R2 | **静默吞异常零观测** | `_dispatch` 的容错 except 吞掉 TypeError，无审计无 stderr——通知层故障完全隐形。 |
| R3 | **测试结构盲区** | 全部单测经 `window_factory` 注入替身，真实默认路径（None→_default_factory）零覆盖；ISS-0008 实盘验收以 /health 延迟为代理证据，**未目视弹窗**。 |

## 3. 经验总结（修改引入复盘与预防）

### 3.1 为什么会被修改引入

1. **优化改变了执行路径，验收却沿用旧假设**：P6 把"子进程弹窗"改为"线程弹窗"，
   新增了一条**只在生产出现的装配分支**（默认工厂）；测试矩阵没有为新分支
   补用例——改了路径，没改验收。
2. **注入点即盲区**：`window_factory` 是为测试留的后门，测试全走后门，
   正门（默认 None）无人走。**凡"可注入"的装配，默认装配必须有用例守正门。**
3. **静默设计放大后果**：通知层"异常不波及调用方"本身是合理容错，
   但没有最低限度留痕，容错就变成了隐形故障。
4. **实盘验收缺"目视"硬标准**：以间接指标（/health 延迟）替代直接证据
   （弹窗出现在屏幕上），代理证据通过时真实目标已失效。

### 3.2 避免再犯的硬规则（纳入工作纪律）

1. **默认装配守门用例**：任何可注入的装配参数（工厂/通道/策略源），至少一条
   用例以**生产默认值**构造并断言真实触达（替身只允许替换最末端可观察点）。
2. **改路径必改验收清单**：变更执行路径的优化单，测试设计必须含
   "新路径端到端可见性"用例；对 UI，**窗口出现为一级断言**
   （截图或窗口枚举为证据）。
3. **静默容错必须留痕**：吞异常处至少写一条审计事件或 stderr；
   "吞错不留痕"视同静默降级，禁止。
4. **实盘验收目视条款**：凡涉及"人类可见"的功能，验收标准必须包含
   目视/截图确认步骤，禁止只用间接指标。

## 4. 整改方案

| 项 | 内容 |
|----|------|
| A | **接线修复**：`__init__` 改 `self._factory = window_factory or self._default_factory`（单行；注入路径行为不变）。 |
| B | **吞错留痕**：`_dispatch` 的 except 增加 stderr 打印（容错不阻断调用方的语义不变；故障不再隐形）。 |
| C | **守门用例**：默认构造 DialogService → show() 必须触达 `_default_factory`；注入路径不回退；吞错必有 stderr（§5.1）。 |
| D | **版本声明**：v0.3.0/v0.3.1 标记受本缺陷影响；修复随 v0.3.2 发布并在发布说明中显式声明。 |

### 4.1 约束

- 仅接线与留痕两行级改动，不动弹窗协议/线程模型（最小回归面）。
- 修复后接续完成 ISS-0012 §4.2 的弹窗与撤回手工验收（同一实盘场景）。
