## 1. 根因（实证链）

**机制层**：详细设计的 §5 接口视图（工具契约）**精确到参数/返回/前置/后置/错误**，有 `5.2 条目形态（统一键集）` 这样逐键钉死的表格；但 §3 逻辑视图自述为「**契约级**」（`:74` 标题原文），其表格的"语义"列只写到**概念名与分支序号**就停止，没有对应的"返回形态"行。于是同一份文档里两种交付粒度并存：**对外接口钉到键名，对内纯函数只到概念名**。

**触发条件**：测试设计的断言列必须由设计文档直接翻译而来（五要素第五项）。翻译「返回结论字段直出」需要三个信息：**哪个字段**、**该字段取什么值**、**诊断要素挂在哪个键下**——三者都缺。

**为什么未在评审中暴露**：§13 第 4 条接缝（`:557`）写「四分支直出断言，断言值取自**返回结论字段**」——这句话在评审时读起来是"设计已交代"，**实际它是把缺口指回自己**：`结论字段` 是一个尚未被命名的东西。

**为什么是"设计引入"而非"实现缺陷"**：本单代码实现为零（全库 `grep detector_factory|to_virtual|to_image|screened|verify_weights` 皆空），缺口存在于文档自身。与 ISS-0076/0077/0078 **同源**——那三单的机制层结论均为「设计文档写到概念层、未回流到形态层」，本单是同一根因在新需求上的第五次出现。

## 2. 四处缺口（逐点实证）

### 2.1 缺口① `WeightVerifier.verify()` 的四分支结论无字段名 —— 最硬

| 位置 | 原文 |
|------|------|
| 详细设计 `:102` | `\|`verify(目录, 清单)` → 四分支结论 \| ①目录不存在 ②目录存在但清单内文件缺失 ③文件齐备但某文件哈希不符 ④全部相符。①②③ 各携带**完整诊断要素**(目录绝对路径、缺失文件名清单 / 实际哈希与期望哈希对照);④ 无附带信息 \|` |
| 详细设计 `:557`（§13 接缝 4） | `\| 4 \| **权重校验纯函数** \| 目录缺失/文件缺失/哈希不符/哈希相符 四分支直出断言,**断言值取自返回结论字段** \|` |
| 测试设计 `:75`~`:78` | `TC-WVER-01~04` 的断言列**均**为「返回结论字段直出」 |

`grep -n "结论字段\|conclusion\|verdict" docs/` → **仅命中测试设计自己的这 4 行**（加上 §13:557 的引用），**无任何定义处**。「携带完整诊断要素」的具体键名（缺失文件名挂在哪个键、哈希对照是 dict 还是字符串）同样未钉。

**影响面**：`TC-WVER-01/02/03/04` 计 4 条**直接无法落地**；`TC-DET-03a/03b`（Executor 侧归约须"含缺失文件名与目录绝对路径"）、`TC-DET-08`（校验失败类不记忆化）、`TC-GOV-04`（五条 message 均含下一步）以其为前提。

**为什么是本单最硬的一处**：测试设计 §4 的 **R7 闸门**（`:197`）明文规定——

> TC-WVER-01~03 的三分支结论必须经由返回值区分,不得靠"都抛异常"通过。

这是防「`raise` 借道假绿」的正式防线（本单前一工单 ISS-0081 正是靠这条抓出 `test_stale_id_refused_when_element_gone` 的假红）。字段名一旦猜错，三条结论在断言上**分不开**，R7 这条防线名存实亡——**它现在建立在一个未命名的东西上**。

### 2.2 缺口② `to_image()` 在详细设计中零出现，却承担坐标契约的唯一证伪

| 位置 | 原文 |
|------|------|
| 测试设计 `:68` | `\| TC-COORD-01c \| 反向成对 \| 同上 \| `to_image([110,120,140,150], (100,100))`;再 `to_image(to_virtual(r,o),o)` \| 前者 `[10,20,40,50]`;往返恒等 \| 返回值直出 \|` |
| 详细设计 `:106`~`:113`（§3.5） | 只定义 `to_virtual(rect, 原点)`；**无 `to_image`** |
| 详细设计 `:428`~`:430`（§9.4 说明） | 「`_draw` 画框前需要把虚拟屏 rect 转回**图内相对坐标**——这是**反向**平移,同属收口模块提供的**成对函数**」 |

`grep -n "to_image" docs/ --include=*.md` → **全仓仅 1 命中，即测试设计 `:68` 自己**。设计**意图**有反向函数（§9.4 明写"成对函数"），**名字**只活在测试设计里——测试设计替详细设计发明了一个公开函数名。

**影响面**：`TC-COORD-01c` 计 1 条。但**它不可省**：详细设计 §4 末段（`:155`~`:157`）自陈——

> 本条是对侦察章程 §8.2 教训的正面回应:同一概念两种矩形格式并存必然出错,且**混用不报错、静默给 0**——属静默降级。本设计把转换收在单点,并由 §13 第 1 条接缝以"截图原点非零"用例直出证伪。

即：**这条用例是"静默给 0"这个已犯过的错的唯一防线**。函数名猜错 ⇒ 防线落在不存在的入口上。

### 2.3 缺口③ `WeightDirResolver.resolve()` 的形参名与配置键名未钉

| 位置 | 原文 |
|------|------|
| 详细设计 `:95` | `\|`resolve(配置项)` → 绝对路径 \| 绝对路径原样;冻结形态锚定到可执行文件所在目录;…(\*\*与 `resolve_audit_dir` 同规矩\*\*) \|` |
| 详细设计 `:407`（§9.3 图） | `A[配置项字符串] --> B{是绝对路径?}` |
| 测试设计 `:79`~`:83` | `TC-WDIR-01~05` 步骤列**均**写 `resolve()`，无实参 |

「配置项」是概念名，不是形参名；`policy.yml` 里该键叫什么（§4`:141` 只写「不吃配置的审计目录」）同样未钉。

**影响面**：`TC-WDIR-01~05` 计 5 条。其中 **`:83` `TC-WDIR-05` 步骤列明写「解析权重目录」、断言列明写「返回值**+调用形参**直出」**——断言**指名要断言形参**，而形参名未定，这条断言写不出来。且测试设计 §4 `:198`（R8）另要求「断言须对场景**真实触发**…确证其确由该分支生效」，与形参名直接相关。

**佐证**：同项目已有先例 `deskpilot/audit_paths.py` 的 `resolve_audit_dir(configured, policy_path=None)` ——「与同规矩」的设计意图指向一个**已知**形参面，本单只是没把它写下来。

### 2.4 缺口④（连带）检测候选项的形态未钉到键级

| 位置 | 原文 |
|------|------|
| 详细设计 `:66`（§2 检测器契约） | `\| 输出 \| 候选区域清单:每条为**图像坐标** `[l,t,r,b]` + 置信度浮点(0~1) \|` |
| 测试设计 `:74` | `\| TC-DEDUP-06 \| 门槛过滤与边界 \| 门槛 0.5 \| 候选置信度 0.49 / 0.5 / 0.51 同批 \| 0.49 丢弃;0.5 与 0.51 保留(< 门槛才丢弃) \| 返回集合 **id** 直出 \|` |

未钉三项：①候选**是否携带 id**；②置信度的键名（`confidence` / `score` / 无键的位置元组）；③候选容器类型（list of list / list of dict / dataclass）。而 `:74` 的断言列**指名 `id`**，`:118`（§3.6）又要求 `screened()` 同时接受候选集合与「置信度」——两处都停在概念名。

**影响面**：`TC-DEDUP-06` 计 1 条**断言无出处**（铁律 3）；`TC-DEDUP-01~05` 的「返回集合长度/含该候选」为**不计名**断言，**不受阻**。

### 4.1 具体提案（每处给候选形态＋仓库先例，供评审直接落笔或推翻）

**提案①的体例基准**：详细设计 §5.2「条目形态（统一键集）」已是本文件逐键钉死的成功先例（键名/取值域/"不省略"三条齐备）；`deskpilot/executor/core.py:292` 的 `{"found": False, "best_confidence": 0.0, "matches": []}` 是"结论＋诊断要素同字典"的现成仓库先例。据此提案：

| 缺口 | 提案形态 | 仓库先例 | 需评审裁定的点 |
|------|---------|---------|--------------|
| ① `verify()` | 返回单字典：`conclusion`（四分支判别键，取值域 `dir_missing`/`file_missing`/`hash_mismatch`/`ok`）＋ 诊断键 `dir`（绝对路径，恒有）、`missing`（缺失文件名清单，仅分支②）、`mismatched`（逐文件「实际 vs 期望」对照，仅分支③） | `core.py:292` 结论＋附加键同字典；`policy.py` 用下划线小写键 | 判别键取**字符串枚举**还是**整数/布尔组合**——字符串枚举**更可读且 R7 断言直接**（`:197` 要求三结论"经由返回值区分"，字符串比对即可，无需映射表）；`mismatched` 是 `list[dict]` 还是 `dict[rel → {expected, actual}]` |
| ② `to_image()` | `to_image(rect, 原点)` → 图像坐标 rect，逐分量**减**（`l-ox, t-oy, r-ox, b-oy`），与 `to_virtual` 严格成对、同签名同顺序 | §3.5 `to_virtual(rect, 原点)` 原样镜像；`to_image(to_virtual(r,o),o)` 往返恒等即测试设计 `:68` 的断言 | 函数名是否就叫 `to_image`（测试设计 `:68` 已用此名；若要改名，测试设计同步改，两文档**必须同名**） |
| ③ `resolve()` | `resolve(configured, policy_path=None)` → `Path`，逐分支与 `resolve_audit_dir` **完全同构**（绝对原样／冻结锚 exe 目录／有 policy_path 锚其目录／否则 cwd） | **`deskpilot/audit_paths.py:13` 现成实现**：`resolve_audit_dir(configured: str, policy_path: str | None = None) -> Path`——形参名、类型、缺省值、四条分支顺序可**逐字照搬** | `policy.yml` 中权重目录的**配置键名**（实测 `policy.yml` 为**扁平顶层键**，`:97 audit_dir: ./audit` 与 `whitelist`/`terminal_apps`/`keys`/`timeouts`/`limits`/`estop`/`cleanup` 同级，**无分节**）——需新定一个顶层键名，建议 `detector_weights_dir`；这是唯一需要**新造**的名字，其余可照搬 |
| ④ 候选形态 | `{"rect": [l,t,r,b], "confidence": float}`（图像坐标）；**检测器不产出 `id`** | §2 契约已写"每条为图像坐标 `[l,t,r,b]` ＋ 置信度浮点"——补键名即可，形态不动；`core.py:309` 已有 `"confidence"` 键名先例 | **`TC-DEDUP-06` 的断言应改**：它现写"返回集合 **id** 直出"，但 §9.6 明定"编号 1..N 由 Executor 侧按坐标序决定"、§2 明定检测器输出"**顺序不承诺**"——**编号权归 Executor，检测器产出 `id` 会与 §9.6 冲突**。故这处宜改断言（改为按 `rect` 或 `confidence` 判保留/丢弃），**不宜**给候选加 `id`。这属"测试设计写错"而非"设计缺字段"，与 ①②③ 性质不同，须一并裁定 |

**提案对红集的影响**：若按上表落笔，缺口④的处置使 `TC-DEDUP-06` 从"受阻"变为"测试设计需修正"（1 条），故**受阻数由 11 条降为 10 条、另 1 条转"测试设计修正"**；`TC-DEDUP-01~05` 本就断言"返回集合长度/含该候选"，不受影响。

## 5. 约束

- 本单**只补文档，零代码**；REQ-003 全部实现仍须走 SDD P1 红→P2 核对→P3 绿，本单不构成"实现许可"（铁律 1）；
- 补钉**不得改变**已冻结的任何口径——分支判定顺序（§9.2 目录→存在→哈希）、去重闭区间（§3.6）、锚定规矩（§3.3 与 `resolve_audit_dir` 同构）、编号整表替换（§9.6）逐条原样；
- 补钉后须**重跑 R6 双向映射**（§0 `:17`~`:19` 已把 TC-WVER/TC-WDIR 映射到 DET-02/DET-03），确认新增形态不产生孤儿断言；
- 与 ISS-0076/0077/0078 **同源同批**（根因均为"设计文档停在概念层、未回流形态层"），建议同批复核，但**单独立项**——修复动作（三节补表）与验收对象（11 条用例可落地）不同；
- 本单与 `ISS-0081` 的 FD-05 口径**无耦合**：整表替换属行为契约（已钉），本单属返回字段契约（未钉）。

### 7.2 【真设计层面】`screened` 的 UIA 集合范围未定 —— 已补钉，请复核

**这是本单唯一需要 sdfang 过目的一处**：它改变行为（哪些候选进编号空间），不是命名。

**证据链**：

| 位置 | 原文 |
|------|------|
| 需求 SOM-05（`REQ-003-…md:95`） | `检测区域与 **UIA 元素**重叠时以 UIA 优先`（未限定元素类型） |
| 详细设计 §3.6（原 `:118`） | `screened(候选集合, **UIA矩形集合**, 门槛)` ——「UIA矩形集合」**未限定范围** |
| 详细设计 §6 装配流（`:221`） | `_element_root(hwnd) → _iter_summaries **过滤 enabled+非零面积**` |
| 实装 `executor/core.py:320-327` | 编号空间的来源正是该过滤后的集合：`if not s["enabled"]: continue` / `if rect[2]-rect[0] <= 0 or rect[3]-rect[1] <= 0: continue` |
| 测试设计 TC-DEDUP-01~06 | 六条**全用普通矩形**，**无一条**覆盖 `enabled` / 零面积维度 |

**机制层**：去重判据用的集合与"什么会被标号"的集合若不统一，会出现两类错配。设检测候选 c 的中心点落在某 UIA 元素 e 的 rect 内，而 e 属于**禁用**或**零面积**：

- **若 `screened` 收全量 UIA 矩形** → c 被判为"重叠"而丢弃。但 e 因被过滤而**不进编号空间**，`som_id` 也寻址不到它。结果：该处视觉目标**既无 UIA 编号、又无检测框**——AI 彻底失去这个落点，而检测通道本可以补位。
- **若 `screened` 收与编号集合同源的过滤后集合**（本设计取此） → c 保留并进入编号空间，`source="detect"`。代价是该处点击可能无效（元素禁用）——但这是**界面事实**，且 `source` 字段已标明它不走精确通道，不构成误导。

**取同源的理由（可陈述）**：SOM-05 的目的原文是"**同一视觉目标不重复标号**"——判据对象是"会被标号的元素"，故判据集合必须与编号集合同源；§1「检测是 UIA 的**补充**」也是同一方向：UIA 通道管不到的地方，正是检测通道该补的位。

**补钉落点**：详细设计 §3.6 增「**UIA矩形集合的范围**」一行，明定"是 `_iter_summaries` 摘要流经**同一条过滤**后的集合——即与编号空间**同源同集**……**不是**控件树全量矩形"，并写明理由与代价认账。

**测试维度补齐**：新增 **TC-SOM-09**（单元，55 用例中的第 47 条单元用例）：替身 UIA 流含 `A` 可交互 / `B` 禁用 / `C` 零面积三类，检测替身给 a/b/c 三条候选，断言只有 A 进编号空间、**a 被去重而 b/c 保留**。R7 同步补失效原因核对：该条的"保留"必须由"该 UIA 元素未进编号空间"引起，**不得借置信度不达标或坐标越界借道**（三条候选置信度须同档达标）。

**为什么上报**：它改的是「**行为是什么**」——决定 AI 能否拿到一个原本拿不到的落点，影响系统表现（覆盖面）。按界线属右栏。**若 sdfang 认为应取全量**（即"UIA 元素无论可否交互都参与去重"），改法仅为 `screened` 调用点的入参集合，单点可换，不动编排（FD-04）。
