# ISS-0031：审计数据保留策略——日志 90 天 / 截图 90 天+450MB 分档治理

| 项 | 内容 |
|----|------|
| 问题单号 | ISS-0031 |
| 标题 | 审计 JSONL 无保留策略无上限累积(6 天 106KB 实证,年增百 MB 级);sdfang 裁定:日志 90 天、截图 90 天+450MB(合计≤500MB),分档治理 |
| 严重级 | **低**（磁盘治理;与 ISS-0010 截图双阈值原则一致化） |
| 状态 | **实现完成,487 用例全绿,待实盘验收**(2026-09-04) |
| 提出 | 2026-09-04（sdfang 询问审计磁盘泄露,裁定阈值与分档方案） |

## 1. 问题现状

1. **日志无治理**：janitor 清理范围仅 shots/+approval/（janitor.py:64-68 实证），
   `audit/logs/audit-*.jsonl` 只增不减——活跃使用 ≈0.4MB/天、年增百 MB 级。
2. **阈值与用途错配**：截图默认 14 天/2GB——年龄对证据审查偏短、容量
   对磁盘治理偏松;治理原则与用户期望(3 个月/500MB)不一致。

## 2. 根因分析

| # | 根因 | 说明 |
|---|------|------|
| R1 | **日志从未纳入清理面** | ISS-0010 立项范围只覆盖体积大的截图,日志体积小被忽略 |
| R2 | **阈值未按证据价值/磁盘预算校准** | 14 天/2GB 是立项初值,未按"审计证据三个月审查窗口"校准 |

## 3. 整改方案（sdfang 裁定）

| 项 | 内容 |
|----|------|
| A | **分档治理**：`logs/` 仅按年龄 90 天清理（体积极小,不设容量档）;`shots/` 双阈值 90 天 + 450MB（471859200 字节）——合计占用 ≤500MB 口径 |
| B | **策略显式化**：policy.yml 增 cleanup 节:`logs_max_age_days: 90`、`shots_max_age_days: 90`、`shots_max_bytes: 471859200`;policy.py 默认值同步（DEFAULT_SHOTS_MAX_AGE_DAYS 14→90、DEFAULT_SHOTS_MAX_BYTES 2GB→450MB、新增 DEFAULT_LOGS_MAX_AGE_DAYS=90） |
| C | **janitor 扩面**：`run_janitor(audit_dir, now, logs_max_age_s, shots_max_age_s, shots_max_bytes, grace_s, audit_log)`——日志采集自新增 `AuditPaths.logs`(root/logs 下 *.jsonl),按龄删除,事件「审计日志清理」;截图路径与事件「截图清理」不变;stats 增 logs_deleted/shots_deleted（deleted 总数保持兼容） |
| D | 装配同步:main._start_janitor 传新参;dist 策略同步;INSTALL.md §5 示例补 cleanup 节 |

### 约束

- **容量先于时长**（任一阈值先触发即清理,容量为硬顶）——文档写明;
- 日志仅年龄档:90 天内的日志**绝不被截图挤兑**（分档隔离);
- 清理范围仅 logs/ 与 shots/（含 client 子目录）;审计根目录的
  estop-state.json/daemon.version 等状态文件永不入清理面;
- 当天日志文件受 90 天年龄自然豁免,无需额外 grace;截图 grace
  （在场保护）沿用 ISS-0010 语义不变。
