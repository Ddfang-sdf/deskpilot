### 1.2 实现侧:零转换

`grep -n "ClientToScreen|ScreenToClient" deskpilot/executor/desktop_icons.py` → **零命中**。

`desktop_icons.py:141` `graphic_rects(hwnd, indices)` 的取值链:

```
virtual_alloc + write_mem + send_itemrect(LVIR_ICON)   # 向 ListView 发 LVM_GETITEMRECT
  → 返回 [back.left, back.top, back.right, back.bottom] # 直接透传,未做任何原点平移
```

`LVM_GETITEMRECT` 返回的是 **client 坐标**。该值被原样写入 `graphic_rect`,再被 `DesktopIconAssembler` 与 UIA 侧的 `BoundingRectangle`(**屏幕/虚拟桌面坐标**,`_iter_summaries` 路径)归并到同一条目——**两路坐标基准不同却未对齐**。

### 1.3 本机实测:今天成立,靠巧合

| 探针 | 实测值 |
|------|--------|
| 虚拟屏原点 | `(0, -1)` |
| 桌面 ListView `GetWindowRect` | `(0, -1, 3840, 1080)` |
| `ClientToScreen(hwnd, (0,0))` | `(0, -1)` |

即:桌面 ListView 的可视原点**恰好等于虚拟屏原点**,故 client 坐标 == 虚拟桌面坐标。**这是环境巧合,不是代码保证**——ListView 左边缘一旦不在虚拟原点(任务栏移至左侧、多屏主副调换、桌面视图层加边距),`graphic_rect` 立即整体偏移,而:

- 无任何断言会红(见 §1.4);
- 错误 rect 会静默流入 AI 的抓点/落点计算,表现为"点偏了",归因困难。

### 1.4 用例侧:零原点断言

`tests/test_desktop_icons_req02.py` 全量检索 `virtual|坐标系|ClientToScreen` → 仅命中替身类的 `virtual_alloc`/`virtual_free`(内存分配 API,与坐标系无关)。`graphic_rect` 相关断言(`:337` 起)只核**相对图形抽验**,无一处断言 rect 的坐标基准。

`tests/test_iconsmerge_iss54.py` 的 `graphic_rect` 全部是硬编码常量(`G_A`/`G_B`),坐标系无关。

## 3. 整改方向(待评审)

| # | 方向 | 说明 |
|---|------|------|
| ①(倾向) | **实现侧补显式转换**:`graphic_rects` 返回值经 `ClientToScreen(hwnd, pt)` 平移为屏幕坐标后再入条目;配一条用例断言"替身 ListView 原点非 (0,0) 时,返回 rect 已平移"(直出可断言) | 把巧合变成契约;与 UIA 侧基准对齐 |
| ② | **反过来收紧需求**:如果实测确认 ListView 恒在虚拟原点(需给出机制级理由:explorer 桌面窗口的定位规则),则改文档措辞为"client 坐标,当且仅当桌面 ListView 位于虚拟原点时等于虚拟桌面坐标",并补一条守卫用例(前提断言) | 不改代码,但把隐含前提显式化;需先证"恒在原点" |
| ③ | 保持现状 + 只在文档加注"已知巧合" | **不倾向**:无断言 = 无守卫,违反"断言必须有出处" |

**方向选择取决于一件事**:桌面 ListView 的可视原点是否**恒**等于虚拟屏原点。这需要实测取证(多显示器 + 任务栏移位的组合),不能推。

### 约束

- 改动须 fail-closed:坐标转换失败(句柄失效)→ 显式报错,不得回退到未转换值;
- 若走方向 ①,须同步 REQ-002 详细设计的条目形态描述(改行为必改文档);
- 测试设计(五要素)评审后产出,核心用例:**替身 ListView 原点取非 (0,0) → 返回 rect 已平移到屏幕坐标**(直出断言);**句柄失效 → 显式报错**。
