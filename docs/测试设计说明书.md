## 1. 引言

### 1.1 编写目的

本文给出 DeskPilot 从**正常功能**到**异常场景**再到**安全场景**的完整测试设计，作为 M1–M3 测试实现、执行与验收的直接依据。核心目标：每条安全不变量（INV-1～INV-10）都有可执行、可判定、可自动化断言的用例；每条异常路径都有明确预期行为——**不允许出现"没测过的拒绝分支"**。

### 1.2 测试范围

| 范围内 | 范围外 |
|--------|--------|
| 全部 22 个工具的功能、异常、安全用例 | OCR 引擎本身的识别率（第三方组件质量） |
| 四道闸、绑定、审批、审计、急停、策略机制 | 浏览器自动化（非目标） |
| 并发与竞态、服务生命周期 | UAC/锁屏等安全桌面的可达性（OS 限制，仅验证显式失败） |
| M1–M3 端到端验收场景 | 性能压测（仅做目标值抽检，见第 7 章） |

### 1.3 术语

| 术语 | 含义 |
|------|------|
| 测试固件 | 测试辅助程序：自动启动/关闭带 `DESKPILOT_TEST_` 前缀标题的记事本窗口 |
| 模拟审批器 | M1 阶段替代真人弹窗的测试组件，可程序化地批准/拒绝/不响应 |
| P0 / P1 / P2 | 用例优先级：P0 安全与阻断级（必须全过）；P1 主流程；P2 边界与次要 |
| 单测 / 集成 / E2E / 评审 | 测试级别：单元测试 / 真实桌面集成 / 端到端 / 静态代码评审 |
| TC-N / TC-E / TC-S / TC-P | 用例类别：正常功能 / 异常场景 / 安全场景 / 性能 |

## 2. 测试策略与环境

### 2.1 测试级别与方法

| 级别 | 对象 | 方法（沿用总体设计 §6） |
|------|------|--------------------------|
| 单测 | 强制层（★重点）、binding、approval、policy、audit | mock 执行层与审批通道，纯单元测试，逐条 INV 对应用例 |
| 集成 | L0/L1 工具、审计落盘、急停监听 | 对真实桌面执行（无副作用） |
| E2E | L2 工具、里程碑验收场景 | 只对测试固件窗口操作，绝不碰已存在窗口 |
| 评审 | INV-5 输入路径、INV-8 MCP 层、审批弹窗控件 | 代码评审逐条核对，产出评审记录 |

### 2.2 测试环境

| 项 | 约定 |
|----|------|
| 测试固件 | 自动启动标题含 `DESKPILOT_TEST_` 前缀的记事本，预置已知文本内容；用例结束自动关闭且不保存 |
| 测试策略文件 | 独立 policy.test.yml：白名单仅含 notepad.exe 等测试进程；terminal_apps 含 cmd.exe（供 L3 场景）；audit_dir 指向隔离测试目录；limits / estop 节可按用例覆盖默认值 |
| 审批通道 | M1 用模拟审批器（可编程：批准/拒绝/超时三态）；M3 增补真人弹窗手测 |
| 测试时钟 | 单测使用可注入的测试时钟（mock 时间），用于超时/过期场景，避免真实等待 |
| 超时参数 | 测试策略可将 approval_ttl 调短（如 2 秒）以加速审批超时用例 |
| 桌面基线 | 单显示器、DPI 100% 为基线；多显示器/DPI 见附录 B 待评审项 |
| 隔离要求 | 测试期间桌面不得有其他同名测试窗口；审计测试目录用例间可清空 |

### 2.3 测试数据

| 数据 | 内容 |
|------|------|
| 文本样例 | 纯 ASCII 串；中英文混合串（含标点与换行）；边界长度串（恰为、超过 input_max_chars，默认 65536） |
| 图像样例 | 已知图标的模板图（命中与不命中两组）；含中英文的截图样张 |
| 按键样例 | L2 许可键全集、L3 危险键全集、未收录键样例、别名变形样例（Return/Enter、大小写）、场景受限键（Backspace）、复位组合键（Ctrl+Shift+F11） |

### 2.4 用例编号与优先级

编号规则：`TC-<类别>-<对象>-<序号>`，类别 ∈ {N 正常, E 异常, S 安全, P 性能}。每条用例标注：优先级、测试级别、追溯（F-* 功能编号 / INV-* 不变量）。

### 2.5 通过/失败与暂停/恢复准则

| 准则 | 内容 |
|------|------|
| 里程碑准出 | P0 用例 100% 通过；P1 用例 100% 通过或经评审豁免；P2 缺陷记录留档 |
| 暂停准则 | 任一 P0 用例失败 → 暂停全部测试，缺陷修复并回归通过后恢复 |
| 拒绝分支覆盖 | 详细设计附录 A 每个错误码至少有一条用例触发——少一条即视为测试设计不完整 |

### 2.6 断言书写约定

断言是把"预期结果"翻译成可执行判定式。本文统一以下观测对象（测试侧通道，与被测服务解耦）：

| 观测对象 | 含义 | 典型用法 |
|----------|------|----------|
| `resp` | 单次工具/接口调用的结构化返回 | `resp.ok`、`resp.error_code`、`resp.message`、`resp.data.*` |
| `audit` | 测试侧审计查询（读 JSONL） | `audit.count(tool=…, decision=…, reason=…)`、`audit.last().field` |
| `desktop` | 独立桌面观测通道（不经 DeskPilot，直接读系统） | `desktop.exists(标题)`、`desktop.text(标题)`、`desktop.clipboard()`、`desktop.foreground()`、`desktop.diff(图a, 图b)`（0 表示无变化） |
| `svc` | 服务内部状态观测口（测试专用） | `svc.bindings.count()`、`svc.tokens.count()`、`svc.frozen`、`svc.alive` |
| `clock` | 测试时钟 | `clock.advance(秒数)` |
| `elapsed` | 调用耗时 | `elapsed(resp) < 50ms` |

规则：断言只读不改；`desktop` 通道不经过 DeskPilot 的任何工具（保证观测独立性）；评审类用例的断言以"评审记录结论 + 静态扫描结果"书写。

## 3. 正常功能测试设计（TC-N）

> 公共前提：服务以测试策略文件正常启动；L2 用例均在测试固件窗口上执行；用例间审计测试目录可清空。

### 3.1 启动与策略

**TC-N-MAIN-01 正常启动**（P1 / 集成 / F-CORE-06）
- 场景：以合法测试策略启动服务，验证启动编排全链路。
- 前提：policy.test.yml 合法；审计测试目录可写；内部端口空闲。
- 步骤：1) 启动服务进程；2) 等待就绪；3) 发起 MCP 握手；4) 查询审计日志。
- 预期：启动成功；MCP 握手通过；审计含"服务启动"事件。
- 断言：`assert resp_handshake.ok == true`；`assert audit.count(event="服务启动") == 1`；`assert svc.alive == true`

**TC-N-MAIN-02 正常退出**（P2 / 集成 / F-CORE-06）
- 场景：运行中的服务收到退出信号后的清理过程。
- 前提：服务已正常启动。
- 步骤：1) 发送退出信号；2) 等待进程结束；3) 查询审计日志。
- 预期：热键释放；停止事件落盘；退出码为 0。
- 断言：`assert proc.exit_code == 0`；`assert audit.last().event == "服务停止"`；`assert svc.hotkey_registered == false`

### 3.2 绑定管理

**TC-N-BIND-01 按标题 attach**（P1 / 集成 / F-CORE-01、F-L1-05）
- 场景：按窗口标题绑定测试固件窗口。
- 前提：固件窗口已打开，标题唯一。
- 步骤：1) attach（标题 = 固件前缀标题）。
- 预期：返回绑定令牌与绑定记录摘要。
- 断言：`assert resp.ok == true`；`assert resp.data.token != ""`；`assert svc.bindings.count() == 1`；`assert resp.data.process_name == "notepad.exe"`

**TC-N-BIND-02 按句柄 attach**（P2 / 集成 / F-L1-05）
- 场景：先枚举再按句柄精确绑定。
- 前提：固件窗口已打开。
- 步骤：1) find_window 按进程名过滤取句柄；2) attach（句柄）。
- 预期：绑定成功，记录句柄与步骤 1 一致。
- 断言：`assert resp.ok == true`；`assert svc.bindings[0].hwnd == hwnd_from_step1`

**TC-N-BIND-03 detach 解绑**（P1 / 集成 / F-L1-05）
- 场景：正常解绑。
- 前提：已持有有效绑定。
- 步骤：1) detach（绑定令牌）。
- 预期：返回成功；绑定表移除该记录。
- 断言：`assert resp.ok == true`；`assert svc.bindings.count() == 0`

**TC-N-BIND-04 活跃时间刷新**（P2 / 单测 / F-CORE-01）
- 场景：绑定内连续操作使绑定不因超时而失效。
- 前提：测试时钟可注入；binding_ttl = 600 秒；已绑定。
- 步骤：1) clock 前进 500 秒，执行一次写操作（mock 执行层）；2) clock 再前进 500 秒，再执行一次。
- 预期：两次均放行（每次通过校验即刷新活跃时间）。
- 断言：`assert resp1.ok == true and resp2.ok == true`；`assert svc.bindings[0].last_active_at == clock.now()`

### 3.3 L0 感知工具

**TC-N-L0-01 截图三范围**（P1 / 集成 / F-L0-01）
- 场景：全屏、区域、指定窗口三种截图范围。
- 前提：固件窗口已打开。
- 步骤：1) 全屏截图；2) 区域截图；3) 指定固件窗口截图。
- 预期：均返回有效图像与元信息。
- 断言：`assert 三次 resp.ok == true`；`assert resp.data.image 非空 and resp.data.width > 0 and resp.data.height > 0`；`assert resp.data.timestamp 非空`

**TC-N-L0-02 OCR 中英文识别**（P1 / 集成 / F-L0-02）
- 场景：对含中英文的样张做文字识别。
- 前提：准备含已知中英文内容的截图样张。
- 步骤：1) ocr（样张区域）。
- 预期：返回文字条目及位置。
- 断言：`assert resp.ok == true`；`assert len(resp.data.items) > 0`；`assert 存在 item.text 包含已知关键字`；`assert 每条 item 含位置字段`

**TC-N-L0-03 窗口枚举与过滤**（P1 / 集成 / F-L0-03）
- 场景：枚举桌面窗口并按进程名过滤。
- 前提：固件窗口已打开。
- 步骤：1) find_window（无过滤）；2) find_window（进程名 = notepad.exe）。
- 预期：全量列表含固件窗口；过滤列表进程名全为 notepad.exe。
- 断言：`assert 存在 w in resp1.data.windows 满足 w.title 包含 "DESKPILOT_TEST_"`；`assert 所有 w in resp2.data.windows 满足 w.process_name == "notepad.exe"`

**TC-N-L0-04 UIA 元素树**（P1 / 集成 / F-L0-04）
- 场景：获取测试窗口的元素树。
- 前提：固件窗口已打开。
- 步骤：1) get_ui_tree（窗口标识）。
- 预期：返回完整树，可交互元素有标记。
- 断言：`assert resp.ok == true`；`assert resp.data.tree 非空`；`assert 存在 node.interactable == true`；`assert 每节点含 name/control_type/automation_id/rect 字段`

**TC-N-L0-05 SoM 标注**（P1 / 集成 / F-L0-05，M3）
- 场景：对目标窗口生成编号标注图（只读操作，无需绑定）。
- 前提：固件窗口已打开。
- 步骤：1) get_clickable_map（窗口标识）。
- 预期：标注图与编号对照表一一对应。
- 断言：`assert resp.ok == true`；`assert resp.data.image 非空`；`assert 编号集合 == 1..N 连续唯一`；`assert 每编号对应元素 rect 在窗口矩形内`

**TC-N-L0-06 模板匹配命中**（P2 / 集成 / F-L0-06）
- 场景：搜索已知图标模板。
- 前提：屏幕含已知图标；阈值 0.8。
- 步骤：1) template_match（模板、全屏、0.8）。
- 预期：命中且置信度达标。
- 断言：`assert len(resp.data.matches) > 0`；`assert resp.data.matches[0].confidence >= 0.8`

**TC-N-L0-07 鼠标位置**（P2 / 集成 / F-L0-07）
- 场景：移动后读取坐标。
- 前提：无。
- 步骤：1) move(300, 300)；2) get_cursor。
- 预期：读回与目标坐标一致。
- 断言：`assert resp.data.x == 300 and resp.data.y == 300`

**TC-N-L0-08 读剪贴板**（P1 / 集成 / F-L0-08）
- 场景：读取预设的剪贴板内容。
- 前提：经 desktop 通道预设剪贴板文本 "abc123"。
- 步骤：1) get_clipboard。
- 预期：返回内容一致。
- 断言：`assert resp.data.text == "abc123"`

### 3.4 L1 控制工具

**TC-N-L1-01 等待已存在窗口**（P1 / 集成 / F-L1-01）
- 场景：目标已存在时首次探测即命中。
- 前提：固件窗口已打开。
- 步骤：1) wait_for_window（固件标题，超时 5 秒）。
- 预期：零延迟返回窗口信息。
- 断言：`assert resp.ok == true`；`assert elapsed(resp) < 1000ms`；`assert resp.data.hwnd 非空`

**TC-N-L1-02 等待晚出现窗口**（P1 / 集成 / F-L1-01）
- 场景：目标在调用之后出现，轮询命中。
- 前提：固件窗口未开；安排在调用 2 秒后启动。
- 步骤：1) 发起 wait_for_window（超时 10 秒）；2) 2 秒后启动固件窗口。
- 预期：命中返回，耗时符合预期。
- 断言：`assert resp.ok == true`；`assert 1500ms < elapsed(resp) < 10000ms`

**TC-N-L1-03 等待元素出现**（P1 / 集成 / F-L1-02）
- 场景：等待动态出现的控件。
- 前提：已绑定固件窗口；安排 1 秒后打开其"查找"对话框。
- 步骤：1) wait_for_element（绑定令牌，元素条件，超时 5 秒）。
- 预期：命中返回元素信息。
- 断言：`assert resp.ok == true`；`assert resp.data.element.name 非空`

**TC-N-L1-04 滚轮滚动**（P1 / 集成 / F-L1-04）
- 场景：在绑定窗口内滚动。
- 前提：固件窗口预置超出可视区的长文本；已绑定。
- 步骤：1) 记录滚动前截图；2) scroll（向下，幅度 3）；3) 再截图。
- 预期：内容位置发生变化。
- 断言：`assert resp.ok == true`；`assert desktop.diff(图前, 图后) != 0`

### 3.5 L2 写入工具

**TC-N-L2-01 启动白名单应用**（P1 / E2E / F-L2-01）
- 场景：launch_app 启动 notepad。
- 前提：测试策略白名单含 notepad.exe。
- 步骤：1) launch_app（notepad）；2) find_window 按进程名查找。
- 预期：启动成功且可被发现。
- 断言：`assert resp.ok == true`；`assert 步骤2 列表中存在新 notepad 窗口`

**TC-N-L2-02 窗口前置**（P1 / E2E / F-L2-02）
- 场景：把绑定窗口提到前台。
- 前提：固件窗口 A 与另一窗口并存且 A 非前台；已绑定 A。
- 步骤：1) activate_window（绑定令牌）。
- 预期：A 成为前台窗口。
- 断言：`assert resp.ok == true`；`assert desktop.foreground() == A 的句柄`

**TC-N-L2-03 元素点击**（P1 / E2E / F-L2-03）
- 场景：按名称点击菜单项，无需坐标。
- 前提：已绑定固件窗口。
- 步骤：1) 记录点击前截图；2) click_element（名称 = "文件"）。
- 预期：点击生效，返回被点元素摘要。
- 断言：`assert resp.ok == true`；`assert resp.data.element.name == "文件"`；`assert desktop.diff(图前, 图后) != 0`

**TC-N-L2-04 按 SoM 编号点击**（P1 / E2E / F-L2-03、F-L0-05，M3）
- 场景：取标注图后仅凭编号点击。
- 前提：已绑定固件窗口；SoM 缓存有效（取图窗口即绑定窗口）。
- 步骤：1) get_clickable_map（固件窗口标识）；2) 按对照表中编号 k click_element（绑定令牌，编号 = k）。
- 预期：命中编号 k 对应元素（点击前校验缓存 hwnd 与绑定句柄一致）。
- 断言：`assert resp.ok == true`；`assert resp.data.element == 对照表[k] 的元素引用`

**TC-N-L2-05 元素设值**（P1 / E2E / F-L2-04）
- 场景：向编辑区元素直接设值。
- 前提：已绑定固件窗口。
- 步骤：1) type_element（编辑区，"Hello"）。
- 预期：设值成功且可读回。
