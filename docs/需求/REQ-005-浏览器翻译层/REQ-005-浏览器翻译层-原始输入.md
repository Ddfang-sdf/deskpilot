## 2. 「浏览器语言」是什么(2026-09-17 源码取证结论)

对 agent-browser v0.38.0(`C:\code\workspace\agent-browser\cli\src\`)的取证
坐实:**浏览器语言不是秘密,是 Chrome 自带的两层公开机制**——

1. **CDP(Chrome DevTools Protocol)**:公开的 JSON-RPC over WebSocket 协议,
   读页面、要坐标、注入输入全走它;
2. **AXTree(可访问性树)**:Chrome 自己把 DOM 汇总成「角色+名称+状态」树
   (`Accessibility.enable` + `Accessibility.getFullAXTree`,snapshot.rs:333,431),
   与 Windows UIA **同源同构**(UIA=Windows 的可访问性树,AXTree=Chrome 的)。

agent-browser 没有做「看懂网页」的智能翻译——它消费 Chrome 自产的语义。
它「识别无文字图标」的真相=网页经 aria-label **自申报**语义,零像素参与。

### 2.1 agent-browser 的坐标与动作链(证据)

- 坐标:ref(@eN)→ backendNodeId(element.rs:282,534)→
  `DOM.scrollIntoViewIfNeeded`(element.rs:633-646)→ `DOM.getBoxModel` →
  box_model_center(element.rs:417,428,997)——布局引擎真值,viewport 相对
  CSS 像素,浮点精度;
- 动作:`Input.dispatchMouseEvent` mousePressed/Released(interaction.rs:111,
  995,1082,1150);键盘 `Input.dispatchKeyEvent` + 文本 `Input.insertText`
  (interaction.rs:184,268,305);
- 兜底长尾(翻译层非银弹的实证):checkbox 坐标点击无效→DOM `.click()`
  (interaction.rs:632-640,注释原话 "mirrors how Playwright dispatches clicks
  through the DOM rather than via raw Input.dispatchMouseEvent coordinates");
  Electron webview 拒 key events→insertText(interaction.rs:300-305);
- 挂接:自拉 Chrome 带独立 user-data-dir(actions.rs:3544),读
  DevToolsActivePort 文件拿 ws 地址(chrome.rs:926,1136);Pre-M144 回退
  HTTP /json/version(chrome.rs:1185)。

### 2.2 与 DeskPilot「确认坐标,再行动」的对比:**形状同构,差在链条两端**

agent-browser 也是「先确认坐标、再行动」,差异全在两端:

| 维度 | DeskPilot(OS 级) | agent-browser(CDP 级) |
|------|------------------|------------------------|
| 坐标来源 | UIA rect(可靠)/CV 连通域(弱,几何显著度无语义)/截图(最弱,DPI 比例陷阱) | 布局引擎 getBoxModel,**每页必有,规范保证** |
| 动作通道 | SendInput 动物理光标,要求前台/焦点/无遮挡 | WebSocket 注入渲染器:不动光标、不要焦点、遮挡可点、无 DPI 映射、不与人抢鼠标 |
| 验证通道 | 截屏/UIA 差分 | Runtime.evaluate 读回 DOM 断言 |
| 覆盖缺口 | 自绘应用 UIA 不申报→掉进弱 CV 兜底(可靠性差的根源) | 网页必有 AXTree,无对应缺口;缺口在原生对话框(=DeskPilot 地盘,互补) |

## 3. 自建可行性评估(2026-09-17)

- **最小 CDP 子集 ≈10 条命令**:Target.attach / Accessibility.enable+
  getFullAXTree / DOM.getDocument+getBoxModel+scrollIntoViewIfNeeded /
  Runtime.evaluate / Input.dispatchMouseEvent+dispatchKeyEvent+insertText /
  Page.navigate+captureScreenshot。Python 自研(websocket+JSON)千行级;
- **三条实现路线**(需求分析阶段终裁):A 自研最小 CDP 子集(符合「自己拥有」,
  无重依赖,范围可控);B playwright-python(成熟但翻译层在别人手里,带入
  node driver/浏览器生命周期包袱);C 收编 agent-browser 本体(Apache-2.0
  允许,但 Rust daemon 技术栈异构+继承全部架构,比自建子集重);
- **v1 范围建议**:单 tab 主框架+同进程 iframe(agent-browser 亦只做到这,
  跨进程 iframe 走退路,element.rs:302);OOPIF/下载管理/多 tab 会话留 v2。

## 4. 硬约束(需求分析时必须逐条落进方案)

1. **Chrome 136+(2025-05)安全限制**:调试端口对默认 user-data-dir 拒绝——
   不能 attach 用户日常 Chrome,必须自己拉起受管实例(独立 profile)。
   agent-browser 正是这么干的。**设计时须实机确认版本行为**;
2. **调试端口安全面**:端口把浏览器(含 cookie)整个暴露给本地进程——
   policy/audit 引擎须为浏览器域立护栏;
3. **原生对话框互补**:文件选择/打印=OS 窗口,落回 DeskPilot UIA 既有地盘;
   JS 对话框走 CDP Page 域——两通道天然互补,「用户只装我们」成立;
4. **用户手势边界**:支付/DRM 类需真实用户手势的动作 CDP 覆盖不了——
   身份类动作人类执行本就是铁律,不冲突;
5. **Electron 误路由约束不变**(ISS-0090 #3):CDP 层只管网页标签内容,
   Electron 应用原生壳仍归 UIA;禁止按「Chromium 进程名」划界。
