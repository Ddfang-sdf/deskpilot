## 1 引言

### 1.1 编写目的

本说明书定义 DeskPilot「浏览器翻译层」的全部需求,作为后续设计、实现与
验收的唯一依据。预期读者:sdfang(审核/决策者)、AI 开发伙伴(实现者)、
维护者(回归/演进)。

### 1.2 背景

- 待开发系统:DeskPilot 浏览器翻译层(内嵌于 DeskPilot daemon,非独立产品);
- 任务提出者:sdfang。2026-09-17 战略裁定:「我们不要联盟,而是我们自己
  要拥有浏览器语言的翻译层。这样用户只需要安装我们就可以了。我们现在占领
  了 Windows 桌面应用,但是浏览器这块领地我们没有」;2026-09-24 立项
  (「立项!先完成这个」);
- 问题形态:DeskPilot MCP 已能「看+写」Windows 桌面,但遇浏览器即成
  「老花眼」——Chromium 网页内容对 UIA 通道默认覆盖为零(穿刺 2 实测),
  截图+OCR 是最弱通道。本需求即为浏览器配上「老花镜」;
- **「老花镜」的确切含义(穿刺 3 实测后修正)**:不是新造视觉能力,而是
  三件事——①**开灯认知**:Chromium 的 UIA 输出只是默认关闭(懒启用开关),
  点亮后 DeskPilot 既有 get_ui_tree 即可看清,眼睛本来就在;②**统一入口**:
  把渲染窗直查/懒启用/坐标换算的机制知识固化为两个工具,AI 无需懂机制;
  ③**共管补强**:CDP/AXTree 仅服务共管浏览器,补 UIA 够不着的尾部能力
  (CSS 选择器/evaluate 读回/滚动控制/免前台注入);
- 与其他系统的关系:与 Chrome DevTools Protocol(CDP)、Windows UIA 为
  外部接口关系;与 DeskPilot 既有强制层(enforcement/审批/急停/审计)为
  内嵌复用关系;agent-browser(C:\code\workspace\agent-browser)为机制
  取证参照物(Apache-2.0,不 fork、不联邦)。

### 1.3 定义

| 术语 | 定义 |
|------|------|
| CDP | Chrome DevTools Protocol,Chromium 公开的 JSON-RPC over WebSocket 调试协议 |
| AXTree | Chromium 自产可访问性树(role+name+state),与 Windows UIA 同源同构 |
| 老花镜 | 本需求的俗称:让 AI 在浏览器上获得「确认形状或文字」能力的感知层 |
| 共管浏览器 | 由 DeskPilot 拉起、持久非默认 user-data-dir、CDP 常开的浏览器实例——人机共用的日常浏览器形态 |
| 用户自拉浏览器 | 用户以常规方式自行启动的浏览器实例(无 CDP 端口) |
| 懒启用 | Chromium UIA 可访问性惰性自激活机制:对渲染窗发 UIA 查询后 2~3 秒内自动点亮(穿刺 3 实测) |
| 感知路由 | 按目标归属选择感知通道的机制:共管 Chromium→CDP/AXTree;用户自拉→UIA;裸浏览器→OCR/CV |
| 浏览器域 | 浏览器窗口内的网页内容面;与「桌面域」(OS 窗口)互补 |
| 渲染窗 | Chromium 的 `Chrome_RenderWidgetHostHWND`(网页内容宿主窗口) |

## 2 任务概述

### 2.1 目标

**一句话**:人说「接手」,AI 就能在人类正在使用的浏览器里,看清页面上的
元素(叫什么/是什么/在哪个像素),并用同一副鼠标键盘继续操作——审批、急停、
冻结等安全语义与桌面域完全一致。

分解目标:

| 编号 | 目标 | 实测状态 |
|------|------|----------|
| G-01 | 用户自拉 Chromium 浏览器,零配置看清(语义+坐标) | 实测达成(Edge GitHub 页 800+ 节点,穿刺 3+接管演示) |
| G-02 | 用户自拉 Firefox 看清 | 实测达成(必应 957 节点/0.8s/坐标像素级吻合) |
| G-03 | 共管浏览器(持久登录态)最强语义面(CDP/AXTree) | 穿刺 1/2 达成(协议全通,真实站 10/10) |
| G-04 | 元素坐标可直接驱动物理鼠标点击(误差 ≤1px 级) | 穿刺 1 达成(30/30,≤0.71px) |
| G-05 | 语义失明目标(装饰图形)有像素兜底 | 实测达成(狐狸坐标直读) |
| G-06 | 浏览器域写操作安全语义与桌面域一致 | 设计继承(强制层进程级生效,实测拦截有效) |

### 2.2 用户的特点

| 干系人 | 角色 | 关注点 |
|--------|------|--------|
| sdfang | 产品决策者/安全审批方 | 领地覆盖、安全模型不破、裁定可追溯 |
| AI 伙伴 | 直接调用方 | 语义可读(与 UIA 同构)、坐标现取现用、错误可自愈、零浏览器类型感知负担 |
| 人类用户 | 监督者与急停执行者 | 人机共用同一浏览器现场,审批/急停语义不变,零新打断 |
| 维护者 | 代码与测试维护 | 无重依赖、通道接口可插拔、复用既有强制层 |

### 2.3 假定和约束

**硬约束(原始输入 §4,全部经实测确认)**:

| # | 约束 | 实测结论(2026-09-24) |
|---|------|----------------------|
| C-1 | Chrome 136+ 调试端口对默认 user-data-dir 拒绝——**CDP 通道**不可 attach 用户日常浏览器(UIA 通道不受此限,见 §3.1 R-01) | 成立且更狠(移交机制+拒绝双封堵,穿刺 1 目标 6)。推导:CDP 通道仅共管浏览器可用 |
| C-2 | 调试端口把浏览器(含 cookie)暴露给本地进程——须护栏 | 共管浏览器端口仅 127.0.0.1、随实例回收;用户自拉浏览器无端口(不存在此面) |
| C-3 | 原生对话框=OS 窗口,落回桌面域 | 设计沿用(两通道天然互补) |
| C-4 | 支付/DRM 类真实用户手势动作不可替代 | 身份类动作人类执行铁律覆盖,不冲突 |
| C-5 | Electron 误路由约束:禁按「Chromium 进程名」划界 | 路由判据=归属/窗口特征,不按进程名(见 §3.1 R-01) |

**依赖**:

| 依赖 | 说明 |
|------|------|
| websocket-client(纯 Python) | 仅 CDP 通道需要(路线 A 唯一新增依赖,侦察已验证);UIA 通道零新增依赖 |
| DeskPilot 既有强制层 | enforcement 分级/审批/急停冻结/安全桌面/审计——浏览器域原样复用 |
| Windows UIA | 用户自拉浏览器感知主通道(懒启用机制,穿刺 3) |
| 受管浏览器二进制 | 共管浏览器=本机 Edge/Chrome(Firefox 可选);不捆绑下载浏览器 |
| Windows 10/11 x64 | 运行环境(与 DeskPilot 本体一致) |

**假定**:①用户将日常浏览迁入共管浏览器为一次性人工动作(含登录);
②国产 Chromium 壳(360/QQ/搜狗)与 Edge/Chrome 同族(同码逐字节一致已
验证 Edge/Chrome 两家,余者按同族假定,实测后补);③Firefox a11y 默认开
启(本机实测成立,其他机器按同版本假定)。

## 3 需求规定

### 3.1 对功能的规定

**R-01 感知路由(归属判定,零浏览器类型判断)**
- 共管 Chromium 实例(DeskPilot 拉起,创建归属)→ CDP/AXTree 通道;
- 其余浏览器窗口(用户自拉,任意内核)→ UIA 通道(渲染窗/DocumentControl 直查,懒启用等待 ≤3s);
- 裸浏览器(前两层不可用)→ OCR/CV 像素兜底;
- **禁止**按浏览器厂商/进程名做 if/else 路由;通道接口统一,输出 schema 统一。

**R-02 统一语义快照 `browser_snapshot`**(读,L0)
- 输出:页面元素的 role+name+state+rect(虚拟桌面物理坐标),与 get_ui_tree 同构;
- 覆盖:交互元素(按钮/链接/输入框/图片)与正文文本;快照每次现取,**不缓存**(真实站文本 3s 即变,穿刺 2);
- 规模参考:Chromium 用户自拉 800+ 节点截断;Firefox 必应 957 文档节点;共管 CDP 百度 310/必应 1325 节点。

**R-03 元素坐标 `browser_get_rect`**(读,L0)
- 输入=语义定位(名称/角色/序号),输出=元素虚拟桌面物理坐标;
- 精度:Chromium CDP 路线 ≤0.71px(公式 `内容区矩形原点+getBoxModel中心×devicePixelRatio`,缩放/滚动/DPI 全档实测);Firefox UIA rect 零换算像素级吻合;
- 附 `elementFromPoint` 遮挡自检(坐标对但顶层非目标时如实报告)。

**R-04 行动链(写,既有工具原样用)**
- 点击/输入/按键/截图全部经 DeskPilot 既有 MCP 工具与强制层(L2 写操作、审批、急停冻结、防误射、证据留档),**v1 不新增 CDP 注入式动作通道**(留 v2 候选);
- 导航=地址栏物理输入(实测:点击→粘贴→回车→必应加载)。

**R-05 共管浏览器生命周期**
- 拉起:持久非默认 user-data-dir(`%LOCALAPPDATA%\DeskPilot\browser-profile`)+ `--remote-debugging-port=0` + DevToolsActivePort 发现;身份类登录由人类完成一次,会话持久;
- 回收:按 user-data-dir 命令行匹配清理(壳进程不级联的坑已实测);
- 用户日常浏览器零触达(默认 profile 永不连接,审计可证)。

**R-06 壳层信息**
- 标签清单/活动标签/地址栏 URL/窗口矩形,经壳 UIA 可得(实测:6 标签含内存占用+活动标签+地址栏 rect)。

**R-07 语义失明面兜底**
- 无 a11y 申报的装饰图形(实测:Firefox 致谢页狐狸)语义层原理性失明;
- 兜底=语义参照系(邻近语义节点 rect)+像素层(截图/视觉/CV)定位,输出坐标供行动(实测:狐狸头/尾坐标直读)。

### 3.2 对性能的规定

| 项 | 指标(实测值) |
|----|--------------|
| 语义快照时延 | 百节点页 <50ms(AXTree 热调 5.5~11.6ms;UIA Firefox 0.8s/1059 节点);千节点重页按 ≤10 倍外推,设计时复核 |
| 坐标获取 | ≤1ms/元素(getBoxModel 0.41~0.63ms;UIA rect 随快照) |
| 懒启用等待 | ≤3s(仅用户自拉 Chromium 首次,其后零等待;Firefox 无此等待) |
| 点击命中精度 | ≤0.71px 误差(30/30 实测) |
| 快照缓存 | 禁止(每次现取) |

### 3.3 输入输出要求

- `browser_snapshot` 输出 schema 与 `get_ui_tree` 元素集同构(name/control_type/rect/interactable),另增 `source`(uia/cdp/ocr 路由出处)与页面元信息(标题/URL);
- `browser_get_rect` 输出 `[l,t,r,b]` 虚拟桌面坐标(与 screenshot/get_ui_tree 同坐标系),误差超界或遮挡时显式报错而非静默给点。

### 3.4 数据管理能力要求

- 快照无持久化(现取现弃);共管浏览器 profile 持久于 `%LOCALAPPDATA%\DeskPilot\browser-profile`(用户登录态数据,属用户数据,不出本机);
- 感知过程审计:路由选择/通道调用/快照规模记审计(与桌面域同规)。

### 3.5 故障处理要求

| 故障 | 处理 |
|------|------|
| 渲染窗失效(标签切换/页面重渲染,实测 hwnd 会变) | 按窗口重查渲染窗,不得使用失效 hwnd(实测 7669388→2885474 案例) |
| 懒启用未亮(首查仍空) | 等待 ≤3s 复走一次;仍空则如实报「页面暂不可读」,禁止给空语义装成功 |
| 坐标映射误差超界 | fail-closed 报错(不虚报命中) |
| 遮挡(elementFromPoint 非目标) | 如实报告顶层元素,由 AI 决策(滚动/换路径) |
| CDP 连接断开(共管实例) | 实例存活校验+重连;实例死亡如实报并提示重新拉起 |

### 3.6 其他专门要求(安全)

- 浏览器域写操作沿用 enforcement 分级(读 L0/写 L2);审批三态、急停冻结、安全桌面(锁屏/UAC 全禁)与桌面域语义一致(决策 D-07);
- `browser_eval`(CDP Runtime.evaluate 兜底,v2 候选)若启用定 L3 审批;
- 感知面只读通道(L0)在冻结期同样受 l0_during_freeze 语义约束(沿用现状)。

## 4 运行环境规定

### 4.1 设备
Windows 10/11 x64;单/多显示器(虚拟桌面坐标系,含负坐标);PMv2 DPI 感知。

### 4.2 支持软件
- 浏览器:共管 Edge/Chrome(153 实测);用户自拉 Edge(153)/Firefox(最新版,2026-09-24 实测);国产 Chromium 壳按同族假定;
- DeskPilot daemon(既有)+ websocket-client(CDP 通道)。

### 4.3 接口
- CDP:WebSocket @127.0.0.1(仅共管实例);
- UIA:Windows UI Automation(用户自拉浏览器与壳层);
- MCP:DeskPilot 既有工具面(行动链)。

### 4.4 控制
受管浏览器的拉起/回收由 DeskPilot daemon 统一控制;用户自拉浏览器只读感知、不改其配置(a11y 懒启用为 Chromium 内建行为,无配置写入)。
