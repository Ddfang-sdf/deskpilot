## D-01 实现路线=自研最小 CDP 子集(路线 A,范围限定共管实例)

- **决策**:CDP 通道以 Python 自研最小子集实现(websocket+JSON),不引
  playwright(路线 B)、不收编 agent-browser 本体(路线 C);**CDP 通道仅
  服务共管浏览器**,不追求全浏览器覆盖。**(2026-09-24 sdfang 裁定:CDP
  补齐进交付——定位=「登录态 webapp 的专业操作面」,价值排序=evaluate
  读回验证/滚动控制/CSS 选择器消歧;并附描述面要求:AI 必须能在工具描述
  中发现「UIA 不足→拉起共管浏览器」的自助路径,见 ISS-0115。)**
- **依据**:侦察活体原型 ~110 行已跑通全链;Edge/Chrome 153 同码逐字节
  一致(Chromium 家族通用);「自己拥有」裁定逐字符合。
- **否决**:B——翻译层在别人手里+node driver 包袱;C——Rust 异构+继承
  全部架构。

## D-02 共管浏览器=持久非默认 profile,用户日常浏览器零触达

- **决策**:共管浏览器以**持久** user-data-dir
  (`%LOCALAPPDATA%\DeskPilot\browser-profile`)拉起——人机共用的日常
  浏览器形态,登录态持久(身份类登录人类完成一次);**不是**临时无尘室,
  **不是**第二个浏览器;用户默认 profile 的日常浏览器永不连接。
- **依据**:硬约束 1 实测(默认 profile 双机制封堵);sdfang 2026-09-24
  场景裁定:「鼠标和键盘只有一副」——人机必须共用同一浏览器现场。
- **护栏**:拉起参数含 `--force-renderer-accessibility`(穿刺 3 优选:t+0
  免等待、节点 +11%);回收按 profile 路径匹配清理(壳进程不级联实测坑)。

## D-03 v1 范围=单 tab 主框架+同进程 iframe

- **决策**:v1 只做单 tab 主框架+同进程 iframe;OOPIF/多 tab 会话/下载
  管理/扩展 v2。
- **依据**:agent-browser 同口径边界;范围可控优先。
- **否决**:一次做多 tab——会话状态面爆炸。

## D-04 工具面=双原语(browser_snapshot/browser_get_rect)+既有行动链

- **决策**:新增 MCP 工具仅两个,均 L0 只读;行动(点击/输入/导航/截图)
  全部复用 DeskPilot 既有工具,**v1 不做 CDP 注入式动作通道**(留 v2);
  `browser_eval`(任意 JS)若 v2 启用定 L3 审批。
- **依据**:穿刺 1 实测——CDP 坐标经换算公式可直接驱动物理点击
  (30/30,≤0.71px);Firefox 实测——UIA rect 零换算像素级吻合,物理动作
  链在用户自拉浏览器全通。「浏览器=普通软件」成立,双通道无必要。
- **否决**:v1 做 browser_click/type/eval 注入系——平行写入通道,安全语义
  要重建一套,收益未证。

## D-05(预留)`browser_eval` 定级 L3

- **决策**(v2 候选,本版不实施):若启用 Runtime.evaluate 兜底,定 L3
  审批,描述面明示仅长尾用途。
- **依据**:任意 JS 注入=最高危点(硬约束 2 向页面内延伸)。

## D-06 Electron 划界不变:禁按「Chromium 进程名」路由

- **决策**:路由判据=归属(注册表/窗口特征),Electron 原生壳归 UIA,
  禁止按进程名做厂商分支。
- **依据**:硬约束 5 / ISS-0090 #3(Electron 误路由前科)。

## D-07 浏览器域安全语义与桌面域一致

- **决策**:审批三态、急停冻结、安全桌面、审计分级——浏览器域原样沿用,
  零新语义、零新分支。
- **依据**:[[secure-desktop-freeze-is-desired]];「用户只装我们」的安全
  承诺一致性;强制层进程级生效,实测对浏览器坐标拦截有效(穿刺 1)。

## D-08 通道分工与「开灯非新感官」定论

- **决策**:感知三通道分工——**UIA=用户自拉浏览器主通道**(懒启用一次,
  零配置);**CDP=共管浏览器专属**(全语义+尾部能力);**OCR/CV=失明面
  兜底**。「老花镜」的正式定义=开灯认知(Chromium UIA 懒启用)+统一入口
  (双原语)+共管补强,**不是新造视觉能力**。
- **依据**:穿刺 3 全矩阵——SPI/注册表/勾选/启动参数四机制均测,证明
  「裸查渲染窗即可自点亮」,任何「开启动作」都不需要;UIA 与 AXTree 语义
  ≈九成重合、坐标等效(0.11px);Firefox 默认点亮零等待。
- **否决**:以 SPI_SETSCREENREADER 作为开启机制——全局信号副作用(latch
  不回落);以「必须用户开 a11y」为前提——实测不需要。
