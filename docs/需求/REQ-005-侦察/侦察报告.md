## 一、七项目标逐条结论

### 目标 1 连通与握手 —— **成**

- 机制:`--remote-debugging-port=0` 拉起受管实例 → 读 profile 下 `DevToolsActivePort` 文件(首行端口、次行 ws 路径)→ 连 browser 级 WebSocket → `Target.getTargets` 找到 page target → `Target.attachToTarget {flatten:true}` 得 sessionId,后续命令带 sessionId 路由。

- **结论:DevToolsActivePort + flatten session 链路在 Edge 153 实测打通,与 agent-browser 记载的机制一致。**

### 目标 2 AXTree —— **成**

- 方法:`Accessibility.enable` + `Accessibility.getFullAXTree`,测试页含表单/按钮/链接/aria-label 图标按钮/ARIA slider。
- 证据:`axtree-full.json`(41 节点全量)、`axtree-sample.json`(36 节点裁剪样本,≤100 达标)。
- 结构样例(引自样本):
  - 图标按钮:`{role:"button", name:"收藏此页"}`——aria-label 自申报语义成立,**零像素参与**,佐证 §2「识别无文字图标的真相」;
  - 文本框:`{role:"textbox", name:"姓名", properties:{focusable:true, editable:"plaintext", multiline/readonly/required}}`;
  - 复选框:`{role:"checkbox", name:"同意条款", properties:{checked:"false", focusable:true}}`;
  - 角色清单:RootWebArea/heading/form/button/link/textbox/checkbox/slider/StaticText/LabelText/InlineTextBox 等 16 种。
- **结论:AXTree 的 role+name+properties(state)三件套与 UIA 的 ControlType+Name+状态属性结构同构,足以支撑统一语义层(浏览器节点与 UIA 节点可共用一个描述面 schema)。**

## 四、发现的坑(如实记录)

1. **WebSocket Origin 拒绝**:Chromium 111+ 拒绝带 Origin 头的握手,websocket-client 默认会带,必须 `suppress_origin=True`——不处理则连接即被拒,是最易踩的第一坑;
2. **launcher PID 是壳**:`subprocess.Popen` 拿到的 msedge PID 只是启动壳,真正 browser 进程由它再拉起并重挂父进程,`taskkill /T` 打壳**不级联**——首跑留下整棵受管进程树+锁住的临时 profile。清理须按 user-data-dir 命令行匹配补刀(已固化进 `kill_managed_edge`,二跑验证 `temp_profile_removed: true`);
3. **默认 profile 拉起即移交**:日常实例在跑时新进程 returncode 0 静默退出、端口不开——自动化若误以为「起来了」会连空,检测端口监听比检测进程存活可靠;
4. **GBK 控制台乱码是显示问题**:落盘 JSON 为正确 UTF-8(已按字节复核),勿误判为协议编码问题;
5. **nameSources 空载**:本版本 AXNode 未回传 nameSources 明细(name 本身已解析正确)——语义来源审计需求不能依赖该字段常在有。
