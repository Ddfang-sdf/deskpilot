## 0. 引言

**目的与读者**:定义 DeskPilot 自建浏览器语言翻译层的完整需求,作为设计、
实现与验收的唯一依据。读者:sdfang(评审/决策)、AI 开发伙伴(实现)、维护者。

**核心命题(sdfang 原话浓缩)**:「我们不要联盟,而是我们自己要拥有浏览器
语言的翻译层。用户只需要安装我们。」——浏览器语言不是秘密,是 Chrome 自
带的两层公开机制(CDP+AXTree),侦察已实测:自研最小 CDP 子集(~110 行
Python 原型)即可打通全链。

**干系人**:

| 干系人 | 角色 | 关注点 |
|--------|------|--------|
| sdfang | 产品决策者/安全审批方 | 领地覆盖、安全模型不破、裁定可追溯 |
| AI 伙伴 | 直接调用方 | 网页语义可读(同构 UIA)、坐标零成本、动作链可靠、错误可自愈 |
| 人类用户 | 审批与急停执行者 | 审批/急停/冻结语义与桌面域一致,零新打断 |
| 维护者 | 代码与测试维护 | 无重依赖、范围可控、复用桌面域既有强制层 |

**术语表**:

| 术语 | 定义 |
|------|------|
| CDP | Chrome DevTools Protocol:公开的 JSON-RPC over WebSocket 协议,读页面/要坐标/注入输入全走它 |
| AXTree | Chrome 自产可访问性树(role+name+state),与 Windows UIA 同源同构 |
| 受管实例 | DeskPilot 以独立临时 user-data-dir 拉起的浏览器实例(唯一可达通道,硬约束 1 实测) |
| 翻译层 | CDP/AXTree → DeskPilot 工具原语的映射层(自研最小子集,路线 A) |
| 浏览器域 | 受管实例内网页标签的内容面;与「桌面域」(OS 窗口)互补 |
| OOPIF | 跨进程 iframe(out-of-process iframe),v1 不做,留 v2 |

## 1. 使用场景(每条对应验收上下文)

| 编号 | 场景 |
|------|------|
| UC-01 | AI 读懂网页:对受管实例当前页取 AXTree,获得 role/name/state 语义树(表单/按钮/链接/aria 图标),语义面与 UIA 同构——「看不懂浏览器」终结 |
| UC-02 | AI 点击网页元素:按语义定位 → getBoxModel 现取坐标 → dispatchMouseEvent 注入 → 动作生效(DOM 读回由 AI 侧组合验证) |
| UC-03 | AI 填写表单:insertText 注入中文文本,读回逐字符一致 |
| UC-04 | 证据留档:Page.captureScreenshot 网页截图,与桌面域证据链同规 |
| UC-05 | 多域协同:网页原生对话框(文件选择/打印)落回桌面域 UIA 处理——「用户只装我们」闭环 |
| UC-06 | 安全场景:锁屏/UAC 期间浏览器域写操作与桌面域同样全禁;急停冻结对受管实例同样生效 |

## 2. 功能性需求(FR)

| 编号 | 需求 | 侦察证据 |
|------|------|----------|
| FR-01 | **受管实例生命周期**:拉起(独立临时 profile,`--remote-debugging-port=0`+DevToolsActivePort 发现)→ 使用 → 按 user-data-dir 匹配可靠清理(壳进程不级联的坑已实测,清理机制固化) | 目标 1/6、坑 2/3 |
| FR-02 | **网页语义快照**:`browser_snapshot`——getFullAXTree 返回 role/name/properties 树,与 UIA 描述面同构 | 目标 2(41 节点,aria 自申报零像素) |
| FR-03 | **元素坐标获取**:`browser_get_rect`——querySelector+getBoxModel,viewport CSS 像素,现取现用不缓存(0.4~0.6ms) | 目标 3/7 |
| FR-04 | **注入点击**:`browser_click`——dispatchMouseEvent 按下/抬起;不动光标、不要焦点、遮挡可点 | 目标 3(计数器读回=1) |
| FR-05 | **注入输入**:`browser_type`——insertText(中文实测逐字符一致) | 目标 5 |
| FR-06 | **逃生舱**:`browser_eval`——Runtime.evaluate 兜底长尾(如 checkbox DOM .click() 类),**入审批护栏** | 原始输入 §2.1 长尾实证 |
| FR-07 | **网页截图**:`browser_screenshot`——captureScreenshot 留档 | 目标 4 |
| FR-08 | **页面导航**:`browser_navigate`——Page.navigate(协议公开,低风险,v1.1 补实测) | 侦察遗留项 |

## 3. 非功能性需求(NFR)

| 编号 | 需求 |
|------|------|
| NFR-01 | **依赖最小化**:路线 A 自研 CDP 子集,除 websocket-client(纯 Python 小包)外零新增重依赖;不引 playwright/node/Rust(决策 D-01) |
| NFR-02 | **安全模型延续**:浏览器域写操作沿用 enforcement 分级(读 L0/写 L2/eval L3,决策 D-05);急停冻结与安全桌面全禁语义与桌面域一致(UC-06) |
| NFR-03 | **调试端口护栏**:调试端口把整个受管浏览器暴露给本地进程——受管实例专用 profile(不碰用户数据),端口仅 127.0.0.1,生命周期随实例回收(硬约束 2) |
| NFR-04 | **Electron 划界不变**:CDP 层只管网页标签内容,Electron 原生壳仍归 UIA;禁止按「Chromium 进程名」划界(硬约束 5,ISS-0090 #3) |
| NFR-05 | **性能**:百节点页快照 <50ms(实测 5.5~11.6ms);千节点重页按 10~25 倍外推,v1 设计时实测复核 |
| NFR-06 | **v1 范围边界**:单 tab 主框架+同进程 iframe;OOPIF/多 tab 会话/下载管理/原生扩展 v2(决策 D-03) |
