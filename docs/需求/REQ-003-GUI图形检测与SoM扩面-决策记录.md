| D-11 | 检测模型的落地形态(原 §4 Q4) | **主包不内嵌、权重驻用户数据目录**:主包保持 MIT 纯净;exe 内置检测能力开关;模型权重由**人类显式获取并放置**到约定目录(获取路径以 **D-16** 为准:代码内无下载器;2026-09-15 sdfang 裁定统一措辞,原「运行时可选出本机下载」表述作废),运行时只做存在性+哈希校验 | ①许可传染面被隔离在"用户自选组件"外,主包不因内嵌 AGPL 权重被拉进传染面;②主包体积与解包启动耗时零冲击(单文件 exe 的自由度是本工程的硬约束);③与既有"出厂只读 + 用户数据(policy.local.yml)"双文件形态同构(ISS-0030),用户数据目录已是既有约定。**代价认账**:首用需一次人工获取放置,离线环境该能力不可用——列 §4 假设 A 项。**否决**:内嵌(AGPL 传染 + 体积劣化)、远程推理(截图出本机,与现有只读本机安全面冲突)、先只做 UIA 可达面(REQ-003 §3 承诺"任意图形",缩小承诺需改 §3) |
| D-12 | 检测器选型(原 §4 Q1;先侦察后定,2026-09-14 侦察、2026-09-15 **sdfang 终裁**) | **CV 单线出货(终裁)**:出厂检测器 = 经典 CV 管线(自适应阈值+轻闭运算+连通域+填充率过滤,侦察变体 E 的产品化),注册表回填标识 `cv-contour`;**权重清单保持为空**——本线零权重零下载,D-16「代码内无下载器」彻底闭环;许可 Apache-2.0(OpenCV,既有依赖零新增)。**回退条款**:真机验收(TC-INT-02)或后续实测证明 CV 精度不足时,C2(干净基座+UI 数据微调)作为**独立新需求**立项,注册表形态支持第二标识共存 | 侦察实测(方案 v0.5 §5.1/§5.2,全部有档):①**H1 画布检出** CV 8/8 精确,两模型零样本皆不达;②H2 三者许可均干净;③H4 耗时 CV 3~10ms / PicoDet 23~34ms / RT-DETR ~220ms,全部预算内;④B1 真实 UI:CV 变体 E 控件逐枚分离(企微/西柚),模型零样本误报为主;⑤**关键互斥事实**:H1(框涂鸦)与「UI 控件微调模型」天然互斥——控件训练分布不含画布涂鸦,微调后大概率反而不框;CV 按构造就框。零样本模型线不可用(通用物体检测≠UI 图形检测);C2 微调投入以周计且增益(控件语义)恰是契约不需要的。**代价认账**:CV 无语义(契约本就只要 rect+confidence,语义归 AI);文字在**全盲应用**里会作为图形入框(需「同行字形合并」精化档,实现期参数);深浅主题/缩放族未实测(样本集续补);**置信度口径**:CV 无学习置信度,`confidence` 定义为**几何显著度**(填充率派生),描述面写明含义、不得冒充语义置信度。侦察全部证据(样本/脚本/标注图/权重台账)归档于 `docs/需求/REQ-003-侦察/` |
| D-13 | **SoM 扩面的编号语义**(原 §4 目标 B) | **单一编号空间 + 来源字段**:UIA 元素与检测出的图形区域在 `get_clickable_map` 里**同排一套 `id`(全局唯一)**,每条 entry 增 `source` 字段标明来源(`"uia"` / `"detect"`);AI 只需认一个 id 空间,不必维护两套映射 | ①两套编号会在同一张图上出现两个"1 号",AI 需靠前缀区分,认知成本与误用面都更大;②"单一编号空间"是 SoM 论文的原始语义(标记而非坐标解锁定位,arXiv 2310.11441)——编号空间分裂会破坏该语义;③`source` 字段让通道归属可判又不占编号面,与 D-08"双字段满足看/找两用途"同构。**代价认账**:AI 需读 `source` 才知道该走 `click_element(som_id)` 还是坐标点击——须在工具描述里显式写明(承目标 C 可发现性) |
| D-14 | **检测区域的点击归属**(D-13 的配套,本单新增) | **两路分开:`som_id` 只解析 UIA 元素**;`source="detect"` 的编号**不入点击解析表**,AI 取 entry 的 `rect` 走坐标点击(`click`) | ①`click_element(som_id)` 语义是"UIA 精确寻址",检测框是模糊落点——让精确通道静默降级为猜点是**能力面混淆**,与 ISS-0044 §1"裸坐标直出差"同根;②"工具=物理层,判断归 AI"(sdfang 裁定):工具给 rect 原语,怎么点归 AI;③代价认账:每个 detect 编号多一次调用跳转(先看图→取 rect→click)。**诊断性要求**:AI 误用 detect 编号调 `click_element(som_id)` 时须**显式报错并指引**"该编号为检测图形区域,请用坐标点击",不得静默拒绝也不得静默代点 |
| D-15 | **检测的耗时记账方式**(原 §4 Q2) | **显式开关 `detect:true` + per-tool 预算覆盖**:`get_clickable_map` 增可选布尔参 `detect`(默认 `false`);不传时**行为与耗时零变化**;传 `true` 时执行检测并走 `TOOL_BUDGET_OVERRIDES["get_clickable_map"]` 覆盖(与 `ocr`/`screenshot` 的 12.0s 同一登记表、同一链路) | ①与既有 `screenshot(ocr=True)` 同构——该形态已被 ISS-0039 验证过一轮,复用已收敛的模式而非另造;②"默认零变化"是 REQ-001 MOUSE-15 立的规矩,默认开启会让所有存量调用无谓变慢;③`detect` 是**能力开关不是降级逻辑**——检测失败≠回退到静默返回 UIA-only,须显式报错(与 ISS-0037/0039 的"感知自愈"语义一致);④具体预算数字**实测后回填**(不预设,遵守"没证据不下结论") |
| D-16 | **模型权重的获取路径**(原 §4 Q5 安全面) | **人类显式获取 + 哈希校验**:deskpilot **代码内不写任何下载器**;模型文件与哈希清单列入本文档,由人类按单把权重放进约定目录;运行时只做**存在性 + 哈希校验**,不合即**显式报错并给出完整指引**(路径、期望哈希、获取步骤) | ①防"任意 URL 下载并加载二进制"的供应链入口——这类能力型工具一旦存在,就是最敏感的越权面,而收益仅是省一次人工步骤;②与"身份类动作永远人类执行"的安全纪律同构;③许可面干净:权重由人类自取,主包不构成"分发"行为,与 D-11/D-12 的隔离策略闭环;④AI 可诊断性不丢——缺权重/哈希不符都报结构化错误与指引(承 ISS-0027/0039 的"AI 可自愈错误"规范),AI 能告知人类该做什么 |
| D-17 | **去重判据的 UIA 矩形集合取全量还是取过滤后**(SOM-05 的口径补充;sdfang 2026-09-12 裁定,**推翻了详设 v0.2 的"同源同集"**) | **取 `_iter_summaries` 摘要流的全量**,不做 `enabled`/非零面积过滤;**编号空间仍只收过滤后那批**。即:判据集合 ⊋ 编号集合,规则陈述为「**凡 UIA 枚举到的矩形,检测不在其上编号**」——「UIA 优先」作用于**枚举面**而非**交付面** | ①**SOM-05 字面即此**:需求 §4.2 原文「重叠时以 UIA 优先」无例外条款,取同源等于给它挖 carve-out,是新增主张而非参数取值;②**检测通道应为纯增量**——只覆盖 UIA 从枚举层面看不见的地方(画布/图标/自绘控件);取同源会让它额外覆盖「UIA 枚举到但否决交付」的区域,输出于是**推翻平台自己的 `enabled` 裁决且无痕迹**;③**免费精度过滤**:RK-2 记检测精度天花板 SOTA 39.5%,而 `enabled` 是平台给出的零成本可用性判词——应当用它过滤检测输出,方向不可逆;④**坏框对 AI 不可学习**:条目键集冻结七键(D-13),**无任何字段**能让 AI 知道"这条 `source="detect"` 的框坐落在禁用控件上";而 `click_element` 是物理层动作、点到死目标**照样报成功** → 取同源产出的是**静默假成功**,取全量的失效形态是"图上有缺口"、AI 能把这个说不出口报给人类。**fail-closed:可观察的"我做不到"优于静默的"我做完了"**;⑤**无漂移面**:全量取的是同一条摘要流,不依赖第二处过滤;取同源需两处过滤**逐字同步**,漏改即静默产生"幽灵占位"(输出里不存在、却支配输出的元素)。**代价认账(非零)**:「UIA 误报 `enabled=False`、但像素上确实可点」的目标**取不到编号**;此与现状(REQ-003 之前该类本就不在编号空间)等价,**非本单新增损失**,且该类是否真实存在、规模多大**未实测不预设**。**若日后实测证明确有此类**,它是一条**独立新需求**(「控件树的覆盖范围是否构成检测通道的上限」),须单独立单定验收判据,不得在 SOM-05 名下当参数改。**实现面零额外成本**:`screened` 是纯函数、集合由参数传入,**只换调用点传入的集合**,不动编排(FD-04) |
