# 桌面图标感知 —— 需求设计决策记录

> 决策树提问记录(2026-09-05 起,sdfang 决策)。每条:编号 / 决策点 / 选定方案 / 理由。此文件为过程性记录,最终设计并入需求文档后归档。

| 编号 | 决策点 | 决策 | 理由 |
|------|--------|------|------|
| D-05 | 实现选型策略 | **侦察先行,数据驱动选型**:先诊断桌面 Progman 窗口 UIA 定位失效(attach 成功但 get_ui_tree/窗口截图报 WINDOW_GONE 的今日实证),诊断结论写入本记录后,再定 UIA ListView 或 Shell IShellFolder | 带病上阵风险最大;Shell 直接定会引入未验证面;诊断成本半小时,收益是消除整条路线的不确定性 |
| D-06 | 栈叠图标返回语义 | **各成一条,rect 如实**(重叠图标返回相同/相交矩形,不合并不加 count) | 工具只给感知事实,合并/去重是判断——符合"工具=物理层,判断归 AI"裁定;置顶序为低频场景引入高实现成本 |
| D-07 | 清单截断上限 | **无上限,不设截断** | 桌面 ListView 枚举天然有界(实测本机 33 个),与 get_ui_tree(节点可达数千)量级完全不同;截断是防御性复杂化 |
| D-08 | name 字段语义 | **双字段**:display(显示名,与 OCR/视觉一致)+ source(文件名/解析目标,唯一可定位) | 单字段无法同时满足"看"与"找"两种用途;同名图标(两个 WeLink 实证)需 source 唯一标识,核验需坐标+display 对齐 |
| D-09 | rect 字段语义 | **双矩形**:graphic(图形矩形,抓点/拖拽用)+ cell(图形+标签单元矩形,核验/占用判断用) | 单矩形无法同时满足两种消费;今天的两次抓空正是"从单元矩形推算图形位置"这类推算的翻车 |
