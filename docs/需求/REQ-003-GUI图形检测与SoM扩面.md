## 1. 背景与问题

无文字图形定位(ISS-0044)的收敛方案 ①④ 覆盖了"UIA 可见控件"与
"带文字标签控件"两个主场景,但**任意图形**(自绘界面 / 纯图标 / 画布)
仍无解——OCR 无锚点、UIA 无节点、SoM 限 UIA 可见、template_match 鸡生蛋,
四条通道在该场景同时失效(原始输入 §2)。

该面的业界正路是纯视觉检测模型(OmniParser/UIED 类):检测模型供给图形
区域 → SoM 覆盖面从 UIA 可交互元素扩展到检测出的图形区域。
业界证据链(原文亲验,原始输入 §3)给出三条硬结论:

1. 纯轮廓法死刑(FSE2020 Table 2,非文本 F1 0.15~0.20)——排除;
2. 检测模型路线**有效但有天花板**(FSE2020 组合方案非文本 F1=0.523;
   OmniParser V2 ScreenSpot-Pro SOTA 39.5%)——因此是 UIA 的**补充**,不是替代;
3. SoM 论文核心结论(裸坐标 REC 25.7,标记解锁定位)——检测区域
   **必须进编号空间**才算可用。

**许可地雷**:OmniParser 的检测模型继承 YOLOv8 的 AGPL,与 deskpilot 的
MIT 冲突;deskpilot 又交付为 PyInstaller 单文件 exe,模型内嵌会同时劣化
体积与启动耗时。这两条约束共同决定了落地形态(D-11/D-12)。

## 3. 范围与非目标

- **本单承诺落地**:DET-01~07、SOM-01~06、GOV-01~04 全部条目必交付;
- **非目标**:替代 UIA 通道——UIA 优先原则不变,检测是补充;
- **非目标**:替 AI 判断图形语义(这是什么图形、该不该点)——判断归 AI;
- **非目标**:自动下载权重(D-16 明确否决,防供应链入口);
- **非目标**:远程推理(D-11 否决,截图不出本机);
- **非目标**:纯轮廓/几何启发式检测(FSE2020 数据死刑);
- **非目标**:曲线/路径规划类能力(属 REQ-004 范围);
- 与 REQ-004 的依赖关系:REQ-004 的"画布占位感知"(目标 B)在
  UIA 不可达部分依赖本单能力;本单不重复其立项(承 REQ-004 §3 非目标二)。

## 4. 约束

### 4.1 硬约束

- **许可**:交付物(含默认配置与文档示例)**不得**纳入 AGPL 系权重;
  检测器选型以 D-12 的侦察实测结果为据,宽松许可系达标即落地;
- **形态**:单文件 exe 体积与解包启动耗时不得因本能力劣化——权重不入包(D-11);
- **安全**:截图不出本机;不写目标窗口;不新增审批路径;不引入下载器(D-16);
- **默认零变化**:`detect` 缺省时行为、耗时、返回结构对既有消费方零影响(D-15);
- **通用性优先**:检测器与推理后端走注册表/参数化,禁止 if 链与 bespoke 类;
- **fail-closed**:未覆盖的情况=显式报错,禁止静默降级(DET-05)。

### 4.2 设计默认(非决策点,评审可推翻)

- **重叠去重口径**:检测区域与 UIA 元素重叠时以 UIA 优先(SOM-05);
  具体判据建议取"检测框中心点是否落在某 UIA 元素矩形内"——实现简单、
  可解释;**最终口径以详细设计为准**。判据所用的 UIA 矩形集合**取枚举全量**
  (不做可交互/面积过滤),而编号空间只收过滤后那批——即「凡 UIA 枚举到的
  矩形,检测不在其上编号」,检测通道是**纯增量**(**D-17** 终裁);
- **检测区域在编号空间的排位**:UIA 元素按既有阅读顺序编号在前,
  检测区域追加在后,内部按坐标序(保证 AI 看到的序稳定、可复现);
- **置信度门槛**:低置信检测框的过滤阈值设为配置项而非硬编码;

- 清单**不设截断上限**(与 REQ-002 ICONS-04 同口径);
- 检测区域**不承诺语义标签**——不输出"这是按钮"类判断(判断归 AI);
  若后续引入图标描述模型,另立需求。

### 4.3 质量属性

| 属性 | 要求 | 验证 |
|------|------|------|
| 性能 | `detect=true` 时全程在 per-tool 预算内(数字实测回填,GOV-03);`detect=false` 时与现状同量级(亚秒级) | R-04 实测 + TC 计时 |
| 可靠性 | 检测失败必显式报错,零静默降级(DET-05);权重校验失败必可诊断(DET-03) | TC 断言异常码+message |
| 安全 | 截图不出本机、不写目标窗口、不新增审批路径、无下载器(DET-07/GOV-02) | 评审 + 形态测试 |
| 可用性 | AI 不翻文档即知 `source` 语义与两路点击分野(GOV-01);错误自带下一步指引(GOV-04) | 描述形态测试 + 错误 message 断言 |
| 可维护性 | 检测器可替换(DET-06);权重路径与哈希清单单源登记 | TC 注册表断言 |

### 4.4 假设与依赖

| 编号 | 假设/依赖 | 失效影响 |
|------|----------|---------|
| A-1 | 人类愿意执行一次性的权重获取步骤(D-16 的代价) | 不执行则该能力永不可用——须在文档与错误指引里说得足够清楚 |
| A-2 | 检测模型在 CPU 上推理可接受(无需 GPU) | 若必须 GPU,则 L0 只读通道的适用性需重新评估 |
| A-3 | 宽松许可系检测器在真实自绘场景上的精度**可接受**(D-12 待实测) | 若不可接受 → 需拿数字回来重裁许可底线,本单 §2.1 部分条目需改 |
| A-4 | 用户数据目录可写且稳定(既有 ISS-0030 双文件形态已成立) | 权重校验无从进行 |
| A-5 | 检测区域与 UIA 元素的几何可比——两者均为虚拟屏坐标 | 坐标系不一致会导致 SOM-05 去重判据失效(注:REQ-002 的坐标系契约问题见 ISS 待开项) |
