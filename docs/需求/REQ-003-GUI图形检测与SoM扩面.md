## 1. 背景与问题

无文字图形定位(ISS-0044)的收敛方案 ①④ 覆盖了"UIA 可见控件"与"带文字
标签控件"两个主场景,但**任意图形**(自绘界面/纯图标/画布)仍无解——
该面的业界正路是纯视觉检测模型(OmniParser/UIED 类)。本单评估该路线
的立项可行性:检测模型供给图形区域 → SoM(get_clickable_map)覆盖面从
UIA 可交互元素扩展到检测出的图形区域。

**证据链(原文亲验,详见 ISS-0044 §2.1)**:
- OmniParser(微软):YOLOv8 图标检测(67K 截图微调)+BLIP 图标描述+OCR
  +SoM;V2 ScreenSpot-Pro SOTA 39.5%——路线有效但有天花板;
- FSE2020:纯轮廓法死刑(F1 0.15~0.20),组合方案 F1=0.523——
  检测模型路线的有效性证据;
- SoM(arXiv 2310.11441):裸坐标直出差(REC 25.7),标记解锁定位——
  SoM 扩面是该路线的正确终点形态。

## 2. 目标(候选,评审后细化)

| 项 | 内容 |
|----|------|
| 目标 A | 评估并引入 GUI 图形检测能力(自绘界面/任意图形出候选区域) |
| 目标 B | SoM(get_clickable_map)扩面:UIA 元素 ∪ 检测图形区域统一编号覆盖 |

## 3. 范围与非目标

- **本单承诺落地**:目标 A/B 必交付;§4 评估清单决定**落地形态**
  (选什么模型、什么部署方式),不决定做不做;
- **非目标**:替代 UIA 通道——UIA 优先原则不变,检测是补充;
- 判断归 AI:检测只给候选区域,语义判断(这是什么图形)归 AI。
