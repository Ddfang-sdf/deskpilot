## 0. 引言

**目的与读者**:本文档定义"鼠标能力补全"的完整需求,作为设计、实现与
验收的唯一依据。读者:sdfang(评审/决策)、AI 开发伙伴(实现)、维护者(回归)。

**干系人**:

| 干系人 | 角色 | 关注点 |
|--------|------|--------|
| sdfang | 产品决策者/安全审批方 | 能力面完整、安全网硬约束、裁定可追溯 |
| AI 伙伴 | 直接调用方/主要受益方 | 组合自由度、可发现、可自愈、参数默认向后兼容 |
| 人类用户 | 审批与急停执行者 | 审批/急停语义不变,零新打断 |
| 维护者 | 代码与测试维护 | 通用性(注册表/参数化),无 bespoke 分支 |

**术语表**:

| 术语 | 定义 |
|------|------|
| 原语 | 不可再分的单一物理动作(mouse_down/mouse_up),组合的基座 |
| 动词 | 常用组合动作(click/drag/hold/scroll 扩展),原语的便捷封装 |
| 安全网 | 原语暴露的三重硬保障:急停抬键/看门狗自愈/up 幂等 |
| 悬空按键 | 按下后因进程死亡等原因未被抬起的物理按键状态 |
| 抬键清扫 | 执行层启动时对三键各发一次幂等 mouseUp 的自愈动作 |

**使用场景**(每条对应验收上下文):

| 编号 | 场景 |
|------|------|
| SC-1 | AI 按住不放拖动文件到新位置(原语组合:down→move→up) |
| SC-2 | AI 右键打开上下文菜单,中键执行特定应用语义 |
| SC-3 | AI 双击/三连击执行高频动作 |
| SC-4 | AI 长按(hold)期间 daemon 被升级重启——启动抬键清扫自愈,鼠标不悬空 |

## 1. 背景与问题

详细设计说明书写明"AI 可以像人一样操控鼠标键盘"——该承诺自 M1 落地起
未兑现:实现仅覆盖左键单击/左键拖拽/垂直滚轮。根因:实现期按"最小可用"
裁剪,承诺与交付之间的差距从未盘点。sdfang 裁定:能力必须**可组合**
(按住+拖动、左右键同按),给 AI 的工具要有人持鼠标的全自由度;
工具=物理层,判断归 AI。

## 3. 范围与非目标

- **非目标**:贴图窗口(如 Snipaste 贴纸)的拖动——贴图是窗口不是桌面图标,另行评估;
- **非目标**:落点校验/碰撞检测等"智能"——判断归 AI(sdfang 裁定);
- **非目标**:看门狗阈值参数化——30s 为固定常量(安全参数不开放:
  用户数据文件无权放宽任何安全参数,双文件政策一致)。

## 4. 约束

- 按下状态由执行层跟踪,其生命周期兜底(MOUSE-04/05/06)为硬约束,任一缺失评审不过;
- 不新增审批路径;原语/动词并入既有 L2 链路;
- 不引入新三方件(pyautogui 现有依赖)。

### 设计默认(非决策点,评审可推翻)

- `hold` 未传 button 时默认 left;
- `scroll` 水平方向符号映射与垂直对称(left=−amount / right=+amount);
- `clicks` 的多击间隔采用 pyautogui 默认参数(实现期实测留痕);
- 看门狗阈值为固定常量 30s,不做策略参数化(安全参数不开放原则)。

### 质量属性(非功能需求)

| 维度 | 需求陈述 |
|------|---------|
| 性能 | 原语/动词单次调用响应时间与既有 click/drag 同级(不引入可感知劣化);hold 按 duration_ms 计时,不额外阻塞 |
| 可靠性 | 悬空按键在三种路径(急停/看门狗/启动清扫)下必被自愈,任一失效即缺陷 |
| 安全 | fail-closed:非法 button/超限 duration 一律 INVALID_PARAMS 零派发;不新增审批路径;安全参数不开放 |
| 可用(AI 友好) | 既有调用默认参数行为零变化;工具描述含组合示例与安全网说明 |

### 假设与依赖

| 项 | 内容 |
|----|------|
| A-1 | pyautogui 多键按下状态独立共存(实现期实测留痕,若违反须上报改设计) |
| A-2 | 物理按键状态为系统级:新进程可直接 mouseUp 抬起旧进程按下的键(启动清扫前提) |
| A-3 | 看门狗时钟可注入(测试接缝),与既有 FakeClock 机制一致 |
