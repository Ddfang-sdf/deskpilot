## 1. 背景与问题

2026-09-05 桌面图标整理演示中,AI 为拿到图标名称与图形矩形走
"screenshot→OCR→像素扫描"两轮链路,两个硬伤:标签几何推算图形中心
有偏差导致**两次抓空**;全屏 OCR 在负载下必然超时。应用场景(实证):
①桌面定位规划;②拖拽后核验;③确定性坐标(消灭抓空根因);
④多步操作前后状态快照。

## 2. 需求条目(唯一 ID + 属性)

| ID | 需求陈述 | 来源 | 优先级 | 验证方式 |
|----|---------|------|--------|---------|
| ICONS-01 | 提供 `list_desktop_icons` 只读工具:L0、无需绑定,返回 `[{display, source, graphic_rect, cell_rect}]`——display 显示名、source 文件名/解析目标(D-08);graphic_rect 图形矩形、cell_rect 图形+标签单元矩形(D-09);全部 rect 为虚拟桌面坐标系 | 原始输入 §2 + D-08/D-09 | 高 | 测试+实测 |
| ICONS-02 | 可选 `region` 参数限定扫描区域;默认全桌面 | 原始输入 §2 | 中 | 测试 |
| ICONS-03 | 栈叠图标**各成一条,rect 如实**(重叠图标返回相同/相交矩形,不合并不加 count) | D-06 | 高 | 测试 |
| ICONS-04 | 清单**不设截断上限**(桌面枚举天然有界) | D-07 | 中 | 测试 |
| ICONS-05 | 取不到桌面图标(桌面被替换/无 ListView)→ **显式报错**,禁止返回空列表假装成功 | 原始输入 fail-closed | 高 | 测试 |
| ICONS-06 | 实现选型**侦察先行**:先诊断桌面 Progman 窗口 UIA 定位失效实证(attach 成功但 get_ui_tree/窗口截图报 WINDOW_GONE),诊断结论写入决策记录后再定 UIA ListView 或 Shell IShellFolder;两方案留痕对比 | D-05 | 高 | 侦察+评审 |
| ICONS-07 | 只给感知(名称+矩形),不做规划/排序/碰撞判断;不新增审批路径 | 原始输入约束 | 高 | 评审 |

## 3. 范围与非目标

- **非目标**:规划/排序/碰撞判断——判断归 AI;
- **非目标**:贴图窗口(非图标,不列入);
- **非目标**:图标置顶顺序(z-order)——低频场景,高实现成本(D-06);
- 与 screenshot 的 `ocr:true` 参数不重叠:本工具给图标矩形,ocr:true 给文字。

## 4. 约束

- L0 只读,不新增审批路径;
- fail-closed:取不到即显式报错;
- 不引入新三方件(候选 pywin32 Shell 接口评估)。

### 设计默认(非决策点,评审可推翻)

- 清单按桌面枚举的自然顺序返回,不承诺排序(AI 需稳定序时可自行按坐标排序);
- 枚举耗时应在 L0 预算(5s)内,实现期实测留痕;若超预算再议专属覆盖。

### 质量属性(非功能需求)

| 维度 | 需求陈述 |
|------|---------|
| 性能 | 全桌面枚举单次调用在 L0 预算(5s)内完成(实现期实测留痕) |
| 可靠性 | 取不到即显式报错,禁止空列表假装成功;返回结构跨调用稳定(字段契约固定) |
| 安全 | L0 只读零副作用;不新增审批路径;不做任何判断/自动执行 |
| 可用(AI 友好) | 一次调用交付 display/source/双矩形,AI 无需自建感知链路;与 screenshot 的 ocr:true 不重叠且互补 |

### 假设与依赖

| 项 | 内容 |
|----|------|
| A-1 | 桌面图标由系统桌面 ListView/Shell 承载,枚举接口在 Win10/11 可用(侦察先行验证) |
| A-2 | 栈叠图标在枚举层各成独立条目(不因重叠被合并)——若所选实现不满足,须在设计评审提出 |
| A-3 | 枚举接缝可注入(测试用替身),与现有元素源接缝模式一致 |
