## 1. 背景与问题(证据)

2026-09-05 桌面图标整理演示中,AI 为拿到图标名称与图形矩形:
① screenshot(图像不可见)→② ocr 取标签框(多次 TOOL_TIMEOUT
重试)→③ 像素扫描脚本取图形中心。链路两轮起,且两个硬伤:
- 标签几何推算图形中心有偏差,导致**两次抓空**(rubber band 框选);
- 全屏 OCR 在负载下必然超时(ISS-0039)。
另有栈叠图标(两图标图形重叠,如 Google/Chrome 列)无法区分归属。

应用场景(sdfang 质询后归纳,实证自当日演示):
1. 桌面定位规划(替代 OCR+扫描两轮链路);
2. 拖拽后核验"图标现在在哪";
3. 确定性坐标(直出矩形,消灭标签推算误差——两次抓空根因);
4. 多步操作前后状态快照(防场景漂移,如贴图遮挡落点)。

## 2. 目标

L0 只读工具 `list_desktop_icons`:`[{name, rect}]` 直出(虚拟桌面坐标),
可选 `region` 参数限定扫描区域;取不到时显式报错(fail-closed,
不返回空列表假装成功)。

## 3. 范围与非目标

- **非目标**:规划/排序/碰撞判断——判断归 AI;
- **非目标**:贴图窗口(非图标,不列入);
- 与 ISS-0037-B(`ocr:true`)不重叠:本工具给图标矩形,ocr:true 给文字。

## 4. 验收标准(草案,评审后按五要素细化)

1. 工具注册于 TOOL_SCHEMAS,参数与默认值形态正确;
2. 实测桌面(33 图标含栈叠列)清单返回:名称与矩形与像素实测一致,
   栈叠图标各成一条;
3. 取不到(桌面被替换/无 ListView)→ 显式报错;
4. 桌面窗口定位失效场景(见 §6 前置侦察)处理方案落地。

## 5. 约束

- 不新增审批路径(L0);
- 只给感知(名称+矩形),不做判断;
- 实现选型经评审:UIA ListView 枚举 / Shell IShellFolder 接口
  (两方案留痕对比,通用性优先)。
