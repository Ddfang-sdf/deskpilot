| TC-DET-01/03a/03b/04/05a/05b/06/06b/07/08/09、TC-GOV-04 | 单元 | 真 Executor/懒装填/错误归约/编号排位;替身仅**检测器工厂**、**权重清单**与 `_shot_fn`/`_element_source` 既有接缝 |

| TC-DET-02、TC-GOV-01a/01b/03a | 形态 | 注册表/`deskpilot.spec`/包目录/**源码文本**直读,**零替身** |
| TC-INT-01/02/03、TC-GOV-03b**【回填】** | 集成 | 真 daemon+真 Executor+真桌面,**零替身**;断言在响应体/PIL 像素/审计落盘/计时 |

合计 **55 用例**:单元×47 + 形态×4 + 集成×4。层级按用例的**主形态**
归类;TC-SOM-02 与 TC-GOV-02 各一条两半(测试半 + 形态半),按主形态计入
单元,其形态半支在 R3 中单列,**不重复计数**;同理 R3 的形态断言也可出现在
单元用例内(TC-DET-06/09 等),一并只计一次。**形态层放零替身**,凡用到
替身者必归单元层——故 TC-GOV-02 不留在形态行。

替身只打在**检测器工厂**(经 `executor.detector_factory` 公开装配位)、
**权重清单**(经 `executor.weight_manifest` 公开装配位,D-18/详设 §3.2)与既有
`_shot_fn`/`_element_source` 接缝;懒装填状态机、错误归约、坐标收口、去重、
排位、整表替换**全部真实**(R2)。

**权重清单装配位的边界**(D-18 新增,防读成"把校验替掉"):替身清单替的是
**声明**——"该有哪些文件、期望哈希是多少";`verify()` **本体一字未改、照常执行**
(签名、流程、三个失败结论的产出逻辑全真)。故:

- **成功支**(哈希相符 → 触达工厂)与**失败支**(缺文件/哈希不符 → `DETECTOR_UNAVAILABLE`)
  **同源同真**:两条支路由**同一个真 `verify()`** 产出,差别只在注入的清单内容。
- 故失败支用例**不得**由"造一个空目录"或"清单为空"构造——那会变成"校验放行"
  这个**另一种语义**;一律**注入故意不合的替身清单**(指向不存在文件 / 期望哈希
  与真实文件不符),让失败结论**由真 `verify()` 算出**。
- 装配位**不接通** `policy.yml`/环境变量(FD-07 未动),故它不是安全面放宽;
  生产装配(`main.py`)**不赋值**,保持出厂常量缺省(详设 §6)。

## 2. 用例(五要素)

> **D-18 前置块(自上而下适用于本表全部 `detect=True` 的成功支用例)**:凡
> `detect=True` **且期望返回成功**的用例,其前提里都必须含一条**装配前提**——
> 「经公开装配位 `executor.detector_factory` 注入替身检测器」**且**
> 「经公开装配位 `executor.weight_manifest` 注入替身清单,其条目指向 `tmp_path`
> 下**真实存在且哈希相符**的文件」。缺任一条,该用例在 P3 会撞上**出厂空清单
> 之外的校验失败**而落 `DETECTOR_UNAVAILABLE`,永远转不了绿。本节各用例的
> 「前提」列已按此写全;`tmp_path` 下的样本文件是**真文件**(经 `verify()` 真算
> sha256 后与替身清单的期望值比对)——替的只是**声明**,不是**校验**。
>
> **清单来源分级**(与上一条配套,防 P3 期把"真清单"写进用例):
> ①**纯函数组**(TC-COORD\*/TC-DEDUP\*/TC-WVER\*/TC-WDIR\*)直接把清单当**入参**喂,
> 不涉任何装配位;②**Executor 组**(TC-DET\*/TC-SOM\*/TC-CACHE\*/TC-CLK\*)一律用
> **替身清单**——**出厂常量的内容待 D-12 终裁**(详设 §13),当下不存在,故本表
> **没有任何用例可以依赖"真清单"**;这也让 TC-DET-08 那条"校验失败**不**记忆化 →
> 补上文件后下一次即成功"成为**同一条用例内**两个方向各跑一次真 `verify()`。

  「替身清单」这一装配位**不存在**,于是 `detect=True` 的**成功路径**在 P3
  整条不可达(真 `verify()` 先撞不存在于当下的出厂清单 → 必然
  `DETECTOR_UNAVAILABLE` → 替身永不触达),十余条用例只能空转。增设装配位后
  该阻塞**消解**,但**仍有三项**不因本设计而变得可测,如实记账:
  - **TC-INT-02**——集成层**禁替身**,它必须用**真实权重**;故受 D-12
    选型与 R-04 实测定版双重阻塞(**本条不是回填问题,是回归期才能闭合**)。
  - **TC-GOV-03b**——预算数字须 R-04 实测,数字到位前不落地。
  - **出厂权重清单的内容**——待 D-12 终裁。**本单出厂清单为空**(不写任何
    检测器标识);空清单使 `verify()` 判 `ok`,**那是真实语义**(无期望文件 =
    无校验不通过)而**非占位值**,故 **空清单 ≠ 可用的出厂形态**:它意味着
    `detect=true` 会走到工厂并因"标识未注册"而失败。**校验失败支的证伪力
