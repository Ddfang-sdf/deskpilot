## 1. 背景与战略裁定

对比分析的战略结论:DeskPilot 与 Codex **互补而非竞争**——Codex 是
潜在客户,不是对手。sdfang 裁定采纳「把 DeskPilot 推进 MCP 生态分发」
方向。最有力的互补证明=**亲验 Codex 挂载 DeskPilot 跑通**,本单含此
验收环。

定位一句话:任何 Agent 想动 Windows 桌面,先过 DeskPilot 这关——
所以要让所有主流 Agent 客户端**一行配置就能挂上**。

## 4. 硬约束(需求分析时必须逐条落进方案)

1. **亲验为验收唯一口径**:Codex 挂载必须以实盘录屏/截图留证,禁止「配置写上了就算完成」;
2. **exe 分发不动摇**:保持单 exe+policy.yml 同目录形态,不为任何客户端定制构建;
3. **内网离线不破**:LocalZip 路径与各客户端注册兼容,不引入必须联网的环节;
4. **文档单源**:Codex 接入章节与既有 claude-code/cursor 章节同结构,禁止分叉叙述;
5. **范围控制**:本单只做「接入与上架」;「为 Codex 优化工具描述/说明书」归 REQ-008 范围,不混做。
