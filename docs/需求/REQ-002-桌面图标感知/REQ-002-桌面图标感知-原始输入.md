## 1. 背景(实证)

2026-09-05 桌面图标整理演示中,AI 为拿到图标名称与图形矩形:
① 调 screenshot(图像不可见)→② 调 ocr 取标签框(多次 TOOL_TIMEOUT
重试)→③ 写像素扫描脚本取图形中心。链路两轮起,且两个硬伤:
- 标签几何推算图形中心有偏差,导致**两次抓空**(rubber band 框选);
- 全屏 OCR 在负载下必然超时(预算保护,机制见 OCR 超时问题单)。
另有栈叠图标(两图标图形重叠,如 Google/Chrome 列)无法区分归属。

应用场景(sdfang 质询后归纳,实证自当日演示):
1. 桌面定位规划(替代 OCR+扫描两轮链路);
2. 拖拽后核验"图标现在在哪"(当日每次核验都要重新 OCR 全场);
3. 确定性坐标(直出矩形,消灭标签推算误差——两次抓空根因);
4. 多步操作前后状态快照(防场景漂移,如贴图遮挡落点)。

## 2. 初版方案

L0 只读工具 `list_desktop_icons`:

| 项 | 内容 |
|----|------|
| 语义 | 返回桌面图标清单 `[{name, rect}]`,rect 为虚拟桌面坐标系 |
| 参数(候选) | `region` 可选(限定扫描区域);默认全桌面 |
| 实现选型 | 评审期定:UIA 桌面 ListView 枚举 / Shell IShellFolder 接口(两方案留痕对比,通用性优先) |
| fail-closed | 取不到(桌面被替换/无 ListView)→显式报错,不返回空列表假装成功 |

### 约束

- 只给**感知**(名称+矩形),不做规划/排序/碰撞判断——判断归 AI;
- 不新增审批路径(L0);
- 与 screenshot 的 `ocr:true` 参数不重叠:本工具给图标矩形,ocr:true 给文字。
