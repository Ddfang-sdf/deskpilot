## 1 引言

### 1.1 编写目的

本文档是 REQ-008 的需求规格说明,把「MCP `instructions` 字段深化」从原始输入的方向性描述落成可设计、可开发、可验收的需求条目,供功能设计/详细设计/测试设计引用,并供 sdfang 评审裁定文中标注的待裁定项(D1~D4)。

### 1.2 背景

2026-09-22 DeskPilot×Codex 对比分析会裁定:DeskPilot 是工具层(MCP server),Codex/Claude Code/Cursor 等 Agent 本体是潜在客户,互补而非竞争。MCP 协议中 server 初始化握手返回的 `instructions` 字段会被客户端 Agent 当作「这个 server 的使用须知」纳入上下文——**server 自带说明书,接入的 Agent 天生读得到**。

现状(2026-09-29 代码亲验):

| 位置 | 事实 |
|------|------|
| `deskpilot/mcp_server.py:410` | `Server("deskpilot", instructions=...)` 仅一句浏览器边界声明,且**该句已过期**——REQ-005(v0.4.4)落地后本服务已覆盖网页域(`browser_snapshot`/`browser_get_rect`),而说明书仍写着「勿用本服务(本服务截不到网页)」,与 ISS-0115 整改后的工具描述(多处点名 browser_snapshot)**自相矛盾** |
| `deskpilot/mcp_server.py:98` | 工具级描述走 `TOOL_SCHEMAS` 单源注册(ISS-0015 已意图化治理)——**工具级已治理,服务级未治理** |
| `docs/INSTALL.md` / README | 审批 90s 超时、daemon 常驻形态等关键使用约束只写给人类,Agent 端零感知 |

缺口一句话:**工具级「每个工具是什么」已讲清,服务级「这个 server 的玩法规矩」几乎空白,且仅有的一句已过期。** Agent 只能踩坑后从错误消息里学。

### 1.3 定义

| 术语 | 含义 |
|------|------|
| instructions | MCP 协议 server 初始化握手(`initialize` 响应)携带的服务说明书字段,客户端 Agent 将其纳入系统上下文 |
| 四道闸 | DeskPilot 强制层安全机制:白名单分级(L1 只读/L2 常规写/L3 高危审批)、绑定令牌、急停冻结、审计留痕 |

| 急停冻结 | 人类甩角/冻结卡/热键 Ctrl+Shift+F11 触发的全写操作拒止态;解冻仅人类通道(弹窗点击/热键) |
| 单源纪律 | 文案集中注册、缺注册即钉红的工程纪律(ISS-0015 工具描述先例) |
| 冷启动实测 | 全新 MCP 客户端会话、不提供任何外部文档,仅凭 instructions 观察 Agent 行为的验收方式 |

## 2 任务概述

### 2.1 目标

把 MCP `instructions` 从一句过期的浏览器边界声明,深化为**结构化、单源化、长度有预算**的服务级使用须知,使任何 MCP 客户端的 Agent 在冷启动(零外部文档)时即知晓:何时会被审批、审批窗语义与超时、急停冻结语义、白名单三态、daemon/stdio 形态差异、错误码自愈总原则、浏览器任务的正确工具路由。

非目标(出范围):

- 不改四道闸任何安全语义与行为(说明书只告知,不授权);
- 不治理工具级 `description`(ISS-0015/ISS-0115 已收口,说明书不复读);
- 不做错误消息文案改写(ISS-0027 面,互补不重叠);
- 不做多语言动态协商(无协议面支持,语言策略一次性裁定,见 D1)。

### 2.2 用户的特点

本需求的直接「用户」是**接入 DeskPilot 的 AI Agent**(经 MCP 客户端),特征:

- 读取 instructions 的时机=会话初始化,此后再不重读——说明书必须一次讲清;
- 无人类文档阅读习惯,依赖结构化、可执行的规则式表述;
- 上下文 token 是稀缺资源——说明书每多一词都在挤占工作记忆;
- 客户端实现不可知——Codex/Claude Code/Cursor/自研客户端均可能接入,措辞不得绑定特定客户端。

间接用户是 Agent 的人类操作员:说明书引导 Agent 行为正确(不试图自解冻、不绕审批),人类看到的审批/冻结现场才符合预期。

### 2.3 假定和约束

硬约束(原始输入 §4 五条,逐条落进方案):

1. **不改任何安全语义**:instructions 只是告知,四道闸行为零变化;
2. **单源纪律**:文案注册表化,缺注册即钉红(与 ISS-0015/REQ-007 同纪律);
3. **受众=AI**:按 REQ-007 裁定,MCP 面文案语言策略独立于界面 i18n,本需求评审时终裁(D1);
4. **跨客户端措辞中立**:不得出现任何特定客户端名;
5. **可验证**:必须有「冷启动 Agent 实测」验收环,禁止仅以文本存在性收口。

假定:

- MCP 协议 `initialize` 响应的 `instructions` 字段被主流客户端读取并纳入上下文(Codex 已实证;Claude Code 冷启动实测在验收环验证);
- 客户端对 instructions 长度无协议级硬限制,长度预算是自加的工程纪律(token 成本),非协议必需。

## 3 需求规定

### 3.1 对功能的规定

**R8-01 说明书内容面(五个必备主题)**
instructions 须结构化覆盖以下五个跨工具全局规矩,每条一两句话讲清「会发生什么+你(Agent)该怎么办」:

| 主题 | 必备语义点 |
|------|-----------|
| 审批 | 高危/新应用写操作会触发人类弹窗;审批约 90 秒,超时即拒(APPROVAL_TIMEOUT);被拒即收手,不得重试轰炸;外层预算须大于 95s(approval_ttl+5)才能等到审批结果 |
| 急停冻结 | 冻结时一切写操作被拒绝;解冻只有人类能做(弹窗按钮/热键);**AI 不存在任何自解冻通道,不得尝试**;冻结后应停止操作并告知人类 |
| 白名单 | 进程三级授权(L1 只读/L2 常规写/L3 高危审批);未入白应用首次写操作触发入白审批;白名单是人类资产,AI 不得修改策略文件 |
| 形态 | daemon 常驻(HTTP :9420,状态连续)与 stdio 一次性会话两种形态;桌面状态(绑定/冻结)跨调用持续存在 |
| 错误码自愈 | 错误码即自愈指引(WINDOW_GONE 重定位/TYPE_MISMATCH 重试/READBACK_UNAVAILABLE 换通道等),先按指引自救,救不动再求助人类 |

**R8-02 浏览器边界句修订(过期纠错)**
现存唯一一句「浏览器任务勿用本服务」已因 REQ-005 落地而过期且与工具描述矛盾,必须改写为正确路由指引:浏览器页面内容读取/元素定位用 `browser_snapshot`/`browser_get_rect`,行动(点击/输入)照用既有工具。

**R8-03 单源化注册**
instructions 文案从 `mcp_server.py` 内联硬编码迁入单源注册体系(注册位置待裁定 D3),注册缺失即测试钉红;变更走版本评审,不允许散点修改。

**R8-04 长度预算与防膨胀钉**
instructions 全长设上限(建议 ≤500 英文词,待裁定 D2),钉测试值守防膨胀;说明书只讲跨工具全局规矩,**禁止复读工具级 description 已有内容**(单源纪律的信息面分工:工具级讲「是什么/怎么用」,服务级讲「全局规矩」)。

**R8-05 语言策略(受众=AI)**
按 REQ-007 裁定,MCP 面语言独立于界面 i18n;说明书语言一次性裁定(候选:英文/中英双语,待裁定 D1),不做运行时协商。

**R8-06 客户端中立**
全文不得出现任何特定客户端产品名;所有行为指引面向「MCP 客户端 Agent」泛称。

### 3.2 对性能的规定

| 项 | 指标 |
|----|------|
| 运行时开销 | 零——instructions 仅在 initialize 握手返回一次,无热路径影响 |
| 长度 | ≤500 英文词(建议值,D2 终裁);以 token 占用最小化为导向 |
| 构建期校验 | 注册缺失/超长即测试钉红,不过夜 |

### 3.3 输入输出要求

- 输出面唯一:MCP `initialize` 响应的 `instructions` 字段(stdio 与 daemon 两形态同一字段,无分叉);
- 字段为纯文本,结构化小段(主题分节),不含 markdown 表格等重排版(客户端上下文中按纯文本消费)。

### 3.4 数据管理能力要求

- 无运行时持久化;文案即代码资产,随仓库版本管理,变更历史走 git;
- 说明书内容不涉密、不含本机路径/用户数据,可随 MCP 握手流出本机(经客户端上云至模型侧)——**撰写时须按「会出本机」假设把关措辞**。

### 3.5 故障处理要求

- 注册缺失/长度超预算 → 构建期测试钉红(fail-closed,不带病发布);
- 运行时无故障面(静态字段);客户端忽略 instructions 字段时系统行为零变化(说明书是提示层,不是安全闸)。

### 3.6 其他专门要求(安全)

- 说明书**只告知不授权**:任何措辞不得暗示「存在绕过审批/冻结/白名单的路径」;相反须明确封堵性事实(AI 无自解冻通道、AI 不得改策略文件);
- 说明书写明的安全语义必须与实现真值逐条对账(审批 TTL、解冻通道、三级授权),防「说明书说谎」——对账钉测试值守(如 approval_ttl 从 policy 默认值读取比对)。

## 4 运行环境规定

### 4.1 设备

无新增设备要求;说明书经 MCP 客户端传入模型上下文,消费端为云端模型。

### 4.2 支持软件

- 服务端:DeskPilot stdio / daemon 两形态(同一 instructions 字段);
- 客户端:任何实现 MCP initialize 握手并读取 instructions 的客户端(Codex/Claude Code/Cursor 等,措辞不绑定)。

### 4.3 接口

- MCP 协议 `initialize` 响应 `instructions` 字段(既有接口,内容面深化,协议零改动)。

### 4.4 控制

验收控制(D4 候选方案):用真实 MCP 客户端(至少其一:Codex / Claude Code)冷启动会话,**不提供任何外部文档**,依次制造三个场景——首次触发审批、冻结后调写工具、未入白应用写操作——观察 Agent 反应是否符合说明书预期(等待人类/告知人类/按错误码自愈),全程录屏留证。
