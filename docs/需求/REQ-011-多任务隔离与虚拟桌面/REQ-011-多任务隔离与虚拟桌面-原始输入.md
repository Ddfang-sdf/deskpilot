## 1. 背景与战略裁定

对比分析发现:Codex 支持多任务并行,各任务在独立 git worktree 中隔离
执行,互不干扰。桌面域的等价问题:两个 Agent(或一个 Agent 的两个任务)
同时通过 DeskPilot 操作,共享同一块物理屏幕、同一个鼠标键盘焦点、同一把
写锁——物理上必然串行,且互相遮挡污染截图取证。

借鉴方向=Windows 虚拟桌面/多会话隔离。但本单存在一个**原则级矛盾**
(§3),须先调研裁定,再谈实现。sdfang 裁定:立单,调研先行。

## 2. 现场实证(2026-09-22 代码亲验)

| 位置 | 事实 |
|------|------|
| `deskpilot/httpd.py` | 写锁(write_lock)全局一把——多任务写操作天然串行排队,读操作并发 |
| ISS-0006 根因 R1/R2/R4 | 多进程并存曾致 estop 竞争、弹窗多开——**「多持有者」在本项目出过真实事故**,隔离设计的复杂度有前车之鉴 |
| `deskpilot/monitors.py` | 多显示器支持已就绪(虚拟桌面坐标、屏号确定性 ISS-0096),但「多显示器」≠「多桌面」——同一时刻人类只看一块屏 |
| 审批窗落位裁定(ISS-0097) | 弹窗一律主屏右下角——若任务窗口在虚拟桌面 B,审批窗在主屏,**人窗分离**,审批语义断裂 |

## 3. 原则级矛盾(本单核心,须裁定)

DeskPilot 立品原则是「**人类不可视 = AI 不可动**」(README 原文;锁屏/
UAC 期间连只读感知都拒绝)。而 Windows 虚拟桌面的特性恰恰是**人类
看不到非活动桌面**——若允许 AI 在虚拟桌面 B 操作,等于开了一个人类
看不见的操作面,原则被架空;若禁止,则虚拟桌面隔离只剩「摆放隔离」
(窗口分桌面放,操作仍须切到活动桌面),价值大减。

候选裁定方向(需求分析阶段终裁):

| 方向 | 含义 | 代价 |
|------|------|------|
| ① 摆放隔离+操作串行 | 虚拟桌面只做窗口归置,写操作仍要求目标窗口在活动桌面 | 安全语义零破坏,但并行度≈0 |
| ② 受管会话隔离 | AI 操作在独立 RDP/受管会话,全程录屏+审计替代人类目视 | 引入「审计替代目视」的新信任模型,原则改写,风险最高 |
| ③ 暂不做,仅归档矛盾 | 维持单桌面串行,等真实并行需求出现再议 | 零风险,零收益 |

## 4. 硬约束(需求分析时必须逐条落进方案)

1. **原则裁定先于一切设计**:§3 矛盾未有 sdfang 书面裁定前,不许进入方案细化;
2. **急停全局有效**:无论何种隔离形态,Ctrl+Shift+F12/甩角熔断必须**跨所有桌面/会话**即时生效——这是不可让渡的;
3. **审批窗与目标同面**:审批窗落位语义须重审(ISS-0097 裁定基于单桌面前提);
4. **多持有者教训**:任何隔离设计须先回答 ISS-0006 的多进程竞争三问(归属/计数/触发面);
5. **范围控制**:本单 v1 只做调研与裁定记录;实现与否、选哪方向,另立开发单。
